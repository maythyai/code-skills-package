# CSP 项目知识与产物治理设计

## 目标与边界

让绿地、棕地、单体和 monorepo 的 Agent 在不盲扫项目的前提下，可靠地定位当前任务所需的项目约定、状态、规格和验证证据。此设计约束 CSP 技能如何创建和维护关键文件；不修改示例项目，不自动迁移或删除任何已有资产，也不将说明书当成新的事实源。

## 方案

扩充已有 `csp-knowledge-hub`、`csp-documentation-governance`、`csp-project-doc-architect`、`csp-doc-lifecycle-manager` 与 `csp-context-engineering` 的职责；在知识中枢增加一份专门的阅读与新鲜度契约。四份 `prompts/000-*_csp.md` 只标注入口、时机和交接，不复制细则。大小检查器只报告真实检查的项目，未接 CI 不宣称强制执行。

### 1. 分层阅读及权威

| 层 | 最小读取 | 职责 | 禁止 |
|---|---|---|---|
| L0 身份与硬约定 | 项目自身 `CLAUDE.md` / `AGENTS.md`（若平台支持自动加载） | 角色、工具、危险操作、常用命令、指向知识路由的入口 | 堆版本历史、全量技能索引、运行指标；将临时观测冒充常量 |
| L1 当前状态 | `.csp/lifecycle-state.json`（若存在）及其指向的最近验证摘要 | 当前版本、阶段、待办与最后一次观测的证据指针 | 将历史日志或完整测试报告内联到状态文件；把旧指标当本次测试 |
| L2 意图路由 | `.csp/AGENTS.md` 操作路由表 + `.csp/manifest.json` 定位查询 | 从意图/阶段找到权威的产品、代码、测试资料 | 把 500 KB manifest 全文放进会话；用 mtime 猜变更 |
| L3 任务细节 | 命中的 PRD/PMS、Spec/CMS、TMS/用例与证据 | 按任务深读与执行 | 每次启动重新读取整个项目 |

L0 是指令入口，L1 是运行状态，L2 是索引，L3 是详情。`docs/` 的活跃 PRD/战略为人可读的原文，`.csp/` 保留工程蒸馏与流程产物；测试证据的规范路径沿用本仓库 `CLAUDE.md` 约定的 `.csp/artifacts/verify/evidence/`。适配项目已有的合理路径时先登记映射，不强制移动。文件缺失时降级读取可用来源并注明缺口；不能静默创建另一份事实源。

### 2. 新鲜度与闭合规则

- `last_known_metrics` 是历史观测摘要，不是质量门禁。记录 `observed_at`、`source_commit`、`environment`、`command`、`exit_code`、`evidence_path` 与指标值；缺元数据视为未知。进入新任务可参考，声称通过或发布前必须重跑对应门禁。优先把大体积指标放 `.csp/verification/`，状态文件只存短摘要/指针，不写长历史；生命周期字段以项目已有 schema/执行器为准，不随意改写 S 阶段结构。
- `.csp/findings-baseline.json` 只存闭合检查器的存量违规豁免，不能自动合并新 findings；新发现保留在各来源的 `*FINDINGS*.json`，从它们构建可重建的开放项导航摘要，去重用稳定 ID + 来源路径，保留证据与状态。摘要不代替来源。只读路由应清楚区分“已有问题”和“允许存量违规”。
- `.csp/manifest.json` 是唯一产物索引；最近变化是从已有索引/文件或 Git 差异计算的派生视图，须带计算依据和时间。若 helper 只比较已索引的 output_path，必须如实标记范围；未实现自动分片、自动回写、所有新文件发现前不得在 skill 中宣称已实现。

### 3. 项目文件合同与大小策略

对项目入口、状态、路由、索引、资料原文、验证证据分别列出：所有者、触发时机、更新方法、敏感性、入 Git 与否、有效性检查、读者和归档条件。保留引用/证据链：活跃 PRD、TMS/CMS、未关闭 findings、被引用的视觉基线和发布快照不得按日期或文件大小自动删除/归档。棕地和 monorepo 先发现入口与数据流，再把有效路径映射到规则；可选的 `src/`/`tests/` 模板不是强制重排命令。

大小分级以**可用性**而非武断的全局绝对上限判断：自动加载的 L0 需精简，路由卡不装长历史，详情可拆子文档并留稳定索引；50/100/250 KB 可作为可配置告警示例，不能称为强制门禁，除非实际脚本/CI 兑现。保留合法的大型索引/发布历史；文件过大先定位热点，再决定拆分，不自动覆盖、删除、截断或移动。检查器输出 scan scope、实际阈值、缺失目录与退出码，默认只读。

### 4. 职责与验证

- `csp-knowledge-hub` 维护分层入口、manifest/路由契约与新鲜度术语；`csp-context-engineering` 规定按意图装载及预算。两者均把最近指标视作提示，而非通过证据。
- `csp-documentation-governance` 负责 `docs/` 对外原文与 `.csp/` 工程蒸馏边界；`csp-project-doc-architect` 设计适配的目录及引用；`csp-doc-lifecycle-manager` 负责保留、归档与反向链接；`csp-file-organizer` 只在识别权威来源和引用后提出非破坏迁移计划。
- 校正现有说明书、skill 和检查器之间的冲突，例如 `docs/strategy/ROADMAP.md`、活跃 PRD 原文、`.csp/test-spec/{module}/`、审查/复盘阶段和测试证据路径。机器检查只覆盖其真实可判定范围；高风险操作依照用户批准执行。
- 验证：大小检查器的空目录、阈值边界、路径有空格、棕地缺少 docs、JSON 索引与 Markdown 大文件夹具；技能引用/路径一致性扫描；`npm run validate:all`、`npm test`。如果未接 CI，只称本地检查，不称仓库已强制执行。

## 不采用的方式

不把开放 findings 填进违规基线；不把采集指标直接宣称实时值；不强制所有仓库使用 10 KB `CLAUDE.md`、根 `VERSION`、根 `verify/` 或固定 `src/tests` 树；不依据日期/个数自动清理 PRD、证据和历史；不以新大型“万能治理 skill”覆盖已有分工。
