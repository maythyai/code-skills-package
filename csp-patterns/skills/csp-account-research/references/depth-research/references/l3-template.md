# L3 轻度调研模板与执行规范

## 调研深度

每家公司 10-15 分钟搜索量。

## 五个核心问题

对每家公司必须回答：

1. **技术触点验证**：L2 阶段识别的信号是否可靠？有无新增/纠正信息？
2. **产品匹配初判**：
   - 哪些产品最可能匹配？（从用户提供的产品列表中选择）
   - 匹配理由（一句话）
3. **竞对关系判定**：
   - 是否已与竞对深度绑定？
   - 判定标准：四选二硬证据法（见下方）
4. **升降层建议**：
   - 维持当前层级 / 建议升一层 / 建议降一层
   - 升降理由（必须基于新发现的证据）
5. **信息可靠性评级**：[F]/[I]/[A]/[E]（详见 [evidence-system.md](./evidence-system.md)）

## 竞对深度绑定判定标准（四选二硬证据法）

必须**同时满足至少 2 条硬证据**才可判定为"深度绑定"并建议降级：

1. 公开采购合同 / 中标公告
2. 官方合作新闻稿 或 联合产品发布
3. 核心系统已迁移到竞对云（非仅试用）
4. 决策人公开背书竞对方案（会议演讲/采访）

⚠️ 以下**不构成**降级依据：

- 仅凭传闻或行业传言
- 招聘 JD 中提及某云平台（可能只是技能要求）
- 试用/PoC 阶段（尚未形成绑定）
- 非核心业务使用（如只用对象存储）

> **竞对厂商列表**：默认为空（由 brief.json 配置竞对厂商），可由 brief.json 配置覆盖。单家搜到列表外竞对则如实记录。

## 输出格式

- Markdown 报告（按层分文件：`A层轻度调研.md`、`B层轻度调研.md`、`C层轻度调研.md`）
- CSV 升降层汇总表（含字段：公司名 / 原分层 / 新分层 / 升降理由 / 证据来源 / 证据强度标签）——**编码必须 `utf-8-sig`（UTF-8 with BOM）**，详见 根 SKILL.md「CSV 输出全局硬约束」。

## L3 批量执行规则

- 按业务规模指标（按行业代入：AUM/ARR/营收/装机量等）从大到小排序
- 分批并行执行（每批 7-8 家）
- 每批完成后汇总升降层判定
- 累计升降层变动超过 20% 时暂停，请求人工审核

## 输入与输出依赖

- **上游输入**：L2 信号扫描产物（`L2_scan/全量信号扫描.csv`）
- **下游输出**：L3 升降层判定，作为 L4 名单冻结的依据
