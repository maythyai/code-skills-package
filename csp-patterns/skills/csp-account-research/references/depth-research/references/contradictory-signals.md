# 矛盾信号解读与多源信息冲突仲裁

## 核心原则

简单的加权平均会掩盖因子间的交互作用。当两个因子出现"表面矛盾"时，往往暗示更深层的信息，需要识别矛盾类型并按规则解读，而非二选一或机械求平均。

## 典型矛盾模式与解读规则

| 矛盾模式 | 表象 | 深层含义 | 建议策略 |
|---------|------|---------|---------|
| 激进态度 + 低外采 | 管理层拥抱技术但不买外部产品 | 自建能力极强，外采空间仅限"补充型"工具 | 定位"增强"而非"替代" |
| 高增长 + 低招聘 | 业务爆发但人没跟上 | 可能即将大规模招聘，或选择外包 | 6 个月后复查，可能出现窗口 |
| 融资活跃 + 技术保守 | 拿了钱但不投技术 | 资金可能用于业务扩张而非 IT | 降低技术产品期望，侧重业务工具 |
| 高透明度 + 竞对绑定 | 信息多但已被竞对覆盖 | 客户开放合作但已有选择 | 寻找竞对未覆盖的细分场景 |
| 低透明度 + 高评分 | 信息少但有限信息很正面 | 可能是隐藏的高价值客户 | 优先安排线下 BD 验证 |

## 解读流程

```
发现矛盾因子组合
  ↓
判断矛盾类型：
├─ 时间差矛盾（今年 vs 去年信息不同）→ 标注"变化信号"，取最新
├─ 维度差矛盾（态度激进但行为保守）→ 深入分析"是战略未落地还是组织惯性"
├─ 信息源差矛盾（不同来源说法不同）→ 按信息源可信度排序采信
└─ 本质矛盾（逻辑上互斥）→ 标注 [需验证]，列为 L4 重点确认项
```

## 非线性预测规则

- 同一因子在不同组合下含义不同（如"激进态度"在高外采 vs 低外采下完全不同）
- 优先级评分不是各因子的简单加法，而是"关键因子组合"决定的
- 当出现矛盾时，往往是最重要的调研线索——指向"信息不完整或行业特殊性"，应主动追查而非平均处理

## 多源信息冲突仲裁

### 信息源可信度三级体系

| 等级 | 信息源类型 | 权重 | 示例 |
|-----|----------|------|------|
| 第 1 等 | 官方确认 | 90-100% | 工商备案、官网声明、融资 PR |
| 第 2 等 | 权威独立来源 | 60-70% | 行业媒体、融资数据库、高管采访 |
| 第 3 等 | 间接推断 | 20-40% | 招聘平台、社交媒体、二手报道 |

### 冲突仲裁规则

- **规则 1：不同等级冲突** → 采信高等级源
- **规则 2：同等级冲突** → 检查是否为"理解差异"、"时间差异"或"渠道偏差"，按情境采信
- **规则 3：升层 vs 降层信号同时存在** → 不做二选一，按权重 + 时间综合判断，标注"需复审"

### 时间衰减权重

```
当前权重 = 原始权重 × max(0.5, 1 - 信息月龄 / 有效期月数)
```

超过有效期的信息权重不归零，最低保留 50%，但需主动标注"信息可能过期"。

### 矛盾决策树

```
发现信息矛盾
├─ 数值矛盾（如规模不一致）→ 选权重最高 + 最新的
├─ 逻辑矛盾（如"自建" vs "云采用"）→ 检查是否为不同部门/时间段
├─ 时间矛盾（新旧表述不同）→ 取较新的，标注"变化信号"
└─ 升降层同时信号 → 综合判断，标注"需 L3 复审"
```

### 矛盾详情记录

每当发现矛盾，必须在调研报告中记录如下表格：

| 公司名 | 信息维度 | 源 A 结论 | 源 B 结论 | 最终采信 | 理由 | 后续验证 |
|-------|---------|----------|----------|---------|------|---------|

该表格作为后续 L4 复审与升降层调整的输入凭据。

## 主动对抗性验证（过程动作，不进交付物）

上述「多源信息冲突仲裁」是**被动**处理——遇到矛盾才处理。本节补充一层**主动**对抗机制：对高 stake 论断主动制造反方搜索，挖掘隐藏的反例。

### 触发范围

L4 深度调研中每条标 [F] 的关键论断写完后必须执行一轮反方搜索，包含：

- 竞对绑定类论断（如"与竞对厂商（brief.json 配置）深度绑定"）
- 技术栈替换意向类论断（如"计划迁移到 X 平台"）
- 决策人采购态度类论断（如"CTO 全面主导 AI 中台"、"CEO 拍板 X 存预算"）
- 产品能力边界类论断（如"已自研 X 能力不需外采"、"现有架构不支持 X"）
- 深绑状态类论断（如"核心系统已迁移到 X"）

低 stake 的描述性陈述（如"招聘了 N 人"、"拼了 X 轮融资"）不需要对抗验证。

### 反方搜索词构造

原论断主语 + 反转词 + 原客体。常用反转词：

- 中文：未 / 未能 / 否认 / 矛盾 / 争议 / 质疑 / 辟谣 / 损失 / 反对 / 不及 / 暂停 / 推迟
- 英文：NOT / no / fail / abandon / dispute / criticize / contradict / decline / pull back / postpone

示例：

| 原论断 | 反方搜索词 |
|------|-----------|
| X 公司与某竞对厂商深度绑定 | `X 公司 未 采用 某竞对厂商`、`X 公司 多云策略`、`X 某竞对厂商 合作争议` |
| X 公司计划迁移到我方产品 | `X 公司 迁移 推迟`、`X 公司 我方产品 未 上线`、`X cloud migration postpone` |
| X 公司 CTO 主导 AI 采购 | `X CTO not lead AI`、`X AI 采购 决策权 分散`、`X CTO 变动` |

### 过程产物落点

本轮反方搜索的查询语句、命中片段、判定理由落到：

```
docs/account-research/process-archive/adversarial_check_<date>.md
```

格式建议：

```markdown
## 公司：<公司名>

### 论断 1：<原 [F] 论断原文>

- 反方搜索词：<查询语句>
- 命中片段：<最多 3 条最相关的原文>
- 判定：找到反例 / 未找到反例
- 如找到反例：对主画像影响 = 降级为 [I] / 加事实性补充
- 如未找到反例：仅本文件留档，不修改主画像
```

### 对主交付物的唯一影响

- **找到反例** → L4 画像 / 作战手册中相应 [F] 论断降级为 [I]，或在该论断旁加 1 句**事实性**矛盾点补充（如"另据 2026-04 同公司招聘 JD 揭示仍保留多云架构"），保持事实陈述风格。
- **未找到反例** → 主画像原状保留 [F] 论断，**不添加**任何表明"做过反方验证"的词句。

### 交付物硬约束

L4 画像 / 客户攻坚作战手册 / D1-D8 交付物 / 对外交付物中**禁止**出现以下过程性表述：

- "已做反方核验" / "已对抗验证" / "反方搜索未发现反例"
- "经多轮验证" / "证据已穷举" / "交叉验证通过"
- 任何描述"做过什么动作"而非"得出什么结论"的句子

过程产物仅作为溯源使用，不进入主交付物。设计意图：过程严谨（每条高 stake 论断都被对抗过）+ 成品干净（读者看到的只有结论和事实）。

### 与被动处理的关系

- 被动处理（上面「多源信息冲突仲裁」部分）：处理搜索过程中自然遇到的矛盾信号
- 主动对抗（本节）：对 L4 画像中的高 stake 论断主动制造反方搜索，发现隐藏反例
- 两者产出都可能触发上述仲裁规则（高等级优于低等级、新优于旧、不静默选边）
