# 间接推断路径设计规范

## 核心认知

直接搜索失败不等于"该信息不存在"。不同行业的信息可获得性差异巨大，当直接搜索无果时，应启动结构化的"间接推断路径"，而非直接标记 [E] 放弃。

## 间接推断的通用四层架构

对任何维度的信息，当第 1 层直接搜索失败时，按以下顺序逐层尝试：

```
第 1 层：直接搜索（预期命中率 80%+）
  └─ 结果：有 → 直接使用 [F]；无 → 进入第 2 层

第 2 层：关联信息推断（从其他公开信息间接推断目标维度）
  └─ 比如：从招聘 JD 推断技术栈，从融资规模推断预算，从团队规模推断工具需求
  └─ 结果：有 → 标注 [I]；无 → 进入第 3 层

第 3 层：行业类比推断（基于同规模/同类型已知公司的数据推算）
  └─ 比如：已知 A 公司 150 人团队 ≈ 800 GPU，则同规模 B 公司可按此比例估算
  └─ 结果：有 → 标注 [A] + 类比依据；无 → 进入第 4 层

第 4 层：标记 [E] + 记录已尝试路径
  └─ 必须记录所有已尝试的搜索路径和失败原因，供后续补充时参考
```

## 常见维度的间接推断路径模板

以下是常见信息维度的结构化推断路径，可按行业特征调整：

### 算力/基础设施规模（当直接搜索无果时）

1. 招聘 JD 关键词推断（JD 中出现具体硬件型号/平台名称）
2. IDC/数据中心/机房租赁新闻
3. 硬件供应商合作公告
4. 团队规模类比法（基于已验证公司的"人均资源比"）

### IT 预算/技术投入规模（当直接搜索无果时）

1. 从业务规模指标 × 行业基准 IT 投入比例估算（按行业代入：AUM/ARR/营收/装机量等）
2. 从技术团队人数 × 人均薪酬估算
3. 从融资规模和"技术投入"表述推断
4. 从同行业同规模已知数据类比

### 技术栈选型（当直接搜索无果时）

1. 招聘 JD 中的技能要求推断（如要求"Kubernetes 经验" → 推断已采用容器化）
2. 开源贡献/GitHub 活动推断
3. 技术大会演讲中提及的工具链
4. 合作伙伴/集成商公告反推

### 竞对关系（当直接搜索无果时）

1. 招聘 JD 中的平台/供应商技能要求
2. 供应商官网案例库/合作客户列表
3. 行业媒体合作报道
4. 技术社区讨论中的厂商提及

## 推断结果与证据强度标签的映射

| 推断层级 | 证据标签 | 使用规则 |
|---------|---------|--------|
| 第 1 层：直接搜索 | [F] | 一手证据，可单独作为分层依据 |
| 第 2 层：关联推断 | [I] | 有至少 1 条间接证据链支撑，可用于分层判定 |
| 第 3 层：类比推断 | [A] | 仅基于行业惯例或类比，仅作参考不作为分层主依据 |
| 第 4 层：无法推断 | [E] | 不参与评分，标注已尝试路径供后续补充 |

## 类比推断的安全规则

类比推断容易过度外推，必须遵守：

1. **类比基座必须有硬数据**：类比参照公司的数据本身必须是 [F] 或 [I] 级别
2. **类比范围限定**：只能在同行业、同规模层级（±50%）的公司间类比
3. **输出区间而非点值**：类比推断结果必须给区间（如"500-1000 张 GPU"），不得给精确数字
4. **标注类比来源**：明确写出"基于 XX 公司的 YY 数据推算"
