# L4 横向对比、定性画像与客户架构分类模型

## L4 横向对比分析方法论

### 核心认知

单家公司的深度调研只是"纵向挖掘"，真正的战略价值来自"横向对比"——多家公司放在一起比较时，"谁先打、为什么"的逻辑才能浮现。

### 对比分析四步法

#### 第 1 步：核心发现对比矩阵

将同批次的公司按关键维度并排对比：

```
| 维度 | 公司 A | 公司 B | 公司 C | 公司 D |
|------|-------|-------|-------|-------|
| 规模 | ... | ... | ... | ... |
| 技术架构 | ... | ... | ... | ... |
| AI 成熟度 | ... | ... | ... | ... |
| 切入难度 | ... | ... | ... | ... |
| 预估年收入 | ... | ... | ... | ... |
| 优先级评分 | ... | ... | ... | ... |
| 竞对风险 | ... | ... | ... | ... |
```

关键共性发现和关键差异发现分别用一句话提炼。

#### 第 2 步：各公司定性画像

每家公司产出一段"叙事性画像"（见下方"定性画像一段话描述法"）。

#### 第 3 步：按产品线分析匹配度

不是按公司看产品，而是按产品看公司——这样可以发现"某产品最适合哪类客户"的规律：

```
产品 X 匹配度：
| 公司 | 匹配度 | 核心理由 |
|------|--------|----------|
| 公司 A | ★★★★★ | ... |
| 公司 B | ★★★☆☆ | ... |
```

#### 第 4 步：优先攻坚路径排序

综合商业价值、切入难度、竞对风险等因素，产出分级攻坚建议：

```
第一优先级（立即启动）：公司 X
- 切入方向：...
- 接触路径：...
- 目标节点：...

第二优先级（近期跟进）：公司 Y
第三优先级（等待窗口）：公司 Z
```

### 对比分析的核心价值

对比分析不仅是排序，更重要的是发现：

- **方法论验证**：L2 分层预测与 L4 实际是否一致？哪些走眼了？
- **行业规律提炼**：同层级公司是否有共同特征？
- **资源分配依据**：有限资源先投入哪里？

## 定性画像一段话描述法

### 核心认知

L4 深度调研产出的结构化数据非常详细，但读者（尤其是销售团队）最需要的是一段浓缩的"定性画像"——用一段话让读者快速建立对该客户的整体认知。

### 四层结构

```
第 1 层：一句话定义（标题）
  └─ 格式："【核心特征】的【行业定位】"
  └─ 示例："全球算法头部中国玩家，AI 化程度最高"

第 2 层：核心逻辑链（为什么得出这个结论）
  └─ 从创始人背景/技术架构/行业地位等起点，逻辑推导至"为什么这家公司是这样"
  └─ 示例："创始人斯坦福博士+Citadel/Two Sigma 双重背景，将全球最成熟的 AI 量化范式直接移植国内……"

第 3 层：反直觉/非显赫洞察（增加阅读价值）
  └─ 指出一个读者可能不会想到的关键信息
  └─ 示例："这类机构对工具性 AI 产品接受度更高，因为研究员本身懂技术，价值判断效率高，采购不需要长期教育"

第 4 层：嵌入式战术建议（可执行）
  └─ 在叙事中自然地嵌入切入点建议
  └─ 示例："切入点是研究员侧自下而上的产品试用，绕过高层决策路径"
```

### 写作规则

1. **一段话定义必须能让没读过报告的人在 5 秒内建立认知**
2. **核心逻辑链不超过 3 句**，每句必须有因果关系
3. **反直觉洞察不能是显而易见的信息**，必须是"想不到但一说就懂"的类型
4. **战术建议不能是"要建立关系"这样的废话**，必须具体到"通过什么渠道触达谁"
5. **总长度控制在 150-250 字之间**

### 与结构化数据的关系

定性画像不是替代结构化表格，而是"放在结构化数据前面的导读"——让读者先建立整体印象，再看细节数据。

## 客户技术架构分类模型构建方法论

### 核心认知

客户不是同质的。同一行业内，不同客户的 IT 架构模式可能完全不同，直接影响产品匹配和销售策略。应在 L4 调研中期（10-15 家完成后）归纳出该行业的"典型 IT 架构分类"，为产品匹配和资源分配提供结构化基础。

### 架构分类模型构建四步法

**第 1 步：从已有数据中提取架构特征**

对已完成 L4 的公司，按以下维度提取其 IT 架构特征：

- 自建 vs 外采比例（全自建 / 混合为主 / 云为主 / 无自建）
- 团队规模与结构（技术占比、是否有独立基础设施团队）
- 技术发展阶段（全面 AI 化 / 部分 AI 化 / 传统+尝试 / 传统模式）
- 年 IT 投入规模（绝对值 + 占业务收入比）
- 外采开放度（完全开放 / 部分开放 / 极为封闭）

**第 2 步：聚类分组，识别 3-6 种典型模式**

根据特征组合，将公司归入几种"原型"：

```
典型分类维度组合：
── 自建程度（核心轴）× 技术发展阶段 × 规模

每种原型应包含：
- 命名：[字母编号] + [三个关键词定义]
- 定义特征：3-4 个确定性属性
- 占比：该类型在样本中的比例
- 代表公司：2-3 家典型
```

**第 3 步：为每种类型构建"五分钟快速识别指标"**

为让一线销售快速判断客户属于哪种架构类型，需提取"可观察指标"——即不需要内部数据、仅通过公开信息 5 分钟内可判断的指标：

```
| 观察维度 | A 型信号 | B 型信号 | C 型信号 | ... |
|---------|---------|---------|---------|-----|
| 招聘岗位类型 | ... | ... | ... | ... |
| 团队规模 | ... | ... | ... | ... |
| 创始人公开发言 | ... | ... | ... | ... |
| IT 投入与业务规模比 | ... | ... | ... | ... |
| 公开的合作记录 | ... | ... | ... | ... |
```

**第 4 步：映射架构类型 → 商业价值和产品策略**

```
| 架构类型 | 单客户年收入潜力 | 成单周期 | 销售难度 | 值得投入的资源级别 |
|---------|-------------|---------|---------|------------------|
| A 型 | ... | ... | ... | ... |
| B 型 | ... | ... | ... | ... |
| C 型 | ... | ... | ... | ... |
```

该映射直接指导销售资源分配和产品推荐策略。

### 架构分类的应用规则

- **分类数量**：3-6 种为宜（太少无区分度，太多不便记忆）
- **命名要求**：使用"字母编号 + 三关键词"格式（如 "B 型：自建主导 + 弹性补充型"），便于快速沟通
- **覆盖率要求**：分类必须覆盖样本中 ≥ 90% 的公司，少数异常可单独标注
- **迭代更新**：随着 L4 样本增加，可能需要拆分或合并某些类型
