# 批量评分一致性保障机制

## 问题背景

大规模批量评分中，评分者会产生"标准漂移"：第 1 批严格、第 N 批可能放松，导致同等条件的公司在不同批次评分不一致。

## 三层保障机制

### 第 1 层：评分前标准锁定

- 从已完成的 L4 精评案例中选取 2-3 个"标准样本"
- 对标准样本的每个维度记录"为什么打这个分"的详细理由
- 所有后续评分以此为参照基准

### 第 2 层：批次内对标检查

- 每完成一个批次（7-8 家），选该批中"最接近标准样本"的 1-2 家做对标
- 检查评分逻辑与标准样本的一致性
- 偏差 > 0.5 分时触发该批次复审

### 第 3 层：批次间差异检测

- 所有批次完成后，计算批次差异系数：

  ```
  差异系数 = |本批次均分 - 标准批次均分| / 标准批次均分
  ```

- < 5% → 稳定通过
- 5-10% → 可接受，标注"偏差已知"
- \> 10% → 触发全批复审

## 评分漂移预防

- 单人单日评分不超过 5 家（避免疲劳效应）
- 每批完成后复盘 1-2 个对标样本
- 维护"标准演进日志"记录任何标准调整及理由

## 流水线模式下的一致性兜底

当启用安全阈值流水线时，硬 A 公司在全量 L2 完成前已进入 L3。全量 L2 完成后需做一次兜底校验：

**校验步骤**：

1. 计算全量批次间差异系数（标准流程）
2. 若差异系数 ≤ 10%：通过，无需回溯
3. 若差异系数 > 10%：
   - 检查已进入 L3 的硬 A 公司，重新按全量标准计算其得分
   - 若重算后仍 ≥ 22 分：无影响，L3 结果有效
   - 若重算后降至 20-22 分（进入边界区）：在其 L3 报告中追加标注"全量校准后分数下调至 X 分，L3 结论仍有效但需留意"
   - 若重算后降至 < 20 分（跌出 A 层）：标记为异常，报告用户决定是否保留 L3 结论

**设计意图**：由于硬 A 门槛（22 分）比 A 层阈值（20 分）高 2 分，提供了足够缓冲。即使出现 10% 漂移，22 分的公司降至 19.8 分的概率极低（需要均分偏移超过 2 个绝对分值）。这就是"安全阈值"的安全性所在。

### 第 4 层：批次快照持久化与跨批对比

借鉴 CI 系列的快照对比机制，每个 L2 批次完成后保存结构化评分快照至磁盘，供后续批次对标和最终一致性校验。

#### 快照格式

```json
{
  "batch_id": 1,
  "completed_at": "2026-06-09T10:00:00",
  "companies_count": 8,
  "stats": {
    "mean_score": 18.5,
    "std_dev": 3.2,
    "layer_distribution": {"A": 2, "B": 4, "C": 2}
  },
  "calibration_samples": [
    {
      "company": "XX公司",
      "score": 22,
      "layer": "A",
      "key_dimensions": {
        "招聘信号": 4,
        "技术选型": 3,
        "合作关系": 5
      }
    }
  ],
  "scoring_criteria_hash": "<当前评分标准版本标识>"
}
```

#### 字段说明

| 字段 | 类型 | 说明 |
|------|------|------|
| batch_id | int | 批次序号（从 1 开始） |
| completed_at | string | 批次完成时间（ISO 8601） |
| companies_count | int | 本批次评分公司数 |
| stats.mean_score | float | 本批次均分 |
| stats.std_dev | float | 本批次标准差 |
| stats.layer_distribution | object | 本批次各层分布 |
| calibration_samples | array | 对标样本（选本批中最接近标准样本的 2 家） |
| scoring_criteria_hash | string | 评分标准版本标识（如 brief.json 的 md5 前 8 位） |

#### 跨批对比算法

每个新批次开始前，读取上一批次快照：

1. 从上批次 `calibration_samples` 中选 2 家，重新用当前标准打分（仅对核心维度快速评估，无需全量搜索）
2. 对比重打分结果与原始分数：
   - 偏差 ≤ 1 分 → PASS（标准稳定）
   - 偏差 1-2 分 → WARN（标准轻微漂移，标注"偏差已知"继续执行）
   - 偏差 > 2 分 → FAIL（标准严重漂移，暂停并向用户报告）
3. FAIL 时向用户报告："第 N 批次评分标准可能发生严重漂移，对标样本偏差 X 分。建议复审本批已完成评分或调整评分标准后重新执行。"

#### 快照存储路径

`.csp/account-research/state/<slug>/docs/account-research/process-archive/batch_snapshots/batch_<N>_snapshot.json`

#### 与 account_research_toolkit.py 集成

新增两个命令支持快照操作：

```bash
# 保存批次快照
python <skill_dir>/references/account_research_toolkit.py save-batch-snapshot \
  --csv <L2评分CSV路径> --batch <批次号> --output <快照输出路径>

# 检测批次间漂移
python <skill_dir>/references/account_research_toolkit.py check-batch-drift \
  --prev-snapshot <上批快照路径> --curr-csv <当前批次CSV路径> --tolerance 1.0
```

#### 与现有三层机制的关系

- 第 1-3 层聚焦"人工判断标准是否一致"（认知层面的对标）
- 第 4 层聚焦"数据持久化与自动化检测"（技术层面的兜底）
- 两者互补：第 1-3 层预防漂移，第 4 层在漂移已发生时及时发现

### 注意力退化防护

大规模批量评分（≥ 30 家）时，LLM 在后期容易出现：
- 评分标准无意识松弛（前期严格、后期宽松）
- 模板化表述替代真实搜索判断
- 跨公司信息混淆（前序公司的信号被套用到当前公司）

**防护手段组合**：

| 手段 | 触发条件 | 作用 |
|------|---------|------|
| 批次快照对比（第 4 层） | 每批次完成后 | 量化检测均分漂移 |
| 批次后期强制减速 | 第 20 家之后每 5 家 | 强制回顾标准样本 |
| 逐家上下文隔离 | 每家完成后 | 物理阻断信息串台 |
| 搜索结果落盘 | 每次搜索后 | 提供事后审计能力 |

四层手段互补：快照检测漂移（事后发现），减速机制防止漂移（事中预防），隔离防止串台（结构保障），落盘提供审计（可追溯性）。
