# Phase 0：任务定义与行业快速画像

## 目标

在启动调研前，用自然语言与用户对话，收集足够信息确定调研范围和深度，产出 `brief.json` 作为后续所有 Phase 的依据。

## 反模式清单（禁止行为）

Agent 在 Phase 0 必须避免的 6 类越界行为：

1. ❌ 跳过 Phase 0 直接进入 L1
2. ❌ 用默认值 / 行业常识 / 推断填补用户未明确提供的必填信息
3. ❌ 在用户未上传产品资料前推进到下一层（产品资料是必经节点）
4. ❌ 把多层问题合并成一长串「一口气问完」
5. ❌ 自答用户确认（如「我假设你已确认，继续执行」）
6. ❌ 向用户暴露内部编号（L1/L2/L3/L4、D1-D8、Phase、brief.json 等）

## 交互原则

1. **禁止暴露内部编号**：不得向用户提及 L1/L2/L3/L4、D1-D8、Phase 等内部概念。用场景化自然语言描述。
2. **分轮对话**：每层问题独立成轮，输出后等用户回复，再进入下一层。禁止一次性列出 10 个问题。
3. **有默认值的不必问**：如果用户没提，竞对默认为空（由 brief.json 配置竞对厂商），不必追问。
4. **已有信息跳过**：如果上下文已经明确了某些信息（如用户直接说了行业和名单），直接确认即可。

## 交互方式映射（枚举/开放/资料）

不同字段用不同的问法，禁止统一塞进一个开放问题让用户打字。

| 字段 | 字段类型 | 优先方式 | 备选方式 |
|---|---|---|---|
| user_role | 枚举（4 选 1）| blocking question 工具弹选项 | 文本编号列出（1/2/3/4 选 1）|
| audience | 枚举（3 选 1）| blocking question 工具弹选项 | 文本编号列出 |
| depth | 枚举（3 选 1）| blocking question 工具弹选项 | 文本编号列出 |
| execution_path | 枚举（4 选 1）| Agent 自动推断后用文字向用户描述并征求确认 | — |
| purpose / focus | 开放（要细节）| 文本开放回答 | — |
| products | 资料型（多/复杂）| **上传文件**（PDF/PPT/Word/Excel）或给产品官网链接 | 少量产品时口述 |
| 公司名单 | 资料型 | **上传文件**（CSV/Excel）或给链接 | 少量时口述 |
| competitors / blacklist / naming_compliance | 选问，有默认值 | 文本简短回答 | 跳过用默认 |
| 启动确认单 | 等用户回「确认」| 文本回复 | — |

说明：
- AskUserQuestion（或宿主等价 blocking question 工具），最多 4 题、每题 2-4 个选项，自动加「其他」。Phase 0 第一层可以一次问 2-3 个枚举问题，秒答。
- 不支持该工具的平台用文本编号列出（如 `1) 一线销售  2) 销售管理  3) 售前  4) 市场战略`），让用户回数字。
- **STOP 节点**（必须中断等用户操作再继续）：
  - 上传产品资料 → 等用户上传文件
  - 上传/提供公司名单（用户说有名单时）→ 等用户上传
  - 启动确认单 → 等用户回「确认」

## 四层前置信息收集

### 第一层：你是谁、给谁用（开场即此层，无独立握手）

开场即进入第一层，不要单独说「准备好了吗」一类废话。固定话术：

> 「在动手之前先确认几件事，避免做无用功。先问第一组：」

然后用 AskUserQuestion（blocking question 工具） 一次问 2 个枚举问题：

| 要收集的 | 字段 | 选项 |
|---------|------|------|
| 用户角色 | user_role | 1) 一线销售/BD  2) 销售管理  3) 售前/方案  4) 市场战略 |
| 结果使用者 | audience | 1) 自己用  2) 团队  3) 老板汇报 |

角色→产出映射（Agent 内部使用，不外露）：
- 一线销售/BD → 侧重攻坚手册、客户画像、拜访话术
- 销售管理层 → 侧重高管摘要、优先级排序、行动路线图
- 售前方案 → 侧重技术匹配、产品场景对应、决策链
- 市场/战略 → 侧重行业洞察、市场规模、竞争格局

第一层结束 → 等用户回复后进入第二层。

### 第二层：你想知道什么

用 AskUserQuestion（blocking question 工具） 问 depth（枚举），同时附一个开放追问收 purpose + focus：

| 要收集的 | 字段 | 方式 |
|---------|------|------|
| 深入程度 | depth | 枚举：1) 快速筛一遍（几天）  2) 挑几家重点深入（一两周）  3) 全部翻个底朝天（数周）|
| 使用目的 | purpose | 开放：「拿到结果后打算做什么？比如制定攻坚计划/准备某家拜访/向老板汇报机会」|
| 关注重点 | focus | 开放：「最关心哪方面？谁最可能买 / 竞对卡位 / 客户技术痛点 / 整体市场多大」|

第二层结束 → 等用户回复后进入第三层。

### 第三层：调研对象起点

开放为主，但「公司名单」字段触发条件性 STOP（用户说「我有名单」就要等文件）。

| 要收集的 | 字段 | 方式 |
|---------|------|------|
| 行业/赛道 | industry_name + scope_in/out | 开放：「调研哪个行业？有没有要排除的细分领域？」|
| 名单来源 | company_pool_source | 开放：「你手上有现成的目标公司名单吗？还是需要我先帮你圈选一批？」|
| 名单规模 | expected_count | 开放：「大概多少家？」|
| 已有信息 | existing_info | 开放：「之前跟这些公司有过接触吗？手上有没有已有的资料可以复用？」|

**条件性 STOP**：
- 用户回答「有名单」且名单 >20 家 → 提示用户上传 CSV/Excel，**等用户上传后再继续**
- 用户回答「有现成资料」 → 提示上传文件或给路径，**等用户上传后再继续**
- 用户口述少量公司名 / 说「需要你帮我圈」 → 不停，继续第四层

第三层结束 → 等用户回复后进入第四层。

### 第四层：约束条件

产品列表是必问，且大概率需要上传文件 → **必经 STOP 节点**。

| 要收集的 | 字段 | 是否必问 | 方式 |
|---------|------|----------|------|
| 我方产品列表 | products | **必问** | **上传文件 / URL / 少量口述**，三选一 |
| 竞对厂商 | competitors | 选问 | 开放回答；用户说不清 → 默认为空（由 brief.json 配置竞对厂商） |
| 黑名单公司 | blacklist | 选问 | 开放回答 |
| 产品名称规范 | naming_compliance | 选问 | 开放回答 |

#### 产品资料消化子步骤（必经）

用户上传产品资料后，Agent 必须执行以下 4 步，不得跳过：

```
1. 读完资料，提炼每个产品的：name / positioning / target_segment / 核心场景（如有）/ 主要竞品（如有）
2. 整理成一张确认表给用户：
   | 产品名 | 一句话定位 | 目标客群 | 核心场景 |
3. 等用户审一遍：可改 / 可补 / 可删
4. 用户确认后才写进 brief.json 的 products 字段
```

**STOP 节点**：用户上传资料 → Agent 消化 → 输出确认表 → 等用户审核回复。

**如果用户少量产品口述**（< 3 个），跳过文件上传，但仍需输出确认表让用户审核。

#### 委托式产品发现子步骤（用户委托 Agent 去发现某厂商完整产品线时触发）

触发条件：用户回答「产品是XX厂商的，你自己去官网找」或类似委托语义。

此场景下，Agent 不得用搜索引擎碎片搜索（逐产品搜→搜到什么算什么），必须执行以下 6 步系统性盘点：

```
Step 1 — 查记忆库：调取该厂商已有产品知识基线（SearchMemory）
Step 2 — 抓官网目录：打开厂商官方产品列表页 + AI/大模型专区，做全量盘点（WebFetch）
Step 3 — 查组织架构：搜索该厂商的事业群/产品线组织归属，从组织归属反查产品（WebSearch）
Step 4 — 补新品：搜索该厂商产品月度动态/新品发布，补漏近半年新上线的产品（WebSearch）
Step 5 — 交叉校验：Step2-4 三方比对，列出完整清单
Step 6 — 输出确认表：用户审核后可改/可补/可删
```

**硬约束**：搜索引擎在此场景下仅用于 Step 4 补漏和 Step 3 组织架构搜索，不得用于主力产品发现。Step 2 官网目录页是唯一权威全量来源。

**STOP 节点**：Step 6 输出确认表后 → 等用户审核回复。

## 用户意图 → 执行路径映射

Agent 根据收集到的信息，自动推荐执行路径。推荐时用自然语言向用户说明"我打算怎么做"，用户确认后执行。

| 用户意图（自然语言） | 内部映射路径 | Agent 该怎么跟用户说 |
|---|---|---|
| "帮我看看这个行业有哪些公司值得跟" | L1 → L2 扫描分层 | "我先帮你圈一批公司，逐个扫一遍公开信息，按值得跟进的程度分成高/中/低三档" |
| "我有名单了，帮我筛一下优先级" | L2 扫描分层（跳过 L1） | "好的，我逐家扫描公开信号，给你一个优先级排序" |
| "这几家重点客户帮我深入了解一下" | 直接 L3/L4（跳过 L1+L2） | "我来把这几家翻一遍，出一份详细的客户画像和攻坚建议" |
| "帮我出一套完整的作战方案" | 全流程 L1→L2→L3→L4→交付物 | "我从头到尾帮你做：先圈公司、逐层筛选、深入调研，最后出一套完整的销售作战材料" |
| "上次做到一半了，继续" | 从 progress.json 恢复 | "我看到上次做到了XX阶段，继续往下？" |
| "只要一份给老板的一页纸总结" | L2 扫描 + 高管摘要 | "我快速扫描一遍，然后给你一份一页纸的高管摘要" |
| "帮我准备明天拜访XX公司的材料" | 单家 L4 深度 | "我把这家公司翻个底朝天，给你一份拜访前必看的客户画像" |

## brief.json 结构

```json
{
  "industry_slug": "quant-pe",
  "industry_name": "量化私募",
  "scope_in": ["头部量化私募", "中型量化私募"],
  "scope_out": ["量化对冲基金", "公募量化"],

  "user_role": "销售管理 / 一线BD / 售前方案 / 市场战略",
  "audience": "自己用 / 团队 / 老板",
  "purpose": "制定攻坚计划 / 准备拜访 / 向上汇报 / 评估新行业",
  "focus": ["优先级排序", "竞对卡位", "技术痛点"],
  "depth": "快速筛选 / 重点深入 / 全盘深入",

  "company_pool_source": "用户提供 / agent搜集",
  "expected_count": 50,
  "existing_info": "无 / 有接触记录 / 有现成资料路径",

  "products": [
    {
      "name": "产品A",
      "positioning": "一句话定位",
      "target_segment": "目标客群",
      "core_scenarios": ["场景1", "场景2"],
      "source": "用户上传 / URL / 口述",
      "raw_files": [".csp/account-research/state/<industry-slug>/_inputs/产品A_白皮书.pdf"]
    }
  ],
  "competitors": [],
  "blacklist": [],
  "naming_compliance": {
    "official_names": ["官方称谓1"],
    "forbidden_names": ["模糊称谓1"]
  },

  "execution_path": "full / scan_only / depth_only / deliverable_only",
  "start_phase": 0,
  "created_at": "YYYY-MM-DD"
}
```

### brief.json 字段说明

| 字段 | 来源 | 说明 |
|------|------|------|
| `user_role` | 第一层收集 | 用户的组织角色 |
| `audience` | 第一层收集 | 调研结果的最终阅读者 |
| `purpose` | 第二层收集 | 拿到结果后做什么 |
| `focus` | 第二层收集 | 最关注的分析维度 |
| `depth` | 第二层收集 | 期望深入程度 |
| `existing_info` | 第三层收集 | 用户已有的信息底子 |
| `products[].source` | 第四层消化 | 产品信息来源（上传/URL/口述）|
| `products[].raw_files` | 第四层消化 | 原始资料文件路径清单 |
| `competitors` | 第四层收集 | 竞对厂商列表（有默认值）|
| `blacklist` | 第四层收集 | 不碰的公司列表 |
| `execution_path` | Agent 自动推断 | 根据意图映射的内部执行路径 |
| `start_phase` | Agent 自动推断 | 从哪个阶段开始执行 |
```

## 行业快速画像（Phase 0 子步骤）

进入新行业前，必须完成以下行业级认知建模，为后续所有 Phase 提供上下文基座。

### 行业 IT 架构分层模型

对目标行业构建"IT 系统分层图"，识别每层的外采可能性：

```
对目标行业，回答以下问题：

1. 该行业的核心业务系统有哪些层级？（如：交易执行层/策略研发层/数据层/工具层/办公层）
2. 每一层对数据安全/延迟/合规的要求分别是什么？
3. 每一层上云或外采的可能性如何？（极低/低/中/高）
4. 我方产品可以切入哪些层级？
```

产出：`行业 IT 架构分层表`（层级名 × 安全要求 × 外采可能性 × 对应产品机会）

### 行业信息源优先级评估

不同行业的公开信息密度差异巨大，需提前评估可用信息源：

| 信息源类型 | 预期信息密度 | 在本行业的适用度 |
|---|---|---|
| 招聘平台 | 高/中/低 | 高=该行业大量在招聘平台发布 JD |
| 技术博客/开源 | 高/中/低 | 高=该行业有技术分享文化 |
| 行业媒体/财经报道 | 高/中/低 | — |
| 学术论文/会议 | 高/中/低 | 高=该行业学术产业联动强 |
| 工商/监管数据 | 高/中/低 | — |
| 行业协会/排名 | 高/中/低 | — |

产出：信息源优先级排序 + 预期信息获取率估算

### 行业保密文化评估

| 评估维度 | 回答 |
|---|---|
| 该行业整体保密程度 | 极高/高/中/低 |
| 技术架构是否公开 | 是/部分/否 |
| 管理层是否经常公开发声 | 经常/偶尔/极少 |
| 采购合作信息是否公开 | 是/部分/否 |
| 行业特殊原因 | （描述为什么保密/公开）|

产出：行业保密等级判定 → 影响后续 L2/L3 的"信息缺失"容忍度设置。

### 行业 vs 通用企业差异点（5 维度）

快速回答以下 5 个差异维度，建立"这个行业和普通企业客户有什么不同"的认知：

1. **IT 的角色**：提效工具 vs 核心生产要素？
2. **技术自信度**：愿意外采 vs 倾向自建？
3. **数据敏感度**：低/中/高/极高？
4. **决策链长度**：多层审批 vs CTO 直接拍板？
5. **采购金额模式**：大单制 vs 持续小额消费？

产出：`行业特征画像`（5 维度表格）→ 直接影响产品推荐策略和攻坚路径设计。

### 行业业务运行逻辑（价值链地图）

上面 4 个子步骤回答的是"怎么卖给这个行业"，本步骤回答"这个行业本身在干什么"——让销售能理解客户的业务语言，也让后续产品匹配从客户痛点出发推导而非硬套。

对目标行业，构建一张业务价值链地图，回答以下问题：

```
1. 价值链全景：这个行业从原料/投入到最终收入的完整链条是什么？
   （示例-游戏：IP获取 → 研发(引擎/美术/程序) → 测试 → 版号申请 → 发行/渠道 → 上线运营 → 变现 → 持续更新）
   （示例-量化私募：策略研发 → 回测验证 → 实盘交易 → 风控监控 → 清算结算 → 投资者服务）

2. 每个环节的核心动作与技术依赖：
   | 价值链环节 | 核心动作 | 主要技术/资源依赖 | 对算力/AI/数据的天然需求 |

3. 收入模型与成本结构：
   - 主要收入来源（卖产品/卖服务/交易佣金/广告/订阅...）
   - 关键成本项（哪些环节烧钱最多）
   - 毛利结构特点

4. 行业当前的关键趋势/压力，以及如何转化为技术需求：
   （示例-游戏：版号收紧 → 单品投入加大 → AI辅助内容生成降本；出海潮 → 需要全球基础设施）

5. 云/AI 天然契合点汇总表：
   | 价值链环节 | 客户痛点 | 我方可对应的产品/能力 | 切入合理性说明 |

6. 行业术语速查（10-20 个关键术语）：
   销售跟客户对话时必须理解的基本概念及一句话解释
```

产出：`行业业务运行逻辑表`（价值链全景 + 环节-技术依赖映射 + 收入成本结构 + 趋势压力 + 产品契合点 + 术语表）

**特殊说明**：
- 本步骤每个行业只需做一次，复用于后续所有公司级调研
- 信息源以公开的行业报告、从业者访谈文章、上市公司年报为主
- 产品契合点必须基于价值链推导得出，禁止从产品列表出发硬套（反模式）

## 启动确认单（Phase 0 末尾必经节点）

四层信息收集完、产品资料消化完、行业快速画像产出完、执行路径推断完之后，Agent 必须输出一份「启动确认单」给用户，**用户明确回复「确认」两个字才能进入 Phase 0.5 / Phase 1**。

### 确认单模板

```
我整理了一下，准备这么干：

- 行业/赛道：XX（排除：XX）
- 调研对象：XX 家公司（来源：你提供/我圈选）
- 重点关注：XX、XX
- 深入程度：XX（说明会做到哪一步停）
- 推进产品：
  | 产品名 | 定位 | 目标客群 |
  | XXX | ... | ... |
- 竞对关注：XX（默认/自定义）
- 排除公司：XX
