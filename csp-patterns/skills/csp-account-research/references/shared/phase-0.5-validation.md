# Phase 0.5：方法论验证批次

首次进入新行业时**必须执行**。当首次对某个行业/赛道执行调研时，不能直接全量铺开，必须先用小样本验证方法论的有效性。

## 执行规则

- 从 L1 池中选取 3-5 家代表性公司作为"验证样本"（覆盖大/中/小规模、不同细分，且至少包含 1 家通过"需求反推"路径入池的非榜单头部公司——用于验证方法论对中腰部公司的适用性）
- 对验证样本走完 L2→L3→L4 全流程
- 验证完成后产出"方法论有效性评估报告"

## 有效性评估指标

| 指标 | 计算方式 | 合格标准 |
|---|---|---|
| 信号命中率 | 有效获取信息的公司数 / 样本总数 | ≥70% |
| 各维度信息获取率 | 每个信号维度的命中数 / 样本数 | 核心维度≥60% |
| 分层预测准确性 | L2 分层与 L4 深调结论一致的比例 | ≥60% |
| 执行效率 | 每家公司实际耗时 vs 预期耗时 | 偏差<50% |
| 信息源覆盖率 | 实际可用的信息源数 / 规划信息源数 | ≥50% |

## 验证后必须产出的调整决策

1. **维度增删**：哪些维度在该行业始终搜不到信息→考虑删除或合并；该行业有独特信号维度需新增
2. **权重修正**：基于验证样本，各维度在 A/B/C 层的浓度分布→修正初始权重假设
3. **搜索策略调整**：哪些信息源在该行业无效→替换为行业特定渠道
4. **分层阈值校准**：验证样本的分数分布是否适合初始阈值→按实际分布调整
5. **时间预估修正**：实际单家耗时→修正全量铺开的资源规划

## 跳过条件

仅当对同一行业的同一调研场景有过成功验证经验时可跳过（换行业必须重新验证）。

---

## 问题根因分类法

方法论验证中发现的问题必须进行根因分类，避免"因为某家公司搜不到信息就认为方法论失效"的错误归因。

### 四类根因模型

| 根因类型 | 定义 | 典型表现 | 正确处置 |
|---|---|---|---|
| 输入端质量问题 | 名单本身有误（名称不准、公司已注销、重复条目）| 搜索无法定位公司主体 | 回 L1 校验名单，通过工商系统确认后重新执行 |
| 方法论局限性 | 搜索策略在该行业不适用 | 某个维度在该行业所有公司都获取率<30% | 调整维度定义或替换为行业特定信息源 |
| 行业结构性特征 | 行业整体保密/低透明度导致信息缺失 | 多数公司均缺失同一维度 | 调整容忍度、降低该维度权重、标注"需线下 BD 补充" |
| 工具端效率问题 | 搜索工具限流、语言障碍、平台变更 | 执行速度异常慢或某平台全部失败 | 更换工具/平台，调整执行节奏 |

### 分类判定决策树

```
发现问题（某家公司信息获取失败）
├─ 该公司名称能否通过工商系统确认？
│  ├─ 否 → 输入端质量问题（不计入方法论有效性统计）
│  └─ 是 → 继续判断
├─ 同行业其他公司该维度是否也获取失败？
│  ├─ 多数失败（>60%） → 行业结构性特征（不是方法论问题）
│  └─ 仅少数失败 → 继续判断
└─ 是否换工具/换搜索策略后可解决？
   ├─ 是 → 工具端效率问题
   └─ 否 → 方法论局限性（需调整维度或信息源）
```

### 与有效性指标的衔接

计算"信号命中率"等指标时，应先排除"输入端质量问题"的样本，仅用"确认可定位的公司"作为分母：

```
修正后命中率 = 有效获取信息的公司数 / (样本总数 - 输入端质量问题数)
```

这避免了因名单质量问题而错误地判断方法论无效。

- [ ] 验证样本 3-5 家全部走完 L2→L3→L4
- [ ] 5 项有效性指标已计算
- [ ] 5 项调整决策已产出
- [ ] 问题根因已分类
- [ ] 修正后命中率已计算
- [ ] 用户已确认"方法论可用"
