# Anti-patterns（反模式）

本文记录在 B2B 客户批量调研中常见的错误做法。Agent 在执行任何 Phase 时若识别到下列模式，必须立即停止并告知用户。

## 编排相关反模式

### AP-1：跳过 Phase 0.5 直接全量铺开

- **错误表现**：首次进入新行业，未做小样本方法论验证就直接对全量公司执行 L2
- **风险**：方法论失效未被及时发现，浪费数十家公司的调研工时
- **正确做法**：首次进入新行业必须先完成 Phase 0.5，验证报告通过后才能进入 Phase 1 全量

### AP-2：跨 Phase 跳步

- **错误表现**：未完成 L2 分层就直接做 L4 深度调研；未完成 L3 升降层就生成交付物
- **风险**：缺失中间产物导致下游决策失去依据
- **正确做法**：严格按 L1→L2→L3→L4→L5 顺序，每 Phase 通过门禁后才能进入下一 Phase

### AP-3：人工确认节点形式化

- **错误表现**：在分层结果或 TOP 名单产出后，未让用户实质审阅就标记 confirmed=true
- **风险**：错误的分层判断累积到下游
- **正确做法**：每个强制人工确认节点必须输出"差异说明 + 待决策项"供用户实质审阅

## 数据相关反模式

### AP-4：以推测填充信息缺失

- **错误表现**：找不到某公司的某维度信息时，用"通常该规模公司应该有 X"填空
- **风险**：交付物中混入虚构数据
- **正确做法**：标注 `[信息缺失]` 或 `[待验证]`，并记录已尝试的搜索路径

### AP-5：单一信息源依赖

- **错误表现**：仅靠招聘平台或仅靠官网就完成 L2 信号扫描
- **风险**：单一渠道偏差导致系统性误判
- **正确做法**：每家公司至少使用 3 类信息源（如招聘+技术博客+采购公告），缺失时明确标注

### AP-6：忽略工商名称校验

- **错误表现**：用用户提供的"通用名"或"简称"直接搜索，搜不到信息就归因为"信息保密"
- **风险**：把"输入端质量问题"误判为"方法论失效"或"行业保密"
- **正确做法**：Phase 1 强制工商名称校验，名称不准确的不得进入 L2

## 评分相关反模式

### AP-7：批次间标准漂移

- **错误表现**：第 1 批评分严格、第 5 批宽松，且未使用标准样本对标
- **风险**：分层结果不可比，TOP 名单失真
- **正确做法**：参考 [批量评分一致性保障机制](./batch-scoring-consistency.md)

### AP-8：忽略升降层动态调整

- **错误表现**：L2 分层后视为最终结论，L3/L4 阶段发现新信号也不调整分层
- **风险**：错过升层机会或继续投入已不值得的客户
- **正确做法**：参考 [渐进收敛规则](./progressive-convergence.md) 中的升降层信号与调整力度
- **自查触发词**：L3/L4 报告中如果出现以下关键词，必须触发升降层复审，不允许只记录信号但不调整分层：
  - 升层触发词：“新设 AI 部门”“新建技术团队”“竞对方案失败”“重新招标”“完成融资”“独立预算”
  - 降层触发词：“全部自研”“零外采”“深度绑定竞对厂商（brief.json 配置）”“排斥外采”“管理层明确反对”

## 行业适配反模式

### AP-9：跨行业方法论强搬

- **错误表现**：互联网行业（A 型）的方法论直接套到量化私募（C 型）
- **风险**：维度权重错配，例如对私募强行评分"技术博客活跃度"
- **正确做法**：参考 [行业类型适配规则](./industry-type-adaptation.md)，跨类型必须重做 Phase 0.5

### AP-10：低透明度行业用高透明度阈值

- **错误表现**：在保守型行业沿用开放型行业的"信息缺失即降权"规则
- **风险**：把行业结构性特征误判为该公司不值得投入
- **正确做法**：参考 [Phase 0.5 问题根因分类法](./phase-0.5-validation.md)，区分"行业结构性特征"与"方法论局限性"

## 产品发现反模式

### AP-11：用搜索引擎碎片替代官方产品目录做产品盘点

- **错误表现**：当用户委托 Agent 自己去发现某厂商完整产品线时，Agent 用搜索引擎逐个关键词搜索（如"我方产品+子产品A""我方产品+子产品B"），搜到什么算什么，遗漏大量产品后等用户纠正再补搜，陷入"打地鼠"循环
- **风险**：产品清单严重不全，导致后续产品匹配、场景切入的调研基础失真；用户反复纠正消耗信任
- **正确做法**：参考 [Phase 0 委托式产品发现子步骤](./phase-0-task-definition.md)，严格按「记忆库→官网目录→组织架构→新品补漏→交叉校验」6 步执行。搜索引擎仅用于组织架构搜索和新品补漏，不得替代官网目录页作为主力发现来源
- **真实案例**：教育科研行业调研启动时，Agent 连续三轮产品清单都遗漏了秒悟、析言GBI、全妙、HappyHorse、千问云等产品，根因就是每次都用搜索引擎碎片搜索而非系统性盘点官网目录

### AP-12：搜索结果未落盘即引用

- **错误表现**：Agent 在评分或画像中引用了搜索获得的信息，但未将搜索原始返回片段落盘至 search_evidence 目录
- **风险**：无法事后审计"这条信息是真的搜到了还是编造的"，幻觉逸出概率大增
- **正确做法**：每次 WebSearch/WebFetch 调用后，立即将原始返回片段落盘至 `.csp/account-research/state/<slug>/docs/account-research/process-archive/search_evidence/`；评分/画像中引用的 [F] 信息必须在 search_evidence 中有对应原文
