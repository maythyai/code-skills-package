# 跨 Skill 数据传递与容错规范

## Phase 间的严格依赖规则

```
signal-scan 的输出 → depth-research 的输入
depth-research 的输出 → deliverable 的输入
```

**依赖校验规则**：

- 下游 Skill 启动前，必须校验上游输出的完整性和格式正确性
- 校验失败时不得"带伤前进"，应回退修复上游

## 上游失败时的降级策略

| 失败场景 | 影响 | 降级方案 |
|---------|------|---------|
| L2 扫描某家公司信息不足 | 该公司无法准确分层 | 标注"信息缺失"，L3 时优先补充搜索 |
| L3 复审大幅降层 | 已规划的 L4 报告失效 | 取消该公司 L4，释放资源给新升层公司 |
| L4 深调发现关键信息矛盾 | 分层判定可能有误 | 回溯更新 L2/L3 评分，必要时调整分层 |
| 某 Phase 执行中断（如 API 限流）| 部分公司未完成 | 标记"待补充"，下一批次优先处理 |

## 数据版本对齐

当中间 Phase 的数据被更新时：

- **向下传播规则**：L2 更新不自动触发 L3 重做，但需在 L3 报告中标注"基于旧版 L2 数据"
- **重做触发条件**：当 L2 更新导致分层变动 ≥ 2 家时，相关 L3/L4 报告需重新执行
- **版本标注**：所有交付物标注"基于 L2 v1.2 / L3 v1.0"等版本信息

## 证据链与产物字段约束

所有 Phase 产出 CSV/Markdown 中涉及"判断/结论"的字段，必须包含：

- 证据来源 URL 或离线引用编号
- 信息抓取/发布时间
- 证据强度标签（参见 depth-research 的 `[F]/[I]/[A]/[E]` 体系）

下游 Skill 在读取上游产物时应抽样检查证据字段填充率，填充率 < 80% 视为校验失败。
