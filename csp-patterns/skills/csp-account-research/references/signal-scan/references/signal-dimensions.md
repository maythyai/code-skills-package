# 信号维度模板（13 维 + 8 子维度）

本文是 signal-scan 的核心评分骨架。Agent 在 L2 扫描启动前必须读取本文。

## 标准信号维度模板（13 维）

| 维度编号 | 维度名称 | 搜索关键词模板 | 评分规则 |
|---|---|---|---|
| D1 | AI/ML 招聘活跃度 | "{公司名} AI工程师 招聘" / "{company} machine learning engineer hiring" | 活跃(3) / 一般(2) / 无(0) |
| D2 | 技术架构公开度 | "{公司名} 技术博客 架构" / "{company} tech blog engineering" | 高(3) / 中(2) / 低(1) / 无(0) |
| D3 | 云服务使用信号 | "{公司名} AWS/Azure/GCP" | 多云(3) / 单云(2) / 自建(1) / 未知(0) |
| D4 | 大模型/LLM 使用信号 | "{公司名} GPT ChatGPT 大模型 LLM" | 已部署(3) / 在探索(2) / 无(0) |
| D5 | AI 编程工具信号 | "{公司名} Copilot Cursor AI编程" | 有(2) / 无(0) |
| D6 | 高管技术背景 | "{公司名} CTO 技术总监 背景" | CS博士/大厂(3) / 技术出身(2) / 非技术(1) |
| D7 | 业务增长态势 | "{公司名} 业务规模指标 增长 融资"（按行业代入：AUM/ARR/营收/装机量/用户数）| 爆发(3) / 稳健(2) / 平稳(1) / 收缩(0) |
| D8 | IT 预算信号 | "{公司名} IT 投入 技术团队规模" | 大团队>50(3) / 中等20-50(2) / 小<20(1) / 未知(0) |
| D9 | 竞对渗透信号 | "{公司名} 竞对厂商（brief.json 配置） 合作" | 深度绑定(-2) / 浅度使用(0) / 无(1) |
| D10 | 合规/安全需求 | "{公司名} 等保 信创 数据安全" | 强需求(2) / 一般(1) / 无(0) |
| D11 | 决策人可触达性 | "{公司名} CTO LinkedIn 会议演讲" | 高(2) / 中(1) / 低(0) |
| D12 | 已有我方产品关系 | "{公司名} 我方产品 合作" | 已合作(3) / 曾试用(1) / 无(0) |
| D13 | 外采倾向度 | 根据招聘+技术公开度+云服务综合判断 | 高(3) / 中(2) / 低(1) |

> **业务规模指标说明**：D7 中"业务规模指标"按目标行业代入对应口径——量化私募/资管=AUM、SaaS=ARR、通用企业=营收、制造业=装机量、互联网=用户数（DAU/MAU）。在 brief.json 中确认后写入。

> **厂商列表说明**：D9 的竞对列表默认为「竞对厂商（brief.json 配置）」，D12 的我方厂商默认为「我方产品」，均可通过 brief.json 配置覆盖。单家公司搜到列表外竞对时如实记录，无需修改全局列表。

## 需求信号深化：八个子维度框架

当 D1-D13 的简化评分无法充分区分客户时，可对"需求信号"维度做八个子维度的精细拆解：

| 子维度 | 信号类型 | 搜索方法 | 权重 |
|--------|---------|---------|------|
| 招聘扩张 | 新增 AI/技术岗位数量突增 | 招聘平台监测 | 高 |
| 技术动态 | 论文发表、开源贡献、技术博客 | 学术搜索 + GitHub | 高 |
| 业务增速 | 业务规模指标年增长率（按行业代入：AUM/ARR/营收/装机量等）| 财报/融资报道 | 中 |
| 合规压力 | 新法规驱动的技术采购需求 | 政策文件/行业新闻 | 中 |
| 策略演进 | 管理层公开表态的战略方向变化 | 采访/演讲/年报 | 中 |
| 团队扩张 | 新部门成立、新办公地点 | 企查查/招聘平台 | 低-中 |
| 基建瓶颈 | 现有系统不足以支撑增长 | 招聘"架构师"/技术博客抱怨 | 低-中 |
| 办公升级 | 搬迁、扩租、子公司设立 | 工商变更/新闻 | 低 |

## 矛盾信号的解读规则

当不同子维度出现矛盾时（如"业务快速增长但招聘没动静"）：

1. **时间差解释**：业务增长可能领先招聘 6-12 个月（还没来得及招）
2. **渠道差异**：可能已招但未同步到公开招聘平台
3. **组织策略**：可能选择外包而非自招

矛盾信号本身比单一信号更有价值——它指向"信息不完整"或"行业特殊性"，是 L3 需要重点验证的方向。

## 行业适配说明

13 维度是"技术型 B2B 客户"的通用模板。不同行业需微调：

- 金融/资管行业：加权 D10（合规需求高）
- 制造业：增加"智能制造/工业互联网"维度
- 互联网/AI：增加"开源贡献"维度

## 信息缺失时的补充搜索渠道

当标准搜索后某维度评 0 分且确认为"搜索无果"（非"确实不存在"）时，可尝试：

| 维度 | 补充渠道 | 搜索示例 |
|------|---------|----------|
| D3 云服务使用 | BuiltWith/技术栈识别 | WebSearch: "公司名 + 技术栈" 或 "公司名 + AWS/Azure/GCP" |
| D7 业务增长 | 招标/中标公开数据 | WebSearch: "公司名 + 中标" site:chinabidding.com |
| D9 竞对渗透 | 政府采购公示 | WebSearch: "公司名 + 某竞对厂商/某竞对厂商 + 中标" |
| D12 已有我方产品关系 | 我方产品官网案例库 | fetch_content: 我方产品客户案例页按行业筛选 |

仅在标准搜索无果时补充，不改变评分规则。命中后按正常证据标签体系标注。

## 评分计算脚本化（推荐执行）

每家公司 13 维度打分完成后，建议调用脚本计算总分和分层，避免在上下文里手动加法：

```bash
python <skill_dir>/../shared/account_research_toolkit.py compute-score \
  --scores '{"D1":3,"D2":2,"D3":0,"D4":2,"D5":0,"D6":3,"D7":2,"D8":1,"D9":0,"D10":2,"D11":1,"D12":3,"D13":2}' \
  --threshold-a 20 --threshold-b 12
```

脚本输出示例：
```json
{"total":21, "layer":"A", "top_contributors":["D1=3","D6=3","D12=3"], "missing_dims":["D3","D5","D9"], "threshold":"A>=20, B>=12, C<12"}
```

Agent 只需将脚本输出的 total 和 layer 记录到上下文，不需要自己做加法。若 Python 环境不可用，则手动计算。
