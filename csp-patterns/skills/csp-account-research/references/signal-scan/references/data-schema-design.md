# 调研数据结构分层设计

## 核心认知

调研数据的字段设计不应是"想到什么加什么"，而应按业务逻辑分层构建，每层字段服务于不同的分析目标。好的字段设计既便于数据查询，又支持后续扩展。

## 五层字段架构（通用框架，按行业调整具体字段）

| 层级 | 定义 | 字段类型 | 分析用途 |
|------|------|---------|----------|
| 第 1 层：基础标识层 | 公司身份和基本属性 | 名称/规模/地域/成立时间/行业细分 | 筛选、分群 |
| 第 2 层：基础设施层 | 技术底座和 IT 架构 | 算力模式/云服务商/自建规模/网络架构 | 产品匹配初判 |
| 第 3 层：技术栈层 | 具体技术选型和工具链 | 模型/框架/工具/平台/开发环境 | 产品匹配精算 |
| 第 4 层：商业判断层 | 采购意图和决策环境 | 预算/决策人/竞对关系/外采倾向/增速 | 优先级排序 |
| 第 5 层：产品匹配层 | 与我方产品的具体匹配 | 各产品得分/首推组合/切入路径/预期 deal size | 行动建议 |

## 字段设计三原则

1. **层级不可跳跃**：上层字段是下层字段的前置依赖（如不知道"算力模式"就无法判断"云产品匹配度"）
2. **同层字段互为补充**：同层内的字段从不同角度刻画同一层面
3. **字段应有明确分析用途**：每个字段必须能回答一个具体问题。如果无法说清"这个字段帮助回答什么决策"，则不应纳入

## 字段演进规则

- **新增字段触发条件**：当分层判定出现系统性偏差（如同一评分的公司实际 deal size 差异大），说明缺少某个关键区分字段
- **字段升权触发条件**：反向验证中发现某字段浓度差极大 → 该字段应从辅助层升至核心判断层
- **字段废弃触发条件**：该字段在所有公司中取值相同或获取率 < 30% → 无区分度，废弃或合并

## CSV 输出规范

**编码**：UTF-8 with BOM

**表头结构**（按五层顺序排列）：

```
公司名称,规模区间,所在地,...[基础标识层],算力模式,GPU类型,...[基础设施层],D1_AI招聘,D2_技术公开度,...D13_外采倾向,总分,分层,[技术栈+商业判断层],关键证据摘要
```

**关键规范**：

- 字段名使用"层级编号_中文语义名"格式（如 `D1_AI招聘`），便于按层筛选
- 每行末尾必须有 `关键证据摘要` 字段（自由文本，概括该公司的核心信号）
- 缺失值统一用空字符串表示，不用 "N/A" 或 "未知"（便于数据分析时过滤）

## Markdown 报告

- 分层统计（A/B/C/缺失各多少家）
- 各层典型代表分析
- 边界公司说明（为什么判 A 不判 B）
- 信号分布热力图（哪些维度普遍得分高/低）
