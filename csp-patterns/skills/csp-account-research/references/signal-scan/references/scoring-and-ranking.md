# 评分与分层规则

## 总分计算

D1-D13 加权求和（D9 为减分项）。满分理论值约 35 分。

## 分层标准（可按项目调整）

- **A 层**（高优先级）：总分 ≥ 20 且 D9 ≥ 0（无竞对深度绑定）
- **B 层**（中优先级）：总分 12-19 或 总分 ≥ 20 但 D9 < 0
- **C 层**（低优先级）：总分 6-11
- **信息缺失**：总分 < 6 或 超过 6 个维度为 0 分

## 信息密度归一化（可选校正，防止中小公司被低估）

当同一批次中公司间的"可评维度数"差异显著时（如头部公司 11 个维度有信息，腰部公司仅 6 个），启用归一化校正：

```
归一化得分 = (实际得分 / 有效维度数) × 13

其中：
- 有效维度数 = 13 - 得 0 分且确认为"搜索无果"的维度数
- 得 0 分但属于"确实不存在"（如确认没有 AI 岗位）的维度仍计入有效维度
- 仅"搜索无果 + 信息缺失"的维度排除
```

**启用条件**：同批次中"有效维度数"最大值与最小值之差 >= 4 时自动启用。差值 < 4 时不校正（说明信息密度差异不大）。

**注意**：归一化得分仅用于分层判定，原始得分仍保留在 CSV 中供溯源。L1_pool.csv 中标注为"需求反推"来源的公司优先触发此校正。

## 信号强度加权量化模型（可选扩展）

当需要对某维度做更精细的量化评估时，可用以下加权模型补充 D1-D13 的简化评分。

### 四维度加权评分

| 维度 | 权重 | 4 分 | 3 分 | 2 分 | 1 分 | 0 分 |
|-----|------|-----|-----|-----|-----|-----|
| 招聘信号 | 40% | 明确 AI 专岗（ML/算法/AI 基础设施）| — | 有 ML 相关但职级不明 | 泛述中提到 AI 技能 | 无 AI 岗位 |
| 技术活动输出 | 30% | 核心团队发表顶级论文 | 活跃开源项目 | 技术博客深度文章 ≥ 5 篇 | 浅度内容或转载 | 无公开输出 |
| 组织架构投入 | 20% | 独立 AI 部门/实验室，专属预算 | — | AI 人才集中但未独立建制 | 矩阵式管理 | 无专门 AI 组织 |
| 融资与战略 | 10% | — | — | 融资中明确提及 AI 战略方向 | 高管演讲强调 AI | 无特别提及 |

**总分计算**：`信号强度 = 招聘×40% + 技术活动×30% + 组织架构×20% + 融资战略×10%`

**分级标准**：

- 3.5+ → 极强 → 高优先级候选
- 2.5-3.5 → 强 → 中等优先级
- 1.5-2.5 → 中强 → 需进一步验证
- < 1.5 → 弱 → 暂不推荐投入

### 权重校准原则

不同行业需调整权重，核心原则：让最能反映该行业"技术投入认真度"的信号获得更高权重。

- **金融/资管行业**：降低招聘权重（20%），提升融资与战略权重（30%）
- **制造业**：提升技术输出权重（40%），增加"专利申请"维度
- **互联网平台**：提升开源贡献权重，增加"GitHub Stars"维度

## 因子权重排序与层级递进判定

客户分层不应是"所有维度平均打分"，而应通过权重排序实现"层级递进判定"：先看最关键因子，再看次要因子。

### 权重确定方法

**步骤 1：反向验证法**

完成首批 L2 扫描后（通常 20-30 家），用实际分层结果反向验证各维度的预测力：

```
对每个维度，计算其在 A/B/C 层的浓度分布：
维度 X 在 A 层的浓度 = （A 层中维度 X 得分 ≥ 阈值的公司数）/ A 层总数

浓度差 = A 层浓度 - C 层浓度
浓度差越大 → 该维度的区分力越强 → 权重越高
```

**步骤 2：权重排序**

| 权重等级 | 含义 | 典型维度 |
|---------|------|---------|
| ★★★★★ | 第一决定因子，直接影响是否进入 A 层 | 管理层技术态度 / 外采倾向 |
| ★★★★☆ | 强相关因子，影响 A 与 B 的边界 | AI 信号强度 / 信息透明度 |
| ★★★☆☆ | 中等因子，影响 deal size 而非分层 | 业务增长态势 / IT 预算规模 |
| ★★☆☆☆ | 辅助因子，用于同层内排序 | 竞对关系 / 决策人可触达性 |
| ★☆☆☆☆ | 背景因子，不参与分层计算 | 地理位置 / 成立时间 |

### 层级递进判定流程

```
判定起点：从最高权重因子开始

第 1 层筛选（★★★★★因子）：
  管理层态度 = 激进？
  ├─ 是 → 进入"高潜力候选池"
  └─ 否 → 降入"需进一步验证池"

第 2 层筛选（★★★★☆因子）：
  AI 信号强度 ≥ 中强？
  ├─ 是 → 维持高潜力
  └─ 否 → 从高潜力降级

第 3 层调整（★★★☆☆因子）：
  业务增长 = 爆发？
  ├─ 是 → 优先级 +0.5
  └─ 否 → 不变

最终分层 = 综合三层筛选结果
```

### 第一决定因子的行业适配

不同行业的第一决定因子可能不同：

- **技术产品型行业**：第一因子 = 管理层技术态度
- **合规驱动型行业**（金融/医疗）：第一因子 = 合规压力/政策驱动
- **成本敏感型行业**（制造/物流）：第一因子 = ROI 明确度

启动调研时应先确定本行业的第一决定因子，再按上述方法校准权重。

## 反向证伪校验（分层判定后必做）

分层判定完成后，Agent 对边界公司（A/B 线 ±2 分 & B/C 线 ±2 分）必须执行一轮反向证伪搜索，防止正向信号搜索导致的乐观偏差。

### 搜索动作

对每家边界公司，用以下模板补充搜索：

```
"{公司名} {竞对厂商名} 中标 合作"        ← 检查有无竞对绑定硬证据
"{公司名} 自研 不外采 自建"              ← 检查有无明确外采排斥信号
"{公司名} 预算 削减 暂停"                ← 检查有无预算收缩信号
```

竞对厂商列表从 brief.json 读取，默认为空（由 brief.json 配置竞对厂商）。

### 证伪信号与降分规则

| 证伪信号 | 触发条件 | 调整动作 |
|---------|---------|---------|
| 竞对绑定硬证据 | 满足四选二硬证据法（见 depth-research L3模板） | D9 降为 -2，总分同步调整 |
| 明确自研声明 | 公开采访/年报中明确说「不外采」「全自研」 | D13 降 1-2 分 |
| 预算收缩 | 公开裁员/削减IT预算报道 | D7 降 1 分 |
| 竞对中标 | 公开招标结果显示竞对中标（非我方） | D9 降为 -1 |

证伪搜索中发现降分信号 → 重新计算总分 → 可能触发降层 → 在分层报告中单独说明原因。

### 与正向评分的衔接

反向证伪结果不替代正向信号，而是补充：正向信号说明"客户可能有需求"，反向证伪回答"有没有因素会阻止成交"。两者都齐全时，边界判定更可靠。

## 执行流程总览

1. **搜索执行**：每家公司按 13 维度逐一搜索，记录信号来源 URL
2. **评分填写**：按评分规则打分，附简要证据描述
3. **分层判定**：汇总得分，按阈值分层
4. **交叉校验**：对边界公司（±2 分在阈值附近）做二次搜索确认
5. **反向证伪**：对边界公司执行反向证伪搜索（竞对绑定/自研声明/预算收缩），按证伪信号调整分数
