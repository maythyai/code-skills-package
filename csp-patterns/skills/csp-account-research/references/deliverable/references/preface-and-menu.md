## 七块使用须知（强制规范）

所有生成的交付物必须在开头包含「使用须知」部分，按以下顺序展开七块内容，顺序不可调整。

### 第1块：给谁读（受众定位）

明确不同角色的阅读路径：

```
本文档服务于以下读者：
- 一线销售：快速判断客户是否值得投入 → 阅读TOP客户卡片
- 销售总监：整体市场评估和资源分配 → 阅读行业全景+deal size
- 高管/VP：战略判断和投资价值 → 阅读高管摘要+市场空间
```

### 第2块：解决什么决策（问题聚焦）

明确文档要帮助回答的具体决策问题：
- 宏观判断：这个行业值不值得投入？（市场规模、增速）
- 排序问题：应该先打谁后打谁？（优先级排序逻辑）
- 战术问题：见了客户该说什么？（话术建议）

### 第3块：数据从哪来的（信息源透明）

分层说明数据来源：
- 直接公开信息（100%可信）：官网、融资公告、工商注册
- 推断信息（有依据但非直接）：从招聘JD推断技术栈、从融资规模推断预算
- 无法获得的信息：明确标注 `[信息缺失]`，不用于最终排序

### 第4块：哪些数字可信（可靠性分级）

三级标注系统：
- **✓ 高**（可直接用于决策）：多条独立来源交叉验证
- **◐ 中**（分类判断时可用）：单一间接证据，逻辑链清晰
- **◑ 低**（仅供参考）：推断链较长或单一弱信号

### 第5块：正确/错误的使用方式（案例教学）

- 正确：基于证据和排序逻辑做初步判断，线下验证后决策
- 错误：将估算值当作确认值直接对客户使用
- 正确：发现新信号后触发分层复审
- 错误：认为「报告已发布，数据不需要更新」

### 第6块：系统性偏差说明

模板：

```markdown
## 哪些判断有系统性偏差风险

**风险1：[XXX行业特征]导致低估**
该行业整体[XXX程度高/保密文化强/信息不对称]。约N%的公司"管理层态度"标记为"缺失"——这不代表他们没有需求，而是公开渠道查不到。
影响范围：[TOP N不受影响/中间梯队可能有X家被低估/C层可能有X家被误杀]

**风险2：新锐公司信息滞后**
成立3年内的公司公开信息少，判断更多依赖推断。这些公司的评分和deal size置信度比老牌公司低15-20个百分点。

**风险3：行业周期波动**
本手册基于[YYYY年M月]的信息快照。如果行业整体业绩大幅下滑，IT预算会收缩，所有deal size估算需要打N折。
```

### 第7块：使用边界声明

模板：

```markdown
## 本文档不能替代什么

1. **不能替代首次拜访**。手册告诉你"值得去见"，但见了之后的一手信息远比手册准确
2. **不能替代技术方案**。手册给出"首推什么产品"的方向，但具体方案要产品/售前团队出
3. **不能替代客户关系**。排名第1不代表能签单，排名第20也可能因为私人关系快速成交
```

## deal size 数字的透明度说明（强制）

所有 deal size 估算必须附带「这个数字怎么来的」说明：

```markdown
**deal size的具体数字怎么来的**：
通过"业务规模 × IT投入比例 × 新技术占比 × 外采比例 × 产品匹配系数"公式估算。
每个参数都是推测，误差叠乘后偏差可达±50%。
报告里写"800-2000万"的意思是"千万级客户"，不是说这家公司真的会花800万或2000万。
```

业务规模按行业代入对应口径：AUM（量化私募/资管）/ ARR（SaaS）/ 营收（通用企业）/ 装机量（制造业）/ 用户数 DAU/MAU（互联网）。

## 数据可靠性标注规范

所有交付物中的数据必须标注可靠性等级（与 depth-research [F]/[I]/[A]/[E] 体系映射）：

| 交付物标签 | depth-research 标签 | 含义 |
|------------|------------------------|------|
| [确认] | [F] Fact | 有直接公开证据 |
| [强推断] | [I] Inference | 多条间接证据支撑 |
| [弱推断] | [A] Analogy | 类比推断或单一弱证据 |
| [信息缺失] | [E] Empty | 无法获得相关信息 |

## 全局文风硬约束（适用所有 D1-D8）

全系列交付物使用正式商业咨询报告语调（McKinsey/Bain 风格），直接陈述事实、给出数据、推导结论。

### 禁用表达类型

| 类型 | 禁用示例 | 应替换为 |
|------|---------|----------|
| 空洞 buzzword | 赋能、深度赋能、打通壁垒、弯道超车、构建护城河、引爆增长、颠覆式创新 | 用具体动作描述："为 X 提供 Y 能力" / "年增速 30%" |
| 戏剧化/drama 表达 | 不难看出、值得注意的是、不言而喻、毋庸置疑、令人瞩目 | 删除或直接陈述结论 |
| 过度修辞 | 全面布局、强势入局、重磅出击、抢占先机、战略卡位 | 用事实替代："2025年新设 AI 部门，招聘 50 人" |
| 空话套话 | 市场前景广阔、竞争激烈、需要加强客户关系、持续跟进 | 给出具体数字或具体动作 |

### 文档内部信息不得重复

同一份文档内，同一个事实/观点/结论只允许出现一次。禁止以下行为：
- 换个说法重复同一观点（车轱辘话）
- 在"总结"段落重复正文已经说过的内容
- 在不同章节用不同措辞表达同一个判断

如果某条信息需要在同一文档的多个位置被引用，后续位置用"（见上文 §X）"引用，不要重写一遍。

### 跨文档信息复用规则

跨文档的适度重复是允许的——不同文档面向不同读者，必要的上下文重复不算冗余。具体原则：
- 关键数字（市场规模、A 层家数等）可以在 D1/D2/D4 中各出现一次，因为读者可能只看其中一份
- 但禁止「大段落复制粘贴」——如果两份文档中出现 3 句以上完全相同或近似相同的文字，必须精简其中一处为简要引用
- 每条结论仍建议有一个“主文档”（详细论证在主文档展开），其他文档简要引用即可

### 图表优先原则

当信息涉及以下场景时，必须优先用图表（表格 / Mermaid 图 / 矩阵图）而非纯文字段落：

- **多维度对比**：3 家以上公司或 3 个以上产品的并排比较 → 用表格
- **时间线 / 里程碑**：涉及时间顺序的事件序列（如行动路线图、攻坚节奏）→ 用 Mermaid gantt 或时间线表格
- **层级分类**：客户分层、产品匹配度矩阵 → 用矩阵表格或四象限图
- **流程 / 依赖关系**：决策链、攻坚路径的步骤序列 → 用 Mermaid flowchart
- **数值分布**：评分分布、市场规模拆解 → 用表格 + 数字标粗

判断标准：如果一段信息用纯文字写出来超过 5 行且包含并列结构（“A 怎样、B 怎样、C 怎样”），就应该改用表格或图。
