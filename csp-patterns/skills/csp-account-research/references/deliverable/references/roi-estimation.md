# ROI 估算方法论与修正系数

## 基础公式

```
年消费预期值（万元）=
  目标客户业务规模
  × 行业基准 IT 投入比例
  × 新技术占比
  × 外采比例
  × 产品匹配系数
```

业务规模按行业代入对应口径——AUM（量化私募/资管）/ ARR（SaaS）/ 营收（通用企业）/ 装机量（制造业）/ 用户数 DAU/MAU（互联网）。在 brief.json 中确认后代入。

## 各参数获取指南

| 参数 | 定义 | 获取方式 | 样例范围 |
|-----|------|---------|---------|
| 业务规模 | 客户核心业务指标（按行业代入口径） | 公开财报 / 融资报道 | — |
| IT 投入比例 | 该行业 IT 投入占业务收入比例 | 行业报告 / 对标客户 | 0.1% - 4% |
| 新技术占比 | AI / 大模型相关占总 IT 投入比例 | 招聘 AI 岗占比 / 融资报道 | 10% - 90% |
| 外采比例 | 新技术投入中通过外采完成的比例 | 招聘「云架构」vs「本地部署」岗位比 | 5% - 95% |
| 产品匹配系数 | 我方产品能覆盖客户外采需求的比例 | 需求对标分析 | 0.3 - 0.8 |

## 关键修正系数

| 修正系数 | 应用条件 | 调整倍数 | 说明 |
|---------|---------|---------|------|
| 存量深化 | 已有合作基础 | × 1.5 - 2.0 | 信任已建立，追加意愿高 |
| 新建能力 | 帮客户搭建 0-1 功能 | × 2.0 - 3.0 | 项目制高价值合作 |
| 爆发增长 | 业务规模年增长 > 50% | × 1.3 - 1.5 | IT 预算追加滞后于业务增长 |
| 自建文化强 | 完全自研体系 | × 0.5 - 0.7 | 实际转化率低于理论值 |
| 政策驱动 | 新法规强制采购 | × 1.5 - 2.5 | 合规 / 安全需求推动 |
| 竞对失利 | 竞对方案落地失败 | × 2.0 - 3.0 | 急需备选方案 |

## 应用规则

1. 最多同时应用 2 个修正系数（避免过度估算）
2. 优先应用最有把握的系数
3. 输出区间而非点值：保守（× 0.7）/ 最可能（× 1.0）/ 乐观（× 1.3 + 修正）
4. 每个 deal size 区间必须附带「这个数字怎么来的」说明（参见 [preface-and-menu.md](./preface-and-menu.md)）

## 输出格式（标准化）

每家客户的 deal size 表达必须遵循**可信度分层**原则：按证据强度标签拆分为两行，让读者一眼区分"有公开信息支撑的数字"和"基于类比推断的数字"。

### 双行输出模板

```
deal size——
  有据（仅含 [F] + [I] 标签数字）：  [X] - [Y] 万元 / 年
  含推断（[F] + [I] + [A]×0.4）：[X'] - [Y'] 万元 / 年
  
公式：[业务规模 a] × [IT 占比 b] × [新技术占比 c] × [外采比例 d] × [匹配系数 e]
  其中 [列出哪些参数来自 [A] 标签，单独标注]
修正：应用 [修正系数名称] × [倍数]
置信区间：有据行 ±50%，含推断行 ±100%（参数叠乘误差 + 类比不确定性）
```

### 分层规则

| 证据强度 | 计入哪行 | 系数 | 说明 |
|---------|---------|------|------|
| [F] 直接证据 | 有据 + 含推断 | × 1.0 | 公开采购合同/官方公告等一手来源 |
| [I] 关联推断 | 有据 + 含推断 | × 1.0 | 招聘JD/技术博客等间接证据 |
| [A] 类比推断 | 仅含推断 | × 0.4 | 同行类比/行业惯例，无直接证据 |
| [E] 信息缺失 | 不计入 | — | 不参与 Deal Size 计算 |

### 示例

```
deal size——
  有据（仅含 [F] + [I] 标签数字）：  300 - 600 万元 / 年
  含推断（[F] + [I] + [A]×0.4）：500 - 1000 万元 / 年
  
公式：年度科研经费(200亿) × IT占比(1.5%) × 新技术占比(40%) × 外采比例(50%) × 匹配系数(0.5)
  其中「IT占比」为 [A] 标签（基于同类985高校均值类比），已在含推断行按 ×0.4 折算
修正：存量深化 ×1.5
置信区间：有据行 ±50%，含推断行 ±100%
```

### 宏观加总规则

当需要汇总多家客户的 Deal Size 时：
- **保守合计**：仅加总各家"有据"行的保守值
- **乐观合计**：加总各家"含推断"行的乐观值
- 两个合计必须分开呈现，禁止混为一个总数
- 若某家仅有"含推断"行（无 [F]/[I] 数据），必须在合计数旁标注 ⚠️"含 [A] 推断"

### 旧格式对照

```
# 旧格式（弃用）
deal size：保守 [X] - 最可能 [Y] - 乐观 [Z] 万元 / 年

# 新格式（启用）
deal size——
  有据（仅含 [F] + [I] 标签数字）：  [X] - [Y] 万元 / 年
  含推断（[F] + [I] + [A]×0.4）：[X'] - [Y'] 万元 / 年
```

## 预期偏差管理

建议每季度回溯：

1. 对比实际成交 vs 预期金额
2. 分析偏差来源（系数不准？基准过时？）
3. 基于偏差更新对应参数
4. 偏差 > 50% 触发参数重校准

## 写作硬约束

- 禁止给出无公式支撑的「拍脑袋」金额
- 禁止用点值（如「800 万」）替代区间
- 必须显式标注业务规模口径（AUM / ARR / 营收 / 装机量 / 用户数）
- 修正系数必须显式列出，不得静默调整
