# D5 / D6 / D7 / D8：辅助交付物

## D5：高潜力客户特征模型

**目标读者**：销售管理层
**篇幅**：200-400 行

从 TOP 客户中归纳「最可能买单」的客户画像：

- 7 维度画像模型（业务规模、增长态势、技术姿态、外采倾向、决策链、信任入口、竞对状态）
- 正向指标（满足越多越优先）
- 负向指标（命中则降级）
- 快速打分卡（新客户 5 分钟判断法）

D5 与 D6 的关系：D5 给出「特征模型」，D6 给出「全量数据」，两者通过 `公司名称` 字段连接。

## D6：公司全景表（CSV）

**目标读者**：全员
**形态**：结构化数据表

20 列宽表结构：

```
公司名称, 业务规模区间, 所在地, 成立时间, 业务模式, 创始人背景, 开发人员规模,
业务规模增速, 公司总人数, 算力模式, GPU类型规模, 云服务商, 云上服务,
大模型使用方式, 具体模型, 训练微调情况, 模型用途, AI编程工具, AI办公工具, Agent工具
```

字段说明：

- **业务规模区间**：按行业代入对应口径——AUM（量化私募/资管）/ ARR（SaaS）/ 营收（通用企业）/ 装机量（制造业）/ 用户数 DAU/MAU（互联网）
- **云服务商**：写死映射——我方产品（brief.json 配置）+ 竞对厂商（brief.json 配置）+ 其他
- **CSV 编码**：UTF-8 with BOM
- **空值规范**：缺失数据写 `[信息缺失]`，不留空字符串

## D7：风险矩阵与核心假设清单

**目标读者**：战略/管理层
**篇幅**：100-200 行

### 触发条件

调研结论要用于重大战略决策（资源分配、市场进入、大客户战略）时，必须同步产出 D7。

### 风险矩阵模板

```markdown
## Top N 风险识别与缓释

**风险1：[风险名称]（概率：高/中/低 | 影响：极高/高/中/低）**

缓释措施：
1. [具体措施1]
2. [具体措施2]
3. [具体措施3]
```

风险分类标准：

| 风险类型 | 典型场景 |
|---------|----------|
| 行业级风险 | 政策变化 / 行业下行 / 安全事件 |
| 执行风险 | 技术通道无法转化 / 竞对先发制人 |
| 数据风险 | 调研信息不完整 / 关键判断基于弱推断 |
| 竞争风险 | 竞对先行进入 / 客户自建能力增强 |

### 核心假设清单模板

```markdown
| 编号 | 假设内容 | 验证方法 | 验证时间 | 当前状态 |
|------|---------|---------|---------|----------|
| H1 | [假设描述] | [如何验证] | [预计何时可验证] | 待验证/已确认/已否定 |
```

假设分类：市场假设 / 客户假设 / 竞争假设 / 产品假设。

### 假设失效预案

对关键假设（影响整体战略方向的）必须附带：

```
假设 H1 失效时：
└─ 影响范围：[哪些结论会变]
└─ 应对方案：[转向什么策略]
└─ 资源调整：[如何重新分配]
```

## D8：行动路线图

**目标读者**：战略/管理层
**篇幅**：100-200 行

### 三层时间框架

```markdown
## 短期（1-3个月）：Quick Win
**目标**：[一句话目标]

| 动作 | 具体内容 | 负责方 | 交付物 |
|------|---------|--------|--------|

**关键指标**：[可验证的里程碑]

## 中期（3-6个月）：深耕
（同上结构）

## 长期（6-12个月）：生态构建
（同上结构）
```

### 各时间层的核心逻辑

| 时间层 | 核心逻辑 | 典型动作 |
|---------|---------|----------|
| 短期 | 建立技术对话、完成首次产品试用 | 技术通道建立、PoC 启动、白皮书发布 |
| 中期 | 试用转化、进入采购评估 | 试用反馈收集、采购提案、技术交流 |
| 长期 | 标杆案例包装、复制突破路径 | 案例白皮书、新客户拓展、生态专区 |

### 与 D7 的衔接

- 短期动作应直接回应 D7 风险矩阵中的缓释措施
- 各时间层设置「里程碑检查点」：未达到则触发策略调整
- 假设验证时间与行动路线图时间对齐
