# Quality Checklist 与版本管理

## 单份交付物自检清单

每生成一份交付物（D1-D8），按以下清单逐项核对，输出到 `*/quality_check.md`。

### 通用（所有 D1-D8 必查）

- [ ] 「七块使用须知」完整且顺序正确
- [ ] 「⚠️ 请先阅读使用须知」强制提示语在文首
- [ ] 所有数据点有可靠性标注（[确认]/[强推断]/[弱推断]/[信息缺失]）
- [ ] [E] Empty 占比 ≤ 20%（与 depth-research 一致）
- [ ] 无禁用产品名称（已执行合规扫描）
- [ ] 业务规模口径在文档头部显式声明
- [ ] 文档头部含版本标注
- [ ] CSV 输出为 UTF-8 with BOM

### D1：客户攻坚作战手册

- [ ] TOP 客户卡片信息完整，无大面积 [信息缺失]
- [ ] 联系方式（电话/邮箱/备案号/官网）按 contact-whitelist 四级白名单采集，每条挂 [来源: XXX] 标签
- [ ] 决策人字段（姓名/职务/决策权/切入路径）全部填齐，缺失标 [需人工核实]
- [ ] 每张卡片含矩阵象限标注（① / ② / ③ / ④）
- [ ] 每张卡片含五类画像标注（A/B/C/D/E 型）
- [ ] 攻坚路径按三步递进，每步含成功指标
- [ ] 自建能力强型客户已做三场景拆分
- [ ] 攻坚建议具体可行，无空话套话
- [ ] 同一公司在卡片、矩阵、画像三处描述一致
- [ ] 行业级结论（TAM/SAM/SOM/分型方法）只在第一部分一页纸精要呈现，不展开复述

### D2：高管摘要

- [ ] 总篇幅 300-500 字（不含标题）
- [ ] 30 秒电梯演讲含「市场规模 + 我方位置 + 建议方向」三要素
- [ ] 核心发现 3 条，每条 ≤ 30 字、含数字
- [ ] 推荐行动 3 条，每条含时间约束
- [ ] 不含具体公司名单 / 不展开方法论 / 不贴数据表
- [ ] 每个块后标注「详见 [文档名] §X」互引
- [ ] 已执行去重自检：摘要中的数字在 D1/D4 有唯一出处，无跨文档近似副本

### D3：产品场景匹配矩阵

- [ ] 每个交叉点含「匹配度 + 典型场景 + 客单价区间」三要素
- [ ] 自建能力强型客户已做三场景拆分
- [ ] 客单价区间口径与 ROI 公式一致

### D4：行业市场洞察

- [ ] 含「空白市场机会池」章节（家数 + 占比 + deal size 池）
- [ ] 竞争格局按单家展开（竞对厂商（brief.json 配置））
- [ ] 渗透率给出统计口径
- [ ] 行业级断言基于 ≥ N 家样本聚合

### D5：高潜力客户特征模型

- [ ] 7 维度画像完整
- [ ] 含正向 / 负向指标
- [ ] 含快速打分卡（5 分钟判断法）

### D6：公司全景表（CSV）

- [ ] 20 列字段完整
- [ ] 业务规模口径在表头声明
- [ ] 缺失数据写 `[信息缺失]`，不留空字符串
- [ ] 与 D1 卡片数据一致（同一公司、同一字段）

### D7：风险矩阵与核心假设清单

- [ ] 每条风险含概率 / 影响等级
- [ ] 每条风险配 ≥ 3 条缓释措施
- [ ] 关键假设含「失效预案」

### D8：行动路线图

- [ ] 三层时间框架（短 / 中 / 长期）完整
- [ ] 每层含「目标 + 动作表 + 关键指标」
- [ ] 与 D7 风险缓释衔接

## 跨交付物一致性自检

D1-D8 全部完成后，做跨文档一致性检查：

- [ ] 同一公司在 D1 / D6 业务规模数字一致
- [ ] 同一公司在 D1 / D5 画像类型一致
- [ ] D2 高管摘要的数字能在 D1 / D4 中找到出处
- [ ] D8 行动路线图与 D7 风险缓释措施衔接
- [ ] 全部交付物使用同一版本号

## 跨文档信息复用检查

- [ ] 同一份文档内部是否存在同一观点换说法重复的情况？（严禁）
- [ ] 跨文档是否存在 3 句以上完全相同或近似相同的大段落复制？（如有，精简其中一处为简要引用）
- [ ] 关键数字在各文档中出现时是否数值一致？（允许多处出现，但数字必须一致）

## Quality Gate 触发自检

- [ ] 已检查 QG-1 到 QG-8（参见 [anti-patterns.md](./anti-patterns.md)）
- [ ] 触发任一 Quality Gate 时已暂停并向用户提供三选一（补数据 / 降级输出 / 取消）

## 版本管理

### 版本号命名规则

| 版本号 | 触发条件 | 示例 |
|--------|---------|------|
| v1.0 | 首次交付 | 调研完成，首版作战手册 |
| v1.1 | 小幅更新（< 5 家公司信息变动） | 修正个别公司评分 / 补充新信息 |
| v1.2 | 中幅更新（5-10 家变动或新增维度） | 补充 L3 复审结论 / 更新竞对信息 |
| v2.0 | 重大更新（分层变动 > 20% 或方法论调整） | 重新执行 L2 扫描 / 大规模升降层 |

### 增量更新 vs 全量重做

**增量更新（v1.x）**：

- 触发：个别公司信息更新 / 新闻事件导致评分变化
- 范围：仅更新受影响的公司和相关段落
- 标注：在更新位置标注 `[v1.1 更新]` + 更新原因

**全量重做（vN.0）**：

触发条件（满足任一）：
- 距上次全量 > 3 个月
- 分层变动公司占比 > 20%
- 方法论或评分维度发生调整
- 用户明确要求重新调研

范围：从 L2 开始重新执行全流程。

### 版本标注格式（强制）

所有交付物必须在文档头部标注：

```
版本：v1.2
基于数据：L2 v1.0 (YYYY.MM.DD) / L3 v1.1 (YYYY.MM.DD) / L4 v1.0 (YYYY.MM.DD)
更新时间：YYYY.MM.DD
更新内容：补充 N 家公司 L3 复审结论
```

该标注作为交付物追溯性与上下游复用的凭据，不可省略。

## 脚本辅助自检（可选）

全部 D1-D8 生成后，环境可用时推荐执行：

```bash
# 跨文档一致性
python <skill_dir>/references/account_research_toolkit.py check-consistency --workspace .csp/account-research/state/<slug>/

# 产品名称合规
python <skill_dir>/references/account_research_toolkit.py check-naming --workspace .csp/account-research/state/<slug>/ --brief .csp/account-research/state/<slug>/brief.json

# 单文档车轱辘话检测（对每个主交付物执行一次）
python <skill_dir>/references/account_research_toolkit.py dedup-check --file .csp/account-research/state/<slug>/docs/account-research/battle-handbook/客户攻坚作战手册.md
python <skill_dir>/references/account_research_toolkit.py dedup-check --file .csp/account-research/state/<slug>/docs/account-research/decision-support/高管摘要.md

# 证据标签配比检查（对 L3/L4 报告执行）
python <skill_dir>/references/account_research_toolkit.py evidence-ratio --file .csp/account-research/state/<slug>/docs/account-research/process-archive/L3_A层轻度调研.md
```

脚本覆盖范围：数字一致性 / 公司名匹配 / 禁用名称检测 / 文档内重复检测 / 证据配比。不覆盖：内容质量 / 叙事连贯性。PASS 不等于免检，仍需完成上方全部 checkbox。
