# D1：客户攻坚作战手册

**目标读者**：销售一线
**篇幅**：500-800 行

## 结构模板

```markdown
# [行业]客户攻坚作战手册

## 第〇部分：使用须知
- 数据来源与时效说明
- 可靠性标注体系说明（[确认]/[强推断]/[弱推断]/[信息缺失]，对应 [F]/[I]/[A]/[E]）
- 正确使用方式与风险提示
- 产品名称速查表（正确名称 + 禁用名称对照）

## 第一部分：全局战略
### 1.1 行业AI渗透率现状
### 1.2 客户分层总览（A/B/C 分布统计 + 饼图描述）
### 1.3 产品匹配策略
- 产品属性对比表（按客户需求维度）
- 首推产品及理由
- 客户画像 → 产品映射三步走
- 市场空间估算（含空白市场，参见 d4-market-insight.md）

## 第二部分：TOP N 客户攻坚卡片
每家客户一张卡片，包含：
- 基础信息快照（业务规模 / 地域 / 业务模式 / 团队规模）
- 技术栈现状（算力 / 模型 / 工具链）
- 产品匹配打分（雷达图描述）
- 竞对威胁评估（竞对厂商（brief.json 配置））
- 攻坚路径建议（切入点 → 首推产品 → 拓展路径 → 预计周期）
- 关键决策人信息
- 风险与机会提示
- 矩阵象限位置（参见 priority-matrix.md）

## 第三部分：分层攻坚策略
### A 层策略（高优先级）
### B 层策略（中优先级）
### C 层处理建议

## 附录
- 完整公司清单与分层
- 数据来源索引
- 更新日志
```

## 章节完整度与质量基准

### 必含章节清单（缺失任一项视为交付不完整）

| 章节 | 最低内容要求 | 深度基准 |
|------|------------|---------|
| 第〇部分：使用须知 | 七块完整（给谁读/解决什么/数据来源/可靠性/产品名称/正确用法/更新说明） | 每块至少 3 行实质内容 |
| 第一部分 §1.1 行业速览 | AI 渗透率数据 + 我方产品当前渗透 + 竞对渗透 + 空白市场估算 | 必须有量化数字，禁止纯定性描述 |
| 第一部分 §1.2 客户分层 | A/B/C 层家数统计 + 各层特征一句话描述 | 必须与 D6 对账 |
| 第一部分 §1.3 产品匹配 | 首推产品+理由 + 客户画像→产品映射 + 市场空间估算 | 至少一张对比表 |
| 第二部分 TOP 卡片 | 每家不少于 12 个字段全部填充（缺失标 [需人工核实]） | 每家"下一步动作"不少于 3 条 |
| 第三部分 分层策略 | A/B/C 各一段差异化策略 | 每层策略必须与该层客户特征关联 |

### 深度与密度自检标准

生成完成后，Agent 对照以下 4 条自检（不通过则修正后再交付）：

1. **信息密度**：每段（两个空行之间）必须包含至少 1 个具体数字或具体公司名——禁止出现连续 3 段纯定性描述而无量化支撑
2. **结论可追溯**：每个"建议"类语句必须关联到具体数据发现（如"建议首推百炼，因为 TOP 5 中 4 家有大模型调用需求[来源: L4 调研]"）
3. **叙事逻辑**：全文必须遵循"全局→聚焦→行动"三段递进（第一部分给全貌→第二部分给具体→第三部分给策略），禁止在第一部分就开始写具体公司攻坚细节
4. **图表密度**：全文至少包含 3 张表格/矩阵（行业速览至少 1 张、产品匹配至少 1 张、TOP 卡片本身算 1 组）

## TOP 客户卡片字段清单

每张卡片必须填齐以下字段（缺失项标注 `[信息缺失]` 或 `[需人工核实]`，不留空白）：

### 基础信息（必填）

| 字段 | 数据源 | 必填 |
|------|--------|------|
| 公司名称 | L1/L2 | ✅ |
| 公司主体（法定全称） | contact-whitelist 优先级1/3 | ✅ |
| 业务规模（按行业代入：AUM/ARR/营收/装机量/用户数） | L4 | ✅ |
| 所在地（注册地址 + 办公地址，如不同则分列） | L4 / contact-whitelist | ✅ |
| L2 评分 + L2 分层 | L2 | ✅ |
| 五类画像（A/B/C/D/E 型） | D5 | ✅ |
| 矩阵象限（①/②/③/④） | priority-matrix | ✅ |

### 联系方式（必填，按白名单采集）

| 字段 | 数据源 | 必填 |
|------|--------|------|
| 备案号/注册号（如适用行业） | contact-whitelist 优先级1 | ✅ |
| 联系电话 | contact-whitelist | ✅ |
| 邮箱 | contact-whitelist | ✅ |
| 官网 | contact-whitelist | ✅ |

> **联系方式采集规范**：严格按 [contact-whitelist.md](./contact-whitelist.md) 四级白名单顺序采集，每条挂 `[来源: XXX]` 标签，查不到标 `[需人工核实]`。禁止用大模型默认知识填充号码/邮箱。

### 决策人（必填）

| 字段 | 数据源 | 必填 |
|------|--------|------|
| 决策人姓名 | L4 | ✅ |
| 决策人职务 | L4 | ✅ |
| 决策权范围（一人拍板/多人合议/多层审批） | L4 | ✅ |
| 最佳切入路径（渠道/中间人/事件） | L4 | ✅ |

> 决策人信息缺失时全部标 `[需人工核实]`，不得省略该行。

### 业务判断（必填）

| 字段 | 数据源 | 必填 |
|------|--------|------|
| 算力/模型/工具链现状 | L4 | ✅ |
| 首推产品 + 理由 | D3 | ✅ |

## 写作硬约束

1. 每个 TOP 卡片必须给出明确「下一步动作」（不少于 3 条具体可执行项）
2. 攻坚路径不得跳过「第一步建立信任」直接推荐高价值产品
3. 同一公司在卡片、矩阵、画像三处的描述必须一致
4. 不得出现「市场很大」「竞争激烈」「需要加强客户关系」等无法验证的废话
5. **联系方式反编造**：电话/邮箱/备案号等字段必须按 [contact-whitelist.md](./contact-whitelist.md) 四级白名单顺序采集，搜不到的统一标 `[需人工核实]`，禁止用大模型默认知识填充
6. **跨文档信息复用**：D1 作为战术执行层，行业级结论（TAM/SAM/SOM、竞对全局渗透率、客户分型方法论）在 D1「第一部分：行业速览」用一页纸精要呈现，详细论证留到 D4；关键数字可以重复出现，但禁止大段落复制
7. **第〇部分（使用须知）+ 第一部分（全局战略，含行业速览与产品匹配策略）为不可跳过的必含模块**。如果数据不足以填充这两部分，Agent 必须在生成前暂停，向用户报告具体缺失项（如"行业 TAM 数据不足——L2/D4 中未找到市场规模估算""产品匹配逻辑未确认——brief.json 中 products 字段缺少 core_scenarios"），由用户三选一决定：
   - (A) 补数据后继续——Agent 等待用户补充后再生成
   - (B) 用已有数据简化输出——生成精简版行业速览，标注"数据不完整，仅供参考"
   - (C) 跳过本章节——用户明确放弃，Agent 记录到 CHANGELOG
   Agent 不可自行跳过或降级。未经用户选择直接省略第〇/第一部分，属于执行事故。
8. **先出大纲后写正文**：生成 D1 前必须先输出章节大纲供用户确认，确认后按大纲逐章展开。禁止跳过大纲确认直接写正文。大纲中必须包含本文件"必含章节清单"中的所有章节。
