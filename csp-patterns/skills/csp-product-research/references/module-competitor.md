# 竞品深度分析 — 执行步骤

> 独立使用时的完整执行流程。数据质量规则见 [data-quality-rules.md](data-quality-rules.md)，方法论参考见 [methodology.md](methodology.md)。（同目录下的参考文件）

## 前置确认

1. **分析对象**：竞品列表（具体公司名）或方向描述（由AI搜索识别竞品）
2. **分析目的**：寻找差异化 / 评估威胁 / 投资尽调 / 学习借鉴
3. **分析深度**：快速档案（每竞品1页）/ 深度深潜（每竞品2-3页）

## 执行流程（AI 自主完成）

### Step 1：竞品识别与分层

如果用户只给了方向而非具体竞品：

1. **品类阶梯定位**：确定全景层和深潜层
2. **四层竞品覆盖**（在全景层搜索）：
   - 直接竞品（做同样的事）
   - 间接替代（用不同方式解决同一问题）
   - 平台级玩家（大厂降维打击的可能）
   - 隐形传统（Excel/人工/不做这件事）
3. 每层列出 3-5 家，标注关系定位

### Step 2：五要素深潜（在深潜层执行）

对每个重要竞品（≥ 3 家），逐一分析：

| 要素 | 必须回答的问题 |
|------|---------------|
| **商业模式** | 怎么赚钱？SaaS/项目制/抽佣/广告？收入结构？客单价量级？ |
| **产品/服务** | 核心功能？产品形态？技术栈？用户体验评价？ |
| **核心竞争力** | 凭什么赢？技术/数据/渠道/品牌/规模？**数据壁垒专项**：是否有随使用时间增长的数据积累？独占性如何？ |
| **融资/估值** | 融资轮次/金额/估值/投资方/是否盈利 |
| **获客方式** | 怎么找到客户？SEO/BD/招投标/渠道/口碑？获客效率如何？ |

**每个竞品深潜后必须回答：**
- 关键局限是什么？它不做什么、做不了什么？
- 与我们的关系：直接竞品 / 上下游竞品 / 潜在客户 / 潜在合作伙伴 / 无关

### Step 3：竞品对比矩阵

多维度对比表：

| 维度 | 竞品A | 竞品B | 竞品C | ... |
|------|-------|-------|-------|-----|
| 定位 | | | | |
| 商业模式 | | | | |
| 客单价 | | | | |
| 目标客户 | | | | |
| 核心竞争力 | | | | |
| 数据壁垒 | | | | |
| 融资阶段 | | | | |
| 关键局限 | | | | |

### Step 4：蓝海战略画布

- 行业普遍投入的维度（大家都在卷什么）
- 行业普遍忽略的维度（机会在哪）
- 差异化空间识别

### Step 5：竞品共同弱点

基于用户评价（G2/知乎/产品社区/应用商店）总结：
- 共同痛点是什么？
- 用户最常抱怨什么？
- 什么是竞品做不好或不愿做的？

### Step 6：差异化策略建议

三层策略框架：
- **追赶层**：竞品有我们没有、必须补齐的
- **差异化层**：我们有或能做出差异的
- **创新层**：行业没人做的蓝海机会

## 报告结构

```markdown
# 竞品深度分析报告

## 核心发现（3-5 句话）
## 一、竞品地图（四层覆盖 + 关系定位）
## 二、核心竞品深潜（每竞品：五要素 + 关键局限 + 关系标注）
## 三、竞品对比矩阵
## 四、蓝海战略画布（红海维度 vs 蓝海机会）
## 五、竞品共同弱点
## 六、差异化策略建议（追赶层 / 差异化层 / 创新层）
## 附录（数据溯源表 + 来源索引）
```

## 交互原则

- AI 自主搜索竞品信息，用户不参与搜索
- 输出后用户可要求对某个竞品追加深度分析
- 如果分析过程中发现方向评估需求，建议进入完整流程
