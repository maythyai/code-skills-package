# 安全约束（详细规则）

正文只保留一句话摘要，这里是完整规则。**所有规则默认强制**；确需突破某条时，必须先向用户说明风险并获得明确同意。

## 1. 环境边界

1. 只在**测试 / 开发 / 预发**环境操作；禁止默认指向生产环境。
2. 用户未给出环境时主动确认，**不猜测生产地址**。
3. 确需在生产验证（如线上冒烟）时：只做**只读**操作（浏览、查询、截图），禁止任何写操作，并事先获得用户明确同意。

## 2. 写操作限制

1. **只读优先**：能用浏览/查询验证的，不做增删改。
2. 表单提交、下单、删除等写操作，仅在明确的测试环境且使用测试数据时进行。
3. **禁止真实支付**：涉及支付的流程一律使用测试/沙箱渠道；没有沙箱时，走到支付确认页前停止并截图取证，向用户报告。
4. 禁止批量删除、清空类操作（如"删除全部""清空购物车"全量操作），除非用户明确要求且确认是测试数据。

## 3. 凭证与数据

1. **禁止使用真实用户凭证**：测试只用用户提供的测试账号，或明确的 mock 登录态。
2. 不在报告、日志、提交信息中记录明文密码、token、cookie 值；引用时脱敏（如 `session_id=***`）。
3. `state-save` / 持久 profile 里可能含登录态：交付前提醒用户清理（`delete-data` 或删除 `auth.json`）。
4. 截图中出现的真实个人信息（手机号、身份证、订单号等）在报告中脱敏或提醒用户。
5. 不读取、不外传与被测无关的本地文件；mock 数据不引用真实生产数据。

## 4. 网络与执行边界

1. `route` 拦截/mock 只作用于被测页面的请求，不做任何绕过他人系统安全控制的用途。
2. `eval` / `run-code` 只在被测页面上下文执行脚本；不借浏览器会话访问无关站点或执行与测试无关的操作。
3. 不利用自动化能力做越权探测（扫描未授权接口、尝试他人账号、绕过权限校验）。发现权限漏洞 → 记录并报告给用户，而不是继续利用。

## 5. 速率与影响

1. 控制请求速率，避免对测试环境造成压力（不做压测，除非用户明确要求且有专门方案）。
2. 涉及短信/邮件验证码的用例：不轰炸真实手机号；用 mock 或测试通道。

## 6. 违规处理

- 任何一步触碰上述红线 → **立即停止**，向用户说明触碰了哪条、已产生的影响、建议的补救。
- 用户明确要求突破红线时：记录该决定（谁、何时、突破哪条、为什么），并只执行被明确授权的最小范围。

## 快速自检清单（每次执行前）

- [ ] 目标 URL 是测试/开发环境吗？
- [ ] 本次用例会触发写操作吗？数据是测试数据吗？
- [ ] 会触碰支付吗？有沙箱吗？
- [ ] 用的是测试账号吗？凭证不会进报告吗？
- [ ] 截图里会有需要脱敏的真实信息吗？
