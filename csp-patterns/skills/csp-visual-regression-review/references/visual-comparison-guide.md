# 视觉比对详细指南

需要比 SKILL.md 核心规则更深细节时读本文件：截图模式、Figma 符合性、掩码、阈值、误报、diff 解读、基线更新政策。

## 两种模式

### 回归模式（regression）

期望图是**先前已批准的应用 UI 基线**。用于：

- PR 视觉回归
- 防止意外的 CSS/布局变更
- 追踪已批准 UI 的演进

审批更严格：两张图都应来自同一应用的渲染管线。

### 符合性模式（conformance）

期望图是**设计师持有来源**：Figma 导出、原型图、交付截图。用于：

- UI 实现 vs Figma
- 原型交付 QA
- 验证 AI 生成 UI 是否符合视觉目标

审批需要解释性判断：设计工具与浏览器的渲染方式天然不同。

## 采集前必备设置

- 视口与设计 frame 对齐
- 显式设置 deviceScaleFactor
- CI 中使用稳定的浏览器与 OS
- 安装生产字体，或记录 fallback 差异
- 禁用动画、隐藏光标/选区
- 冻结日期/时间与随机数据
- 使用确定性种子数据
- 等待 UI 稳定后再截图
- 掩码动态区域
- 在已知尺寸下比对图像

## Figma 到 UI 的符合性比对

1. 确认 Figma 文件/frame 是最新且已批准的。
2. 导出精确的 frame/state/node。
3. 视口尺寸与 Figma frame 对齐。
4. 浏览器缩放 / deviceScaleFactor 保持一致。
5. 使用相同内容，或明确接受内容差异。
6. 掩码含实时数据或生成媒体的区域。
7. 用 diff 输出作为证据，然后人工检查受影响区域。

## 动态内容掩码

**通常掩码**：

- 头像与用户上传媒体
- 时间戳、日期、计数器、实时指标
- 广告、地图、随机插图、含实时数据的图表
- 光标/caret 与文本选区
- 骨架屏 shimmer 或加载动画
- 参考图用假数据时的个性化名称

**禁止掩码**：

- 主 CTA 对齐
- 应与固定设计文案匹配的内容
- 导致溢出的布局容器
- 本应实现的状态指示器
- 破图或缺失 icon

## 阈值参考

裸 diff 比例只是分流信号：

| 区间 | 建议动作 |
| --- | --- |
| 0–0.5% | 大概率可接受，抽查高影响区域 |
| 0.5–2% | 检查布局、排版、颜色、资源区域 |
| 2–5% | 除非有已知动态内容解释，否则大概率 major |
| >5% | 稳定回归大概率 blocker；符合性模式先查数据/内容差异是否主导 |

永不只看裸比例：破坏性 CTA 或价格数字上的微小 diff，比装饰图上的大 diff 重要得多。

## 常见误报

- 亚像素抗锯齿
- OS/浏览器/字体渲染差异
- 字体 fallback 或缺失字重
- Figma shadow/blur/gradient/blend-mode 差异
- 单环境出现滚动条
- 真实内容 vs mock 数据导致的换行
- 图片压缩或 CDN 变换
- 未掩码的动态内容
- sticky header 在不同滚动位置被截取

## 有意义的失败模式（必须上报）

- 缺失或多余可见元素
- 页面层级错误或 CTA 强调错误
- 语义色或状态色错误
- 布局偏移、溢出、裁剪、异常换行
- 影响可读性的排版 scale 或 line-height 不匹配
- 改变分组的间距/密度不匹配
- 资源错误：尺寸、裁剪、宽高比
- 截图或交互流中缺失状态
- 响应式布局偏离设计意图

## 基线更新政策

仅在以下条件全部满足时更新基线：

- 视觉变更是有意为之
- 设计 owner 或评审者已批准
- 新基线在同一确定性环境中生成
- 报告解释了改了什么、为什么改

绝不通过更新基线来掩盖回归。

## 与兄弟技能的边界

| | 本技能 | csp-ui-alignment-review | csp-qa | csp-h5-visual-testing |
| --- | --- | --- | --- | --- |
| 回答的问题 | 哪里变了 | 该修什么、谁来修 | 能否发布 | 批量取证（不解释） |
| 输入 | 截图对 | diff + 代码/DOM | 全部证据汇总 | 页面清单 |
| 输出 | diff 证据 + 分类 | 对齐问题清单 | 发布裁决 | 截图 + HTML 报告 |
| 是否改代码 | 否 | 可建议 | 否 | 否 |
