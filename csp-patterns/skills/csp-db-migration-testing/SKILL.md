# Database Migration Testing

Prove every migration is correct, reversible, zero-downtime, and data-preserving — *before* it runs against production.

## When to Activate

- Any production DB with >1M rows (lock duration matters)
- Zero-downtime deployment requirement (no maintenance windows)
- A recent migration incident (lock timeout, data loss, failed rollback)
- Adopting expand-contract discipline and you need verification gates
- ORM-autogenerated migrations (Prisma, Drizzle, Alembic) entering CI
- Pre-release: prove the full migration chain (v1 → v2 → ... → vN) applies cleanly to a fresh DB and to a copy of prod

## Boundary with csp-db-migration

| Dimension | csp-db-migration (authoring) | csp-db-migration-testing (this) |
|---|---|---|
| Question | "How do I write a safe migration?" | "How do I prove this migration is safe?" |
| Output | Migration SQL/scripts, expand-contract patterns | Test harness, CI gates, rehearsal reports |
| When | Build phase | Verify phase |
| Concerns | Lock avoidance, online schema change, backfill strategy | Rollback works, schema matches fresh, data preserved, lint passes |

## Migration Test Matrix

| Test type | What it proves | Tool | Frequency |
|---|---|---|---|
| **Lint** | No dangerous patterns (ADD COLUMN NOT NULL DEFAULT on PG<11, CREATE INDEX without CONCURRENTLY, DROP COLUMN without expand-contract) | squawk, custom rules | Every PR |
| **Apply-clean** | Full chain v1→vN applies to fresh DB without error | Testcontainers + Flyway/Alembic/Prisma | Every PR |
| **Rollback rehearsal** | Every `up` has a working `down`; up→down→up is idempotent | Alembic `upgrade head && downgrade -1 && upgrade head`, Flyway undo (Teams) | Every PR |
| **Schema equivalence** | Migrated DB schema == fresh DB schema (no drift) | pg_dump + apgdiff, Prisma migrate diff | Every PR |
| **Backfill assertion** | Row counts, checksums, sampling match pre/post | Custom SQL assertions | Every migration with backfill |
| **Zero-downtime rehearsal** | Migration completes without ACCESS EXCLUSIVE lock on hot tables | gh-ost dry-run, pt-osc rehearsal, `pg_stat_activity` monitoring | Pre-release, large tables |
| **Prod-copy rehearsal** | Full chain applies to an anonymized copy of prod | Testcontainers + prod dump | Pre-release |
| **Differential** | Queries return same results pre/post migration | [[csp-differential-testing]] | Major refactors |

## Setup & Canonical Commands

```bash
# squawk lint (Postgres migrations)
pip install squawk-cli   # or: npm i -g squawk-cli
squawk migrations/*.sql --fail-on-violations
# Docker: docker run --rm -v $PWD:/data ghcr.io/sbdchd/squawk:latest migrations/*.sql

# Prisma migrate diff (CI gate: generated migration matches schema?)
prisma migrate diff \
  --from-migrations ./prisma/migrations \
  --to-schema-datamodel ./prisma/schema.prisma \
  --exit-code

# Alembic rehearsal
alembic upgrade head && alembic downgrade -1 && alembic upgrade head

# Flyway check (drift + changes)
flyway check -drift -changes -url=$DB_URL -user=$DB_USER -password=$DB_PASS

# gh-ost dry run (MySQL online schema change)
gh-ost \
  --host=localhost --database=app --table=users \
  --alter="ADD COLUMN email VARCHAR(255)" \
  --execute --initially-drop-ghost-table \
  --max-load=Threads_running=50 \
  --critical-load=Threads_running=100

# Schema equivalence: fresh vs migrated
createdb fresh && createdb migrated
psql fresh    -f schema_vN.sql
psql migrated -f schema_v1.sql && psql migrated -f migrations/*.sql
diff <(pg_dump --schema-only fresh | grep -v '^--' | sort) \
     <(pg_dump --schema-only migrated | grep -v '^--' | sort)
```

## Pattern 1: Testcontainers + Flyway (Java, apply + rollback + schema assert)

```java
@Testcontainers
class MigrationIT {
    @Container
    static PostgreSQLContainer<?> pg = new PostgreSQLContainer<>("postgres:16-alpine");

    @Test
    void full_chain_applies_cleanly() {
        Flyway flyway = Flyway.configure()
            .dataSource(pg.getJdbcUrl(), pg.getUsername(), pg.getPassword())
            .locations("classpath:db/migration")
            .load();

        MigrateResult result = flyway.migrate();
        assertThat(result.migrationsExecuted).isGreaterThan(0);
        assertThat(result.success).isTrue();
    }

    @Test
    void rollback_rehearsal_up_down_up() throws Exception {
        try (Connection c = DriverManager.getConnection(
                pg.getJdbcUrl(), pg.getUsername(), pg.getPassword())) {

            Flyway flyway = Flyway.configure().dataSource(c).load();
            flyway.migrate();                          // up to head
            flyway.undo();                             // down one (Flyway Teams)
            MigrateResult re = flyway.migrate();       // up again
            assertThat(re.success).isTrue();

            // Assert schema is intact after round-trip
            DatabaseMetaData meta = c.getMetaData();
            try (ResultSet rs = meta.getColumns(null, null, "users", null)) {
                List<String> cols = new ArrayList<>();
                while (rs.next()) cols.add(rs.getString("COLUMN_NAME"));
                assertThat(cols).contains("id", "email", "created_at");
            }
        }
    }

    @Test
    void backfill_preserves_row_count_and_checksum() throws Exception {
        try (Connection c = DriverManager.getConnection(
                pg.getJdbcUrl(), pg.getUsername(), pg.getPassword())) {

            // Seed pre-migration data
            c.createStatement().execute("INSERT INTO users(id, name) VALUES (1,'a'),(2,'b'),(3,'c')");
            long before = count(c, "users");
            String checksumBefore = checksum(c, "users", "id, name");

            // Run migration that backfills email from name
            Flyway.configure().dataSource(c).load().migrate();

            long after = count(c, "users");
            String checksumAfter = checksum(c, "users", "id, name");  // name unchanged

            assertThat(after).isEqualTo(before);
            assertThat(checksumAfter).isEqualTo(checksumBefore);

            // Assert backfilled column is populated
            try (ResultSet rs = c.createStatement().executeQuery(
                    "SELECT count(*) FROM users WHERE email IS NULL")) {
                rs.next();
                assertThat(rs.getInt(1)).isZero();
            }
        }
    }

    private long count(Connection c, String table) throws SQLException {
        try (ResultSet rs = c.createStatement().executeQuery("SELECT count(*) FROM " + table)) {
            rs.next(); return rs.getLong(1);
        }
    }
    private String checksum(Connection c, String table, String cols) throws SQLException {
        try (ResultSet rs = c.createStatement().executeQuery(
                "SELECT md5(string_agg(" + cols.replace(",", " || ',' || ") + ", ',' ORDER BY id)) FROM " + table)) {
            rs.next(); return rs.getString(1);
        }
    }
}
```

## Pattern 2: Alembic Rehearsal (Python)

```python
# tests/test_migrations.py
import pytest
from alembic.config import Config
from alembic import command
from alembic.script import ScriptDirectory
from sqlalchemy import create_engine, inspect, text
from testcontainers.postgres import PostgresContainer

@pytest.fixture(scope="module")
def pg():
    with PostgresContainer("postgres:16-alpine") as pg:
        yield pg

def test_full_chain_up_down_up(pg):
    url = pg.get_connection_url()
    cfg = Config("alembic.ini")
    cfg.set_main_option("sqlalchemy.url", url)

    script = ScriptDirectory.from_config(cfg)
    revisions = list(script.walk_revisions())

    # Upgrade to head
    command.upgrade(cfg, "head")
    engine = create_engine(url)
    insp = inspect(engine)
    assert "users" in insp.get_table_names()

    # Downgrade one step
    head = script.get_current_head()
    prev = script.get_revision(head).down_revision
    command.downgrade(cfg, prev)

    # Upgrade again — must be idempotent
    command.upgrade(cfg, "head")
    insp = inspect(engine)
    assert "users" in insp.get_table_names()

def test_backfill_row_count_preserved(pg):
    url = pg.get_connection_url()
    engine = create_engine(url)
    with engine.begin() as c:
        c.execute(text("INSERT INTO users(id, name) VALUES (1,'a'),(2,'b')"))
        before = c.execute(text("SELECT count(*) FROM users")).scalar()

    cfg = Config("alembic.ini")
    cfg.set_main_option("sqlalchemy.url", url)
    command.upgrade(cfg, "head")

    with engine.begin() as c:
        after = c.execute(text("SELECT count(*) FROM users")).scalar()
        nulls = c.execute(text("SELECT count(*) FROM users WHERE email IS NULL")).scalar()
    assert after == before
    assert nulls == 0
```

## Pattern 3: Prisma Migrate Diff Gate (Node)

```typescript
// tests/migration.test.ts
import { execSync } from "child_process";
import { describe, it, expect } from "vitest";

describe("Prisma migration integrity", () => {
  it("generated migrations match schema (no drift)", () => {
    // Exits non-zero if migrations don't produce the current schema
    expect(() => execSync(
      "npx prisma migrate diff " +
      "--from-migrations ./prisma/migrations " +
      "--to-schema-datamodel ./prisma/schema.prisma " +
      "--exit-code",
      { stdio: "pipe" }
    )).not.toThrow();
  });

  it("migrations apply cleanly to a fresh DB", () => {
    execSync("npx prisma migrate deploy", {
      env: { ...process.env, DATABASE_URL: process.env.TEST_DATABASE_URL! },
      stdio: "pipe",
    });
  });

  it("no dangerous patterns in migration SQL", () => {
    const sql = execSync("cat prisma/migrations/*/migration.sql").toString();
    // PG < 11: ADD COLUMN NOT NULL DEFAULT rewrites table
    expect(sql).not.toMatch(/ADD\s+COLUMN\s+\w+\s+\w+\s+NOT\s+NULL\s+DEFAULT/i);
    // CREATE INDEX without CONCURRENTLY on hot tables
    expect(sql).not.toMatch(/CREATE\s+INDEX\s+(?!CONCURRENTLY)/i);
    // DROP COLUMN without expand-contract (no prior deprecation migration)
    expect(sql).not.toMatch(/DROP\s+COLUMN\s+(?!IF\s+EXISTS)/i);
  });
});
```

## Pattern 4: squawk Lint Config (Postgres)

```toml
# .squawk.toml
[rules]
# Error-level: block CI
adding-field-with-default = "error"          # PG < 11 rewrites table
renaming-column = "error"                     # breaks running queries
ban-drop-column = "error"                     # use expand-contract
ban-drop-table = "error"
require-concurrent-index-creation = "error"   # CREATE INDEX locks writes
constraint-missing-not-valid = "error"        # ADD CONSTRAINT locks; use NOT VALID + VALIDATE
prefer-create-index-concurrently = "error"
ban-alter-type = "error"                      # ALTER TYPE ... ADD VALUE is non-transactional pre-PG12

# Warning-level: surface in PR comment
adding-serial-primary-key = "warn"
backfill-without-default = "warn"
```

```bash
squawk migrations/*.sql --config .squawk.toml --fail-on-violations error
# CI: post PR comment with violations
squawk migrations/*.sql --config .squawk.toml --format github-actions
```

squawk 2.x (2024+) added `require-table-schema` and GitHub PR comment integration.

## Pattern 5: gh-ost Rehearsal (MySQL zero-downtime)

```bash
# Dry run against a prod copy (anonymized)
gh-ost \
  --host=prod-copy.internal \
  --database=app \
  --table=orders \
  --alter="ADD COLUMN customer_email VARCHAR(255), ADD INDEX idx_email (customer_email)" \
  --execute \
  --initially-drop-ghost-table \
  --max-load=Threads_running=50 \
  --critical-load=Threads_running=100 \
  --chunk-size=1000 \
  --max-lag-millis=1500 \
  --throttle-control-replicas="replica1.internal,replica2.internal" \
  --postpone-cut-over-flag-file=/tmp/gh-ost.postpone \
  --verbose

# Assertions after rehearsal:
# 1. No lock waits > 1s on the original table
# 2. Replication lag stayed < 1.5s
# 3. Cut-over completed in < 5s
# 4. Row count matches: SELECT count(*) FROM orders == SELECT count(*) FROM _orders_gho
```

gh-ost is binary-log based (no triggers) — safer than pt-osc for high-write tables. pt-osc uses triggers — faster for small tables, riskier for large.

## Pattern 6: Expand-Contract Verification (multi-migration discipline)

```sql
-- Migration 001: EXPAND (add new column, nullable, no default)
ALTER TABLE users ADD COLUMN email_new VARCHAR(255);
CREATE INDEX CONCURRENTLY idx_users_email_new ON users(email_new);

-- Migration 002: BACKFILL (batched, no lock)
UPDATE users SET email_new = email WHERE email_new IS NULL AND id BETWEEN 1 AND 10000;
-- ... repeat in batches, assert row count after each

-- Migration 003: DUAL-WRITE (app code writes both columns)
-- (no SQL migration; app code change)

-- Migration 004: MIGRATE READS (app code reads new column)
-- (no SQL migration; app code change)

-- Migration 005: CONTRACT (drop old column, after bake period)
ALTER TABLE users DROP COLUMN email;
DROP INDEX CONCURRENTLY idx_users_email;
```

Verification at each step:
- After 001: `email_new` exists, nullable, no default. Old column untouched.
- After 002: `SELECT count(*) FROM users WHERE email_new IS NULL` == 0. Checksum matches old column.
- After 003: Both columns updated on new writes. Assert via trigger or app-level test.
- After 004: Reads come from `email_new`. Assert via query log or app-level test.
- After 005: Old column gone. Schema matches fresh DB.

Each step is its own migration with its own test. Never combine expand + backfill + contract in one migration.

## CI Integration

| Gate | Tool | Scope | Failure action |
|---|---|---|---|
| Lint | squawk | Changed migration files | Block merge |
| Apply-clean | Testcontainers + Flyway/Alembic/Prisma | Full chain to fresh DB | Block merge |
| Rollback rehearsal | Alembic up/down/up, Flyway undo | Changed migrations | Block merge |
| Schema equivalence | pg_dump + diff, Prisma migrate diff | Migrated vs fresh | Block merge |
| Backfill assertion | Custom SQL (count, checksum) | Migrations with backfill | Block merge |
| Zero-downtime rehearsal | gh-ost dry-run, pg_stat_activity | Large tables (>1M rows) | Pre-release gate |
| Prod-copy rehearsal | Testcontainers + anonymized dump | Full chain | Pre-release gate |

## Anti-Patterns

- **Only testing `up`** — `down` is untested until production rollback. Every `up` must have a rehearsed `down`.
- **`ALTER TABLE ... ADD COLUMN ... NOT NULL DEFAULT ...` on PG < 11** — Rewrites the entire table, ACCESS EXCLUSIVE lock. Use nullable + backfill + SET NOT NULL (NOT VALID + VALIDATE).
- **`CREATE INDEX` without `CONCURRENTLY` on a hot table** — Full write lock for the duration. Always CONCURRENTLY outside a transaction.
- **Backfill in the same migration as schema change** — Split them. Schema change is seconds; backfill is hours. Combining them means hours of lock.
- **No row-count/checksum assertions after backfill** — Silent data loss. Assert `count(*)` and `md5(string_agg(...))` pre/post.
- **ORM-autogenerated migrations without lint** — Prisma/Drizzle/Alembic autogenerate will produce dangerous SQL. squawk + human review are mandatory.
- **Testing only on an empty DB** — Empty DB migrations are instant. Test on a prod-sized copy to surface lock duration and backfill time.
- **Skipping the bake period in expand-contract** — Dropping the old column immediately after migrating reads means no rollback path. Bake for at least one deploy cycle.
