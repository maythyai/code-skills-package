# 自动化证据与人工检查指南

自动化无障碍扫描结果解读、人工检查清单、路径优先级、严重度与修复层的详细版。

## 原则

自动化工具能抓住重要的问题类别，但**不证明无障碍**。把自动化发现与用户路径人工审查结合。

## 自动化检查能抓什么

- 颜色对比度
- 缺表单 label
- 缺可访问名称
- 重复 ID
- 非法 ARIA
- 标题顺序
- 缺图片 alt
- 缺 landmark
- 非法 role/state 关系

**归组规则**：同一修复适用时按组件归组重复发现，不逐实例报告。

## 人工检查（始终考虑）

- 纯键盘操作
- 可见焦点顺序
- modal/popover 焦点管理
- 主路径的 screen-reader 清晰度
- 错误恢复
- 内容可读性
- reduced motion
- 窄宽度下的 zoom/reflow
- 触控目标尺寸与间距
- 复杂组件行为：menus、tabs、comboboxes、dialogs、tables、toasts

## 用户路径优先级

1. 登录 / 注册
2. 结账 / 支付
3. 创建/编辑/提交表单
4. 搜索与筛选
5. 导航与设置
6. 破坏性操作
7. 错误恢复

## 严重度

### Blocker

- 键盘陷阱
- 主操作不可达
- 关键按钮或链接无可访问名称
- 必需表单无法完成或纠正
- 关键文本/操作严重对比度失败
- modal/dialog 无法键盘操作

### Major

- 组件级重复违规
- 重要状态未播报或不可见
- 常见路径焦点顺序混乱
- 错误文本未关联 input
- 常见内容对比度失败

### Minor

- 有 workaround 的局部问题
- 非关键装饰性 alt 问题
- 小焦点 polish 问题
- 不阻断理解的标题顺序问题

### Manual review（自动工具无法判定正确性）

- screen-reader 措辞质量
- 复杂工作流逻辑
- icon-only 控件的意图
- reduced-motion 可接受性
- 内容清晰度

## 修复层顺序

1. 共享组件原语（问题重复）
2. 组件 variant/状态（模式特定）
3. 页面组合（确属局部）
4. Token（系统级：对比度/焦点/状态色）
5. 文案/内容（名称或说明不清晰）

## 常见模式与修复

| 模式 | 修复 |
| --- | --- |
| 占位符当 label | 加持久 label 并关联 input |
| icon-only 按钮 | 提供可访问名称（aria-label / 可见文本） |
| Modal 打开无焦点处理 | 聚焦首个有意义元素、圈定焦点、关闭后还原焦点 |
| 错误仅视觉呈现 | `aria-describedby` 关联 + 标记 invalid 状态 |
| 可点击 `div` | 用原生 button/link；确需自定义时实现键盘语义 |
| focus ring 被移除 | 用设计 token 恢复可见 focus-visible 样式 |
| 仅颜色区分状态 | 加 icon/文本/形状或程序化状态（aria-pressed 等） |
| 标题跳级（视觉驱动） | 按文档结构而非视觉样式定标题层级 |

## 修复指引

- 优先原生元素，其次 ARIA。
- 不要用 ARIA 掩盖语义问题；先修底层元素。
- 问题重复时在共享组件层修复。
- 改进语义与焦点行为时保留视觉设计。
- 为关键键盘与 a11y 行为加测试。
- 键盘与 screen-reader 路径保留人工验证步骤。

## 验证清单

- [ ] 跑自动化 a11y 扫描
- [ ] 纯键盘走完主路径
- [ ] light/dark/high-contrast 表面下检查可见焦点
- [ ] 验证关键控件的 screen-reader 名称
- [ ] 验证表单 label 与错误关联
- [ ] 验证 modal/menu/tab 行为
- [ ] 验证破坏性动画的 reduced-motion 行为
- [ ] 相关时验证触控目标与 zoom/reflow

## 与 csp-access 主审计的关系

- 本指南覆盖"实现阶段"的证据解读；主 SKILL.md 的 WCAG 50+ 项覆盖"合规审计"。
- 主审计的 Step 3 逐项核对时，自动化发现可作为证据填入 finding 的 `evidence` 字段。
- 主审计给出合规等级；本指南给修复行动。两者输出合流到同一份审计报告。
