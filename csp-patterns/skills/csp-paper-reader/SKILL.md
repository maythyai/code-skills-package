# 全方位论文阅读

将论文检索、下载、解析、摘要、笔记生成、关联资源（代码/数据集/学术圈响应）整合为一条完整流程，最终交付一份自包含的专业 HTML 阅读报告 + 原始论文 PDF。

## 执行流程

### 1. 确认输入

- 用户提供**具体论文**（标题 / arXiv ID / URL / PDF文件）→ 直接进入步骤 2。
- 用户提供**领域关键词** → 先执行检索：
  - 使用 `search-paper-arxiv` 技能或 arXiv API 检索，默认返回 Top 5 论文（用户未指定数量时）。
  - 展示检索结果列表（标题、作者、日期、摘要前两句），让用户选择要深入解读的论文，或确认全部解读。
  - 若用户指定了数量，按指定数量检索。

### 2. 下载与解析

对每篇目标论文：

1. **获取 PDF**：通过 arXiv 下载链接或用户上传的本地文件获取 PDF。**将原始 PDF 保存到工作区**，后续与 HTML 报告一并交付。
2. **搜索 Project 主页**：使用 `web_search` 搜索论文的官方 Project Page / GitHub 仓库主页，记录 URL 用于报告展示。
3. **提取文本**：使用 `parse_file` 工具解析 PDF，获取全文文本。
4. **提取图片**：运行 `scripts/extract_figures.py` 脚本从 PDF 中提取关键图片。
   - 优先提取：teaser 图、核心方法示意图、主要实验结果图、指标对比图表。
   - 过滤策略：跳过 <10KB 的碎片图；优先从项目主页/GitHub README 抓取高清原图作为补充。
   - 若提取失败，在文档中标注 `[图片见原文 Figure X]` 并保留 caption。
5. **结构化解析**：将全文按章节拆分，识别 Abstract、Introduction、Related Work、Method、Experiments、Conclusion 等段落。

### 3. 深度分析

对每篇论文按以下维度生成**深度**分析内容（不是简单摘录，而是三层递进解读）：

| 维度 | 深度要求 |
|------|----------|
| 相关工作 | 不仅列出引用文献，还要说明每条前人工作的**核心思路**、本文与它的**具体区别**（改了什么、为什么改）、以及该方向的发展脉络 |
| 主要贡献 | 提炼 3-5 条核心贡献点，每条用"做了什么 → 解决了什么问题 → 带来什么效果"三段式表述 |
| 核心方法 | **三层递进**：① 直觉解释（通俗语言+类比）→ ② 公式推导（关键公式居中展示，逐项解释符号含义和设计动机）→ ③ 代码对应（伪代码概览 + 关键源码片段≤50行/片段，带语法高亮）。每个设计选择都要回答"为什么这样做"而非仅描述"做了什么" |
| 实验结论 | 逐表/逐图解读：说明实验设置 → 基线选择理由 → 主结果量化对比（标注提升百分比）→ 消融实验揭示了什么 → 失败案例分析。所有关键数字使用高亮标记 |
| 应用场景 | 列举 3+ 个实际或潜在应用方向，每个说明适用条件、预期收益、当前落地障碍 |
| 局限与展望 | 区分"作者自述局限"和"你识别的隐含局限"，对每条局限给出可能的改进思路或开放问题 |

### 4. 关联资源收集

对每篇论文自动搜索并整理：

- **代码仓库**：搜索 GitHub / Papers with Code。
  - 若找到：分析仓库结构（README、核心模块、入口文件），将关键代码片段（算法实现、模型定义等）结合到文档的核心方法章节中。
  - 若未找到：标注"暂未发现公开代码仓库"。
- **数据集**：列出论文使用的数据集名称 + 官方链接 + 规模描述 + 用途说明。
- **学术圈响应**：搜索 Twitter/X 讨论、技术博客解读、后续引用论文，简要汇总社区反馈。

### 5. 生成 HTML 报告

读取 `templates/report.html` 模板和 `references/html-style-guide.md` 样式规范，生成自包含 HTML 文档：

- **Project 主页链接**：在报告标题区下方、摘要之前，以醒目卡片形式展示论文 Project Page / 项目主页链接（如有）。若无官方主页，则展示 arXiv 抽象页链接。格式示例：`📄 Project Page: <a href="...">...</a>`。
- **导读速览卡片**：在 Project 链接之后、摘要之前，插入一个"快速导读"卡片（`.quick-guide`），用 3-5 个要点概括论文核心信息（一句话总结、关键指标、核心创新点、适用场景、推荐阅读顺序），帮助读者在 30 秒内建立全局认知。
- **阅读进度条**：页面顶部固定一条细进度条（`.reading-progress`），随滚动实时更新宽度，让读者感知阅读进度。
- **段落排版优化**：正文段落间距 1em；列表项间距 0.5em；h3 子标题上方加 24px 间距 + 左侧 3px 强调色竖线装饰；表格斑马纹交替背景色；关键数字/指标使用 `.highlight` 类高亮显示（浅蓝背景 + 圆角）。
- **公式样式**：数学公式使用居中块级展示（`.formula-block`），字号略大于正文，上下留白 16px，背景微灰以区分正文。
- **视觉风格**：学术风 — 衬线正文（Source Serif / Noto Serif）、无衬线标题、配色克制（黑白灰 + 一个强调色）。
- **布局**：左侧固定侧边栏目录导航 + 右侧主内容区。
- **交互**：各分析维度支持折叠/展开（使用 display:none/block 即时切换）；目录点击先展开目标章节再平滑滚动定位；移动端跳转后自动关闭侧边栏。
- **图片**：所有提取的图片以 base64 inline 嵌入，确保离线可用。
- **代码**：使用内联 CSS 实现语法高亮样式，不依赖外部 JS 库。
- **自包含**：所有 CSS、图片、字体声明均 inline，无外部请求。

输出文件命名：`{论文标题简写}_reading_report.html` 或多篇时 `{领域名}_papers_report.html`。

### 6. 交付

将生成的 **HTML 报告文件**和**原始论文 PDF** 一并写入工作区，告知用户两个文件的路径。

## 失败处理

- PDF 解析失败 → 告知用户，建议上传可解析版本或提供 arXiv ID 重新下载。
- 图片提取全部失败 → 继续生成文字报告，在对应位置标注 `[图片见原文]`。
- 代码仓库搜索无结果 → 正常标注，不影响其他内容生成。
- arXiv API 不可用 → 提示用户手动提供 PDF 文件或稍后重试。

## 验证方式

生成后用浏览器打开 HTML 文件检查：
1. 侧边栏目录导航是否正常显示和跳转（包括折叠状态的章节）。
2. 折叠/展开交互是否正常工作。
3. 移动端（窄视口）导航跳转后内容是否正常显示、侧边栏是否自动关闭。
4. 图片是否正确显示（非破损图标）。
5. 代码片段是否有基本语法高亮。
6. 所有分析维度是否都有深度内容覆盖。
7. 阅读进度条是否随滚动更新。
8. 快速导读卡片是否在摘要之前正确展示。
9. 页面无外部资源请求（断网测试）。
