# 状态报告模板骨架

**读这份文件的时机**：Step 6 落盘时复制骨架，然后按 `writing-patterns.md` 填三段式、按 `audience-tailoring.md` 裁四版。

产物路径：`docs/analysis/STATUS-{团队或项目}-{周期}.md`

周期段写法：周报 `2026-W41` / 双周报 `2026-W40-W41` / 月报 `2026-09`。

**填写顺序：A → D → B → C**（A 是母版，其余三版从 A 裁剪；C 最后填，否则容易先写出 3 个数字再去母版里凑证据）。文档中的**排列顺序**是 C → A → B → D（按读者重要性，方便转发时直接截取）。两个顺序不同是有意的。

各节填什么、常见错误见下表；写法细则在对应 reference 里：

| 小节 | 填什么 | 细则 | 最常见的错误 |
|---|---|---|---|
| 摘要 | 状态灯 + 上期计划交代结果 + 阻塞数与待决策数 | `audience-tailoring.md` §4 版本 A | 写成成果概述，不含「需要你做什么」 |
| C 高管版 | 目标达成度 / 3 个数字 / 1 个风险 / 1 个决策项 | `audience-tailoring.md` §3、§4 | 数字与 A 版不同源；风险选了「好看的那条」 |
| A.1 进展 | 上期计划逐项交代 + 插入工作 + 关键指标 | `writing-patterns.md` §2、§4 | 用百分比代替里程碑；漏掉 ❌ 的原因 |
| A.2 风险 | 五要素 + 信号源检查表 + 本期关闭的风险 | `writing-patterns.md` §4 第②段 | 写「暂无风险」却不填信号源表 |
| A.3 决策 | 五要素 + 上期决策项归属 + 已决策事项 | `writing-patterns.md` §4 第③段 | 只抛问题不给方案；把已自行执行的事写在这里 |
| A.4 / A.5 | 资源请求（数量+日期）/ 下期计划（可验证判据） | `cadence-and-format.md` §2.1 | 下期计划 > 8 条；判据写成「继续推进」 |
| B 跨团队版 | 影响他们的变更 / 需要他们配合的时间点 | `audience-tailoring.md` §4 版本 B | 写内部人事与内部排期争议 |
| D 内部版 | 任务清单 + 认领 / 待认领（带预估）/ 下期任务级计划 | `audience-tailoring.md` §4 版本 D | 出现真实姓名；出现归责表述 |
| 附录 | 采集参数 / 指标底稿（含上期值）/ 口径登记表 / 存疑项 / 高频改动区 / 术语 / 状态灯定义 / `[TBD]` 汇总 | `data-collection.md` §6 | 正文出现的数字在底稿里找不到同名行 |

## 一、完整骨架（单文件含四受众版本）

复制以下整块，替换 `{}`。填写提示以 `<!-- -->` 注释内嵌，定稿前删掉注释。

```markdown
---
doc_type: status-report
team_or_project: {团队或项目名}
period: {2026-W41}
period_start: {2026-10-05}
period_end: {2026-10-11}
prev_report: {docs/analysis/STATUS-{team}-{上期}.md 或 none}
overall_status: yellow      # green | yellow | red，定义见 §5.1，跨期不变
audiences: [manager, cross-team, executive, internal]
blocking_risks: {1}
open_decisions: {1}
tbd_count: {N}
---

# 状态报告 — {团队或项目} {周期}（{起始日} ~ {结束日}）

> **本报告的目的**：让读者做出决策，不是展示工作量。
> 三条铁律：① 坏消息与好消息同样显眼（风险在第 2 段，不在文末）；
> ② 每个数字都有口径，口径跨期一致（变更须显式声明）；
> ③ 不写无法被行动的信息。
> 全篇只写角色不写姓名，只写事不做归责。

**摘要（30 秒读完）**

状态：{🟢/🟡/🔴} {一句话}
上期计划 {N} 项：{a} 完成 / {b} 部分 / {c} 未完成
本期阻塞风险：{n} 项（{最高严重度}）　待决策：{n} 项（最近截止 {日期}）
```

## 三、落盘前最终检查

```
[ ] 文件名符合 STATUS-{团队或项目}-{周期}.md，周期段用 YYYY-Wnn / YYYY-Wnn-Wmm / YYYY-MM
[ ] 落在 docs/analysis/，不在仓库根目录
[ ] frontmatter 已填（period / prev_report / overall_status / blocking_risks / open_decisions）
[ ] 三个铁律逐条过：风险在前 1/3 / 每个数字有口径 / 每段能被行动
[ ] 上期计划逐项交代，结论只有 ✅/⚠️/❌，❌ 都有可核查的原因
[ ] 每条风险五要素齐全，编号跨期沿用，已关闭的进 A.2.3
[ ] 「已查信号源」表五格全部填了（写「暂无风险」的前提）
[ ] 每个决策项五要素齐全，且上期决策项都有归属（A.3.1）
[ ] 四个版本同一指标数值完全一致（逐个对账）
[ ] 高管版 ≤ 40 行，恰好 3 个数字 / 1 个风险 / 1 个决策项
[ ] 长度阈值：高管 ≤ 40 行、上级 ≤ 120 行、跨团队 ≤ 60 行
[ ] 全篇 grep 无「上周/本周/近期/最近/尽快/前不久/下阶段」
[ ] 全篇 grep 无「显著/大幅/明显/顺利/稳步/基本完成」
[ ] 全篇 grep 无「请领导指示/详见附件/后续跟进/暂无风险」
[ ] 全篇无真实姓名（只有角色）、无 blame 表述、无内部域名、无凭据
[ ] 每个数字都能在事实底稿里找到同名行
[ ] 口径与上期一致；若有变更，四要素声明齐全
[ ] 事实底稿单独留存，未覆盖上期底稿
```

**自检命令**（复制改路径后跑）：

```bash
F="docs/analysis/STATUS-{team}-{period}.md"
wc -l "$F"
grep -nE '上周|本周|近期|最近|尽快|前不久|下阶段' "$F" || echo "OK 相对时间"
```
