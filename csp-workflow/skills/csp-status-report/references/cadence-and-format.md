# 周期、节奏与格式纪律

**读这份文件的时机**：Step 0（定周期与粒度）与 Step 6（格式自检）。

## 一、周期与粒度分工

| | **周报** | **双周报** | **月报** |
|---|---|---|---|
| 文件周期段 | `YYYY-Wnn` | `YYYY-Wnn-Wmm` | `YYYY-MM` |
| 采集时间窗 | 7 天 | 14 天 | 自然月 |
| 进展粒度 | 任务级（T-nnn） | 任务级聚合到里程碑 | **里程碑级**，不下探到任务 |
| 指标粒度 | 本期 vs 上期（1 周环比） | 本期 vs 上期 + 4 周趋势 | 本期 vs 上期 + 3–6 个月趋势 |
| 风险条目 | 全部五要素 | 全部五要素 | 只保留 `[阻塞-下期]` 及以上；已缓解的合并成一句 |
| 决策项 | 全部 | 全部 | 只保留需要更高层级决策的；团队内可决定的移到内部版 |
| 受众 | 上级 + 团队内部（B/C 版按需） | 上级 + 跨团队 | **高管 + 跨团队**（周报不发高管） |
| 上期计划交代 | 逐项 | 逐项 | 按里程碑汇总，异常项才逐项 |
| 事实底稿附录 | 必附 | 必附 | 必附 + 跨期趋势表 |
| **不该放什么** | 跨期趋势分析（→ 月报）、指标归因（→ `csp-product-metrics-review`）、超过 8 条的任务流水（合并同类或只留在内部版）、路线图变更论证（→ `csp-roadmap-update`） | 日粒度活动流水、单条提交的说明、超过 8 条的风险明细（同类合并成一条 + 附录列全）、经验教训（→ `csp-retro`） | 任务级清单、单周过程细节、超过 8 条的风险明细、口径的推导过程（只留口径登记表）、「本期临时指标」的趋势解读 |
| 编写耗时预算 | ≤ 45 分钟 | ≤ 60 分钟 | ≤ 2 小时 |

**不在本技能范围**：里程碑 / 项目收尾总结 → `csp-retro`（周期报告只引用其结论一行）；里程碑是否达成 gate → `csp-audit-milestone` 命令。把「要决策的周期报告」和「要学习的收尾总结」混在一份里，两者都会失效——读者同时被要求做决定和做反思，通常两样都不做。

**混合周期的规则**：同一个项目只选一种主周期。若上级要周报、高管要月报，则月报**必须由周报的事实底稿汇总生成，不得重新采集**——重新采集是口径漂移的头号来源（时间窗对不齐、bot 排除规则不同、任务分母不同）。汇总时在月报附录写清「本期数据由 W{nn}–W{mm} 四份周报底稿汇总，未重新采集」。

**选周期的判据**：

| 情形 | 用 |
|---|---|
| 项目处于交付冲刺、里程碑在 6 周内、有活跃阻塞 | 周报 |
| 项目处于稳定迭代、阻塞少、上级不需要每周介入 | 双周报 |
| 项目周期以季度计、受众主要是高管与跨团队 | 月报（+ 出现 `[阻塞-本期]` 风险时立即发临时周报，不等月报） |
| 团队同时被上级和高管要求汇报 | 上级周报 + 高管月报；**不要给高管发周报**（信息密度不匹配，会被忽略，之后真正的红灯也一起被忽略） |

**临时报告的触发条件**（不等周期）：

```
[ ] 出现新的 [阻塞-本期] 风险，且需要上级在 3 个工作日内动作
[ ] 里程碑确定延误（不是「有风险」，是「已确定」）
[ ] 发生 P1 事故
[ ] 需要一项不可逆决策（如放弃某条技术路线、缩减范围）
```

临时报告只发版本 A 与（若涉及）版本 C，正文 ≤ 20 行，标题写明「临时」与触发原因。

## 二、「上期计划必须在本期交代」——为什么这条规则最重要

**规则**：本期报告的第一张表，必须是上期报告「下期计划」的逐项交代，含未完成项及原因。

### 2.1 可操作方法：整段复制，不靠记忆

1. 打开上期文件，定位「下期计划」表（母版 §A.5 / 内部版 §D.5）。
2. **整段复制**到本期的「上期计划逐项交代」表——连编号（P1…Pn）与「完成判据」列一起复制，**一个字不改**。
3. 在复制来的表右侧补两列：「本期实际状态」「判定 + 原因 / 剩余」。判定只允许 ✅ / ⚠️ / ❌ 三个值（见 §2.3），不允许「进行中」。
4. 「本期实际状态」与上期完全相同的行 → 自动成为风险段信号源 2（连续两期未推进项）的候选，逐行决定是否升级为 `R{n}`。
5. 判定为 ❌ 且实际情形是「取消」的 → 必须补三样：决定人角色、决定日期、原目标由什么承接（或明确写「不承接」）。

**为什么必须复制而不是重写**：重写时人会不自觉地按本期实际做的事去重述上期计划（上期写的是「调研 X」，本期记成「调研并实现 X」），完成率因此虚高。逐字复制是唯一能防住这种自我美化的办法，也是读者能对账的前提。

**条数纪律**：上期「下期计划」≤ 8 条。若本期 ✅ 占比 < 50%，下期计划条数必须减半，并在报告里写明「本期完成 {a}/{N}，下期计划由 {N} 条减至 {N/2} 条」——这是把估算偏差变成一个可见动作的唯一办法；否则每期都会重复同一份过载计划。

### 2.2 不做这件事会发生什么（可信度按期数衰减）

| 不交代会发生什么 | 机制 |
|---|---|
| **计划退化成许愿** | 写下计划没有后果 → 计划越写越乐观 → 最后没人相信任何计划，包括排期承诺 |
| **延误被稀释** | 每期只报本期做了什么，一个滑了 6 周的项在 6 份报告里都「正在推进」，从不显形 |
| **失去速率基线** | 没有「计划 vs 实际」的对比，就无法算出团队的真实速率，也就无法做可信的排期预测 |
| **风险变成事故** | 未交代的未完成项不会进入风险段的信号源 2（连续两期未推进项）检查 |
| **读者停止阅读** | 读者会对比上期。发现两次「计划了但没交代」之后，报告的可信度整体归零，之后连真正的红灯也一起被忽略 |

**可信度衰减是按期数累积的**，所以这条规则的代价不是当期，而是 3–4 期之后：

| 连续未交代的期数 | 读者的判断 | 汇报人失去什么 |
|---|---|---|
| 第 1 期 | 以为是遗漏 | 无（但会被追问） |
| 第 2 期 | 开始怀疑汇报人是否掌握实情 | 读者绕过报告直接去问一线，报告失去信息枢纽地位 |
| 第 3 期 | 认定「计划」是装饰 | 计划不再被当作承诺；排期沟通每次都要从头论证 |
| 第 4 期起 | 报告被当作仪式性文档 | 只有数字被扫一眼，风险段与决策段失效——**真正的红灯一起被忽略** |

**恢复到第 1 期的信任需要连续 4 期以上逐项交代**，且其中至少一期出现诚实的 ❌。所以：宁可当期难看，不要欠账。

### 2.3 交代的合法结论（只有三种判定值，没有「进行中」）

| 结论 | 要求 |
|---|---|
| ✅ 完成 | 给可验证的达成证据（合并记录 / 灰度比例 / 指标数值 / 验收日期） |
| ⚠️ 部分完成 | 写清到达了什么状态、剩余什么、为什么没全做完 |
| ❌ 未完成 / 未开始 | **必须写原因**，且原因要落到可核查的事实（被插入项挤占 N 人日 / 依赖 R_n 未解除 / 估算偏差 / 优先级被调整），不能写「时间不够」 |
| ❌ 取消（❌ 的子类） | 判定仍记 ❌，另需三样：**决定人角色 + 决定日期 + 原目标由什么承接**（或明确写「不承接」）。**无决定人的取消一律视为未完成**——悄悄丢弃的计划下期会以插入项的形式回来 |

**「未完成」不是坏消息，隐瞒未完成才是。** 一个诚实标注 ❌ 并给出原因的报告，比一个全是 ✅ 的报告更能支撑决策。

**连续未完成的升级规则**：

| 连续未完成期数 | 处置 |
|---|---|
| 1 期 | 正常交代 + 原因 |
| 2 期 | 必须进入风险段（信号源 2），标 `[阻塞-下期]` 或 `[质量]` |
| 3 期 | 必须成为决策项：继续做（要什么资源）/ 降优先级 / 取消。**不允许第四期继续滑** |

## 三、跨期一致性

### 3.1 指标连续性

**规则**：核心指标集一旦确立，**至少连续保持 8 期不变**。每期换指标的报告无法纵向对比，等于每期都在重新开始。

| 类别 | 建议固定的核心指标（各选 1–2 个，选定后不换） |
|---|---|
| 进度 | 计划完成率（分母固定）、里程碑达成数 |
| 交付 | 主干人工变更数、发布次数 / 回滚次数 |
| 质量 | P95 或 P99 时延、5xx 错误率、缺陷数按分级 |
| 稳定性 | 可用性、P1/P2 告警数、事故影响时长 |
| 流程健康 | 打开超 5 日的 MR 数、跨团队请求响应时长、打回数 |

**每期都变的「特色指标」另设一区**，标题写明「本期临时指标（不纳入纵向对比）」。这样既保留了灵活性，又不污染趋势线。

### 3.2 口径变更的处理

口径**尽量不改**。确实必须改（例如监控迁移、统计脚本升级、组织结构变化）时：

```markdown
> **口径变更声明（W41 起生效）**
> 指标「计划完成率」的分母由「本期计划任务数」改为「本期计划任务数 + 期内插入项」。
> 变更原因：连续 3 期插入项占比 > 20%，原口径无法反映真实负荷。
> 新旧口径对照：
> | 期 | 旧口径 | 新口径 |
> |---|---|---|
> | W39 | 82%（9/11） | 69%（9/13） |
> | W40 | 91%（10/11） | 71%（10/14） |
> | W41 | 25%（1/4） | 14%（1/7） |
> 自 W41 起所有报告使用新口径；历史报告不回改，但事实底稿保留双口径两期以便过渡。
```

**四要素缺一不可**：变更内容、变更原因、新旧口径至少 2 期对照、生效期。

**禁止的做法**：

| 做法 | 为什么禁止 |
|---|---|
| 悄悄换指标（上期报 A，本期报 B，不解释） | 读者会以为是 A 变差了才换 |
| 悄悄换口径（分母变了不说） | 同上，且更隐蔽 |
| 数字变差时改口径，变好时不改 | 一次被发现，全部历史数据都被重新审视 |
| 「本期起采用更科学的统计方式」而不给对照 | 「更科学」不可验证；给对照表才叫声明 |

### 3.3 跨期追踪的编号体系

编号一旦分配，跨期沿用，不复用、不重排：

| 前缀 | 含义 | 生命周期 |
|---|---|---|
| `P{n}` | 上期计划项 | 交代完毕后关闭；下期计划用新的 P 编号 |
| `T-{nnn}` | 任务 | 全局递增，跨期不变 |
| `R{n}` | 风险 | 关闭后移入「本期关闭的风险」表，编号不再复用 |
| `D{n}` | 决策项 | 决策后移入「已决策事项」表，编号不再复用 |
| `M{n}` | 里程碑 | 项目级，全周期不变 |

**好处**：读者说「R1 怎么样了」时，双方指同一条。编号重排会让「连续两期未推进」的检测失效。

### 3.4 趋势表（月报必含，周报可选）

```markdown
### 8 期趋势（示例数据）

| 指标 | W34 | W35 | W36 | W37 | W38 | W39 | W40 | W41 | 口径 |
|---|---|---|---|---|---|---|---|---|---|
| 计划完成率 | 73% | 80% | 75% | 88% | 82% | 91% | 78% | 25% | 分母 = 本期计划任务数 |
| checkout P99 | 910ms | 880ms | 860ms | 850ms | 830ms | 820ms | 820ms | 210ms | 全接口聚合，预发环境 |
| 5xx 错误率 | 0.42% | 0.38% | 0.35% | 0.33% | 0.31% | 0.31% | 0.31% | 0.04% | 网关侧 5xx |
| 打开超 5 日 MR | 1 | 2 | 2 | 3 | 3 | 2 | 2 | 4 | 创建日早于周期起始且仍 opened |
```

**趋势表能暴露的东西，单期报告永远暴露不了**：连续 5 期缓慢恶化的指标（如 MR 堆积 1→4）、一次性跃升是否可持续、以及「计划完成率长期 80% 左右」这类系统性估算偏差。

## 四、格式纪律（阈值化）

| 纪律 | 具体阈值 | 检查方法 |
|---|---|---|
| **长度上限** | 高管版 ≤ 40 行；上级版 ≤ 120 行；跨团队版 ≤ 60 行；内部版不限但全表格化 | `wc -l` 或数行 |
| **正文总行数** | ≤ 256 行（不含附录）。附录不计入上限，但正文每个数字必须在附录有同名行，反之附录每行都要能被正文或口径表引用 | `wc -l` 减去附录段行数 |
| **节内条目数** | 每节 ≤ 8 条：风险 ≤ 8、进展 ≤ 8、上期交代 ≤ 8（等于上期计划条数）、下期计划 ≤ 8、关键指标 5–8 行、**决策项 ≤ 4** | 数表格行；超限处理见 §4.1 |
| **单条目字数** | ≤ 256 字，其中留在正文的结论句 ≤ 64 字 | 目视最长单元格；超限处理见 §4.1 |
| **标题层级** | ≤ 3 级（`##` / `###` / `####`） | 出现第 4 级 → 说明该拆成两个文档或改成表格 |
| **关键数字数** | 高管版恰好 3 个；上级版 ≤ 8 个；每个数字带口径或指向附录口径表 | 超出 → 移入事实底稿 |
| **表格优先** | ≥ 3 条并列信息 → 一律用表格，不用段落罗列 | 搜正文里的顿号列表与「首先/其次/另外」 |
| **段落长度** | 单个段落 ≤ 4 行；超过就拆成表格或列表 | 目视 |
| **绝对日期** | 全篇禁用「上周 / 本周 / 近期 / 最近 / 尽快 / 前不久 / 下阶段」；一律 `2026-10-11` 或 `W41` | `grep -nE '上周\|本周\|近期\|最近\|尽快\|前不久\|下阶段'` |
| **相对时间** | 允许「6 个工作日无回复」这类**带锚点的**相对表述（锚点是绝对日期）；不允许无锚点的「前几天」 | 检查每个相对表述前是否有绝对日期 |
| **形容词禁令** | 禁用「显著 / 大幅 / 明显 / 基本 / 顺利 / 持续 / 有效 / 积极 / 稳步」修饰成果；一律换成数值 | `grep -nE '显著\|大幅\|明显\|基本完成\|顺利\|稳步'` |
| **不确定表述** | 禁用「应该 / 大概 / 估计 / 差不多」；要么给数字，要么标 `[待核实]` | `grep -nE '应该\|大概\|估计\|差不多'` |
| **术语** | 首次出现给一句定义，或统一进附录术语表；缩写首次出现展开 | 逐个检查缩写 |
| **数字口径** | 每个数字后跟口径，或统一在附录口径表；不允许裸数字 | 对照事实底稿逐行核 |
| **无 blame** | 只写事不写人；「{项} 连续 2 期未推进」而非「{某人} 没做」 | `grep -n` 人名（本技能产物应只有角色） |
| **状态标签** | 风险用固定四档 `[阻塞-本期]/[阻塞-下期]/[质量]/[效率]`；任务用 `✅/⚠️/❌` 三档 | 检查是否出现自造标签 |
| **占位符** | 未取到的数据一律 `[TBD]` 或 `[待核实]`，不留空、不猜 | `grep -n 'TBD\|待核实'` 汇总数量 |

### 4.1 超限时的处理（按顺序试，不要直接放宽阈值）

| 超限 | 处理 |
|---|---|
| 风险 > 8 条 | 说明没排序。按严重度取前 8，其余同类合并成一条（附录列全）。合并后仍 > 8 → 它们不是同一类风险，按类型拆节或拆文档（§4.2） |
| 决策项 > 4 条 | 说明没排优先级。只留截止时间最早的 4 条；其余在上级版单列沟通，下期再上。一次会议拍不了 5 个决定 |
| 单条目 > 256 字 | 一条 512 字的风险通常其实是三条。先拆条；拆不动就把证据与推导移入附录，正文只留 ≤ 64 字的结论句 |
| 进展 > 8 条 | 按「状态迁移幅度」取前 8（起点与终点差异最大的），其余压成一行「另有 {N} 项按计划推进，明细见内部版」 |
| 正文 > 256 行 | 先按 `audience-tailoring.md` §3.1 的 8 步删；删不下来 → 按 §4.2 判据拆分 |

### 4.2 什么时候该拆成两个文档（而不是写长）

| 判据 | 拆法 |
|---|---|
| 受众之间需要保密隔离（人力/外包成本、未公开的范围裁剪） | 主文件留索引（≤ 8 行），各受众拆为同名 + `-{受众}.md`；事实底稿只存一份，放上级版 |
| 正文 > 256 行且按 §4.1 裁不下来 | 说明装了两个主题，按主题拆（如「交付状态」与「质量专项」各一份） |
| 一份文档含 ≥ 2 个独立项目/团队（各有里程碑、风险与决策） | 按项目拆 `STATUS-{项目}-{周期}.md`，另建一份汇总（≤ 40 行：各项目状态灯 + 各 1 个最大风险 + 各 1 个决策项） |
| 单节 > 8 条且无法按严重度裁剪（例如 12 条风险「都同样重要」） | 它们不是同一类；按类型拆成两节或两份（交付类 / 质量类 / 依赖类） |
| 想在周期报告里放里程碑或项目收尾的经验总结 | 不拆，直接移出 → `csp-retro`；本文件只留一行链接与其结论 |

**拆分的代价**（能不拆就不拆）：多份文件 = 多次口径漂移的机会 + 读者只读其中一份 + 四版同源检查从 1 次变成 N 次。拆完必须做到：① 主文件首屏列出全部子文件路径；② 事实底稿只存一份；③ 各子文件的同一指标同源同值。

### 4.3 自检命令（把路径换成本期报告）

```bash
F="docs/analysis/STATUS-{team}-{period}.md"

wc -l "$F"
grep -nE '上周|本周|近期|最近|尽快|前不久|下阶段' "$F" || echo "OK: 无相对时间"
grep -nE '显著|大幅|明显|顺利|稳步|基本完成' "$F" || echo "OK: 无空泛形容词"
grep -nE '应该|大概|估计|差不多' "$F" || echo "OK: 无不确定表述"
grep -nE '请领导指示|详见附件|后续跟进|暂无风险' "$F" || echo "OK: 无推诿表述"
grep -cE '^\|' "$F"    # 表格行数，占比过低说明段落化
grep -n 'TBD\|待核实' "$F" | wc -l    # 缺口数量，应全部登记在附录
```

## 五、节奏落地建议

| 事项 | 建议 |
|---|---|
| 采集时间 | 周期结束当天做一次全量采集（命令跑一遍约 10 分钟），不要靠记忆回溯 |
| 编写时间 | 采集后 24 小时内成稿；隔一周再写，事实底稿之外的记忆全部不可靠 |
| 事实底稿留存 | 每期底稿存为 `docs/analysis/STATUS-{team}-{period}.md` 的附录，或单独存 `.csp/artifacts/status/{period}-facts.md`；**不要覆盖上期底稿**（跨期对比依赖它） |
| 口径登记表 | 单独维护一份跨期口径表（可放在首期报告的附录，之后每期引用），列出每个核心指标的分子/分母/时间窗/排除规则 |
| 首期特殊处理 | 第一次写时没有上期基线 → 显式声明「本期建立基线，无历史对比」，并把口径登记表作为本期最重要的产物 |
| 与 `csp-plan-phase` 的衔接 | 状态报告的「下期计划」是 `csp-plan-phase` 的输入之一；若下期计划需要重排资源，走 `csp-plan-phase` 而不是在状态报告里现场重排 |
| 与 `csp-roadmap-update` 的衔接 | 决策项被批准且涉及范围/时间线变更 → 交 `csp-roadmap-update` 落地，状态报告下期只交代结果 |
