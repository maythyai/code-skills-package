# 影响分析报告模板

产物路径：`docs/analysis/IMPACT-{change-slug}-{date}.md`（如 `IMPACT-remove-orders-legacy-flag-2026-02-14.md`）。八个必备小节缺一不可；某节确实不适用时写"不适用 + 一句话原因"，不许删节。下面模板中 `>` 引用块是填写说明，交付时删除；表格给的是**填好的样例**，照格式替换为真实内容。

```markdown
# IMPACT: {变更标题}

- 日期：{YYYY-MM-DD}
- 变更单元：{精确到符号级：文件/函数/表.字段/接口路径/配置键/消息 schema}
- 变更类型：{新增行为 / 修改行为 / 删除 / 重命名 / 格式转换}
- 风险级别：{R1 / R2 / R3 / R4}（判定依据见第 4 节）
- 分析人：{role 即可，不署名}

## 1. 变更描述

> 三段以内：改什么、为什么改、怎么改（方案要点）。改动的 git 形状：
> `git diff --stat` 摘要（几个文件、几行、哪些模块）。

示例：
删除 `orders.legacy_flag` 列及 `OrderService.buildLegacyFlag()`。该列为 2023 年迁移遗留，
新链路已不读取。本次改动涉及 3 个文件、-142 行，含 1 个 migration（删列 DDL）。

## 2. 影响面六维表

> 每维一行到多行。"证据"列必须是命令 + 输出摘要，不接受"我记得/应该没有"。
> 结论只有三种：需改动 / 需通知 / 不受影响（未发现，注明搜索方法与盲区）。

| 维度 | 受影响对象 | 证据（命令 → 输出摘要） | 结论 |
|------|-----------|------------------------|------|
| 1 代码级 | `ReportJob.export()` 调用 `buildLegacyFlag()` | `grep -rn "buildLegacyFlag" --include='*.java' .` → 2 处：定义 + ReportJob | 需改动 |
| 1 代码级（动态引用） | 未发现反射/字符串引用 | `grep -rn '"legacy_flag"\|"legacyFlag"' .` → 仅测试 fixture；反射入口审查无命中 | 不受影响（盲区：外部仓库未搜） |
| 2 契约级 | 对外 API `GET /v1/orders` 响应含 `legacyFlag` 字段 | `grep -rn "legacyFlag" --include='*.json' api/` → OrderResponse schema 命中 | 需改动（契约变化 → 穿透，见维度 6） |
| 3 数据级 | 存量 1.2 亿行含该列；报表 SQL 直接 `SELECT legacy_flag` | `grep -rn "legacy_flag" --include='*.sql' analytics/` → 3 个报表脚本 | 需改动 + 需通知数据团队 |
| 4 运行时级 | 无共享资源/定时任务变化（ReportJob 为周任务，改后仍幂等） | `grep -rn "@Scheduled" ReportJob.java` → cron 周跑；新逻辑只删字段无状态写入 | 不受影响 |
| 5 部署级 | 订单服务 + 报表服务两个部署单元；删列 DDL 必须最后执行 | `find . -name 'deployment*.yaml'` → 2 个；发布顺序见第 6 节 | 需改动 |
| 6 使用方级 | 网关日志：近 30 天 `legacyFlag` 字段被 2 个外部合作方读取 | 访问日志抽样 → partnerA 812 次/天、partnerB 37 次/天 | 需通知（走废弃流程） |

## 3. 传导路径图

> 正向影响传导（谁依赖我 → 向上传），标注每层节点与截止原因（契约边界/2 层上限/去重）。

示例：

    OrderService.buildLegacyFlag()   ← 变更点
    ├── 第1层: ReportJob.export()            [需改动]
    │   └── 第2层: 周报表文件（对外产物）     [契约边界 → 停，需通知数据团队]
    ├── 第1层: OrderResponse.legacyFlag      [契约本身变化 → 穿透]
    │   └── 外部: partnerA / partnerB 读取    [需通知 + 废弃流程，≥14 天]
    └── 第1层: orders.legacy_flag 列          [数据级 → 见第 6 节发布顺序]

    截止说明：ReportJob 分支在第 2 层命中对外产物契约边界，停止追溯，记"需通知"。

## 4. 风险分级

> 三轴各选一档 → 按 SKILL.md 分级表定级，写明命中了哪条判定条件。

| 轴 | 取值 | 依据 |
|----|------|------|
| 影响范围 | 对外（外部合作方读取字段） | 第 2 节维度 6 证据 |
| 可逆性 | 不可逆（删列 + 删公开字段） | 命中 irreversible 两类形态 |
| 检测难度 | 只有用户会发现（该字段无测试断言、无监控） | `grep -rn "legacyFlag" --include='*Test*'` → 无断言 |

**级别：R4**。强制动作：expand-contract 改造（见第 6 节）、设计评审、灰度、回滚演练、
下游通知、架构负责人签字。

## 5. 回归范围

| 集合 | 内容 | 跑在哪 |
|------|------|--------|
| 最小必要回归集 | `OrderServiceTest`（含对 `buildLegacyFlag` 的 3 条断言，需同步改为新行为）、`ReportJobTest.export 字段断言`、契约测试 `orders-api-contract` | CI 每次提交 |
| 完整回归集 | 最小集 + 报表服务全量集成测试 + `GET /v1/orders` 端到端（验证 partnerA 样例请求响应） | 预发环境，发布前 |

> 断言审查记录：列出检查过的测试与结论（覆盖旧行为需同步修改 / 覆盖新行为 / 无断言）。
> 无断言覆盖的受影响路径 → 补测试或加监控，写在这里。

示例：`OrderApiIT` 调用了 `GET /v1/orders` 但未断言响应字段集合 → 不构成保护，
已补断言（提交 {hash}）。

## 6. 发布顺序

> 逐步骤：步骤号 / 内容 / 部署单元 / 灰度策略 / 单步回滚动作。不可逆步骤必须排在
> 观察期之后且单独成步。

| 步骤 | 内容 | 灰度 | 回滚动作 |
|------|------|------|---------|
| 1 | 应用停止读取 legacy_flag（双读改单读新逻辑） | 订单服务 10%→100% | 回退应用版本，无数据影响 |
| 2 | API 响应 legacyFlag 标记 Deprecated 头 + 公告 | 全量 | 回退版本即可 |
| 3 | 报表 SQL 切换数据源，通知数据团队 | 报表服务全量 | SQL 回退旧版本 |
| 4 | 观察期 ≥14 天：监控字段读取量归零 | — | 不适用（无变更） |
| 5 | 应用停写 + 删除代码引用 | 订单服务灰度 | 回退版本，列仍在，无损 |
| 6 | DDL 删列（单独发布，架构负责人签字后执行） | 低峰窗口 | **不可回滚**——前置条件：步骤 5 稳定运行 ≥7 天 |

## 7. 回滚方案

> 总体回滚剧本：发现异常时的第一动作、各步骤回滚入口、数据兜底（备份表/快照位置与保留期）、
> 回滚决策人。演练记录（日期 + 结论）也写这里；R3/R4 未演练不允许发布。

## 8. 需通知的人

> 来源：传导截止规则 R2 的"需通知"节点 + 维度 6 全部对象。列出：对象 / 通知内容 /
> 渠道（中性描述：IM、邮件、工单系统评论）/ 是否已确认。

| 对象 | 通知内容 | 状态 |
|------|---------|------|
| 数据团队 | 报表 SQL 切换 + legacy_flag 下线时间表 | 已确认 |
| partnerA / partnerB（经合作方接口人） | 字段废弃公告 + 迁移指引 + 下线日期 | 已发送，待确认 |
| 订单服务 owner / 报表服务 owner | 评审邀请（git blame 定位：见 git 证据） | 已确认 |
```

## 质量自检（交付前逐项过）

- [ ] 第 2 节每行"证据"列都是命令 + 输出摘要，无印象式结论
- [ ] 动态引用四类（反射/字符串路由/DI/构建期）在第 2 节有独立行，含"未发现"结论与盲区说明
- [ ] 第 3 节每条传导路径标注了截止原因
- [ ] 第 4 节三轴取值都能回链到第 2 节证据
- [ ] 第 5 节含断言审查记录；"测试存在但未断言"的路径已标注
- [ ] 不可逆步骤排在观察期后、单独成步、标注"不可回滚"
- [ ] 第 8 节覆盖全部"需通知"节点，含外部使用方
- [ ] 文件位于 `docs/analysis/`，文件名含 change-slug 与日期
