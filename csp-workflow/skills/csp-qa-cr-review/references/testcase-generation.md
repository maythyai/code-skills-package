# 测试用例生成 — Aone TestHub xlsx

## 触发条件

- **入参明确**：用户包含"生成用例""出用例""测试用例" → 评审完成后直接生成
- **入参未提及**：评审后询问"是否需要生成可导入 Aone 的测试用例？"

## 数据来源

1. Step 2 识别的逻辑变更点
2. 功能入口清单
3. 问题明细中的验证点

## 矩阵式用例组织（强制）

用例不能只是代码分支的逐条枚举，必须按业务视角组织为**入口×状态组合**矩阵。

### 规则 A：追溯 callers 建入口维度（文件夹）

- diff 修改了方法 M 的内部逻辑时，搜索 M 的所有调用方
- 每个调用方 = 一个业务触发入口 = 一个文件夹维度
- 仅从 diff 看到一条调用路径就停止 → 遗漏其他入口验证

### 规则 B：数据状态组合 > 单枚举值枚举

- 同一入口下，用例按**数据状态组合**排列
- ✅ 组合场景："退一张票（混合状态）" → 同时验证退票过滤 + 未退票正常发送
- ❌ 单枚举枚举："REFUND_COMPLETE→跳过""REFUNDING→跳过" → 各只验证一个方向
- 单枚举仅用于组合无法覆盖的边界（特殊分支逻辑）

### 规则 C：命名用业务操作语言

- 名称用测试人员能直接理解的业务操作描述
- 代码枚举值放 E 列（前置条件）或 J 列（描述），不混入 A 列名称

## 命名规范（A 列，强制）

格式：`前提：[业务场景/数据状态]-[触发的行为/操作]，[预期结果]`

| | 正例 | 反例 |
|---|---|---|
| ✅ | 前提：邀请函订单，票品已退票完成-设置邀请函失效发送通知，此订单应跳过失效通知 | ❌ 票品已退票完成-跳过邀请函失效通知 |

- 读者仅看名称即可理解整个用例意图
- 可保留关键代码枚举标注（如 `退票完成(REFUND_COMPLETE)`）

## 正反例对比

| | 手工用例（正确） | 自动用例 v1（缺陷） |
|---|---|---|
| 入口维度 | 2 个文件夹：不修改失效时间 / 修改失效时间 | 仅 1 个入口 |
| 状态组合 | 3 行：不退/全退/退一张 | 4 条独立枚举+1 正向=5 条 |
| 命名 | "退一张票，退的不发，剩下发" | "票品状态为退票完成(REFUND_COMPLETE)-跳过通知" |

正确做法：先 `grep sendCancelMsg` 找所有 callers → 识别入口 → 每入口按组合出用例

## xlsx 输出格式（Aone TestHub 导入模板）

| 列 | 字段 | 说明 |
|----|------|------|
| A | 用例名称 | 必填，业务语言完整叙事句 |
| B | 用例文件夹 | 层级用 / 分隔 |
| C | 优先级 | P0-P3 |
| D | 用例类型 | 手工/自动化 |
| E | 前置条件 | 业务语言描述数据准备 |
| F | 内容类型 | 文本 |
| G | 步骤内容 | 操作序列 |
| H | 预期结果 | 可观测业务结果 |
| I | 标签 | 英文;隔开 |
| J | 描述 | 技术细节（SQL/代码对应） |

## 优先级与标签

- 核心正向用例：P1
- 回归用例：P1
- 边界/异常：P2
- 标签统一包含 `CR{cr_id}`

## 文件生成

- 文件名：`{app}_{变更描述}_CR{cr_id}_测试用例.xlsx`
- 使用 openpyxl 加载内置模板，删除样例行后填充数据
- 保存到 outputs 目录，`present_files` 返回

### 文件锁 fallback

重新生成时若旧文件被 Excel 打开（PermissionError），禁止 `rm -f` 强删，改用 `v2`/时间戳后缀另存。
