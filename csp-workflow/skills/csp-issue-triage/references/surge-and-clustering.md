# 批量聚类与激增处置手册

适用：单日新增 >20 单的批量分诊，或例行分诊中发现聚集迹象。目标：把"一堆单"变成"几个聚类 + 每个聚类的处置决定"，并识别需要升级的激增。

## 1. 三路聚类的计数方法

对分诊窗口内的全部**有效缺陷单**（去重合并后，剔除误报/环境/咨询/需求），按三路分别分组计数。数据来源：工单系统的导出清单或看板透视（按签名/模块/版本字段分组计数）；签名缺失的单先按 `fingerprint-and-dedup.md` 补签名再入组。

| 聚类路 | 分组键 | 计数口径 |
|--------|--------|---------|
| 指纹聚类 | 规范化堆栈签名（无栈单用弱签名，单独标注） | 窗口内该签名的单数；同时记录该签名的历史累计（90 天） |
| 模块聚类 | 分诊打标的模块归属 | 窗口内该模块新增单数 |
| 版本聚类 | "首次出现版本"字段 | 窗口内首现版本 = 某新版本的单数 |

基线：取**前 7 天同口径日均值**；样本不足（新模块、新版本无历史）时，用全队列日均做分母并在记录中注明基线来源。

## 2. 激增判据（默认阈值与调参）

| 聚类路 | 默认激增判据（满足其一） | 调参指引 |
|--------|------------------------|---------|
| 同一指纹 | 24h 内 ≥5 单；或达前 7 天日均 3 倍；或该签名历史累计 90 天内第 3 次成簇 | 高流量产品可上调绝对数（如 ≥10），倍数阈值比绝对数更稳健，优先用倍数 |
| 同一模块 | 单日 ≥ 该模块前 7 天日均 3 倍，且绝对数 ≥3 | 模块粒度太粗会掩盖激增：单模块日均 >5 单的团队应按子模块细分 |
| 发版窗口 | 新版本发布后 48h 内，"首现版本 = 新版本" ≥3 单 | 灰度发布期间阈值减半（灰度流量小，3 单已是强信号）；48h 覆盖首个完整工作日 + 周末发布场景 |

误报控制：单日总量 <10 时不触发激增判定（小样本波动），只记录观测值；节假日后首个工作日、大型活动后 24h 内的总量上涨先对照运营日历再判定。

## 3. 激增类型判别

命中激增后先判类型，再选升级动作：

| 特征组合 | 类型 | 含义 |
|---------|------|------|
| 版本聚类命中 + 指纹集中（≥60% 的单共享 1–2 个签名） | 发布回归 | 新版本引入的具体 bug |
| 版本聚类命中 + 指纹分散 | 发布面问题 | 配置/依赖/环境随发布变化，不是单点代码 bug |
| 模块聚类命中 + 版本聚类不命中 | 存量劣化或外部依赖故障 | 与发布无关：下游服务、中间件、数据规模变化 |
| 指纹聚类单路命中（模块/版本都不集中） | 跨切面 bug | 公共库/公共中间件问题，扩散风险最高 |

## 4. 升级动作决策树

按序评估，每步记录"评估过 + 结论"，不允许跳步不评：

```
激增确认
 ├─ 1. 是否伴随 P0（数据/资金/核心阻断）？
 │     └─ 是 → 移交事故指挥流程（csp-incident-commander），本分诊记录附聚类证据
 ├─ 2. 是否与发版窗口强关联（版本聚类命中）？
 │     ├─ 是 → a. 评估暂停发布/冻结灰度扩量（默认动作：先冻结，再评估）
 │     │        b. 评估回滚：变更可逆？回滚成本 < 带病运行成本？→ 回滚
 │     │        c. 不可回滚（含数据迁移）→ 热修通道（csp-hotfix）+ 降级开关
 │     └─ 否 → 3
 ├─ 3. 是否指向外部依赖/基础设施（存量劣化型）？
 │     └─ 是 → 拉依赖方确认；本地动作 = 加监控哨兵 + 评估降级/熔断
 └─ 4. 其余情况 → 成立专项：
        指定专人集中处理该聚类，暂停其常规迭代；
        专项目标 = 聚类内单收敛到 0 或降级为散单；
        设复盘期限（专项结束后 5 个工作日内出根因与防复发项）
```

升级动作与级别的关系：暂停发布/回滚是**团队级决定**，分诊给出证据与建议，由发布负责人拍板；分诊记录必须留下"建议 + 决定 + 决定人（role）"三要素。

## 5. 激增期的分诊降级策略（保秩序，不保精细）

激增期单量超出处理能力时，按以下顺序降级操作，**定级矩阵与 SLA 定义不降级**：

1. 判重优先做深：激增期重复单占比通常 >30%，先把副本吸收进主单，有效工作量立刻下降；
2. 聚类内**只深挖一个代表单**（信息最全的），其余同签名单直接挂代表单进展，不逐单排查；
3. P2/P3 允许批量定级 + 批量路由（按聚类整组指派），明细后补；
4. 待补信息单的催办期从 3 个工作日延长到 5 个，但**请求必须当天发出**；
5. 分诊记录（TRIAGE-{date}.md）照常产出，激增期记录是事后复盘的核心证据，这一项不允许降级。

## 6. 激增复盘输入清单

专项/激增结束后，把以下材料归档到分诊记录同目录（复盘时用）：

- [ ] 激增期间的历次 TRIAGE 记录（含每日聚类观测值）
- [ ] 代表单的根因三要素（根因/修复动作/验证方式）
- [ ] 升级动作时间线：首个激增信号出现时间 → 冻结/回滚/专项决定时间 → 收敛时间（用于度量"信号到动作"的时延）
- [ ] 阈值回顾：本次激增在哪个阈值命中？有无更早命中的可能（如灰度期减半阈值是否生效）？
- [ ] 防复发项：进入 backlog 的治理项单号（监控哨兵、契约测试、幂等改造、发布检查项）
