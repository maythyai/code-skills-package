# 行业关注维度对照表

当用户难以表述"业务关注点"时，参考下表引导用户从"宽泛说法"收敛到"具体可检索的能力点"。

> 用法：从用户给的业务场景关键词出发，在下表找到最匹配的行业行，把"常见关注维度"念给用户听，让用户挑选 1–3 个最贴近的维度作为本次调研的"业务关注点"。

## 一、车企 / 智能汽车

| 业务场景类别 | 常见关注维度（建议挑 1–3 个） | 应排除（即便相关也不调研） |
|--------------|------------------------------|----------------------------|
| AI 主动服务 | 主动唤起时机、上下文判断、场景触发、用户授权与无感交互、隐私边界、跨场景延续 | 通用问答、TTS 音色、闲聊风格 |
| 智能座舱 | 多模态融合、车内识别、HMI 交互、应用生态、车机算力 | 自动驾驶能力 |
| 智驾 NOA | 城市/高速 NOA 接管率、覆盖城市数、感知方案（纯视觉/激光雷达）、端到端模型 | 座舱娱乐、外观设计 |
| OTA / 软件迭代 | OTA 节奏、功能上车速度、订阅服务模式、灰度策略 | 硬件参数 |
| 充电服务 | 超充网络、补能体验、即插即充、车桩协议、车主权益 | 续航里程参数 |
| 出海 | 海外发布会、当地合规、海外 AI 助理、海外补能/服务 | 国内市场动作 |

## 七、用法示例

用户："我想调研车企的 AI"
→ 追问：是想关注 **主动服务**（车主未问但主动推送）/ **应答能力**（车主问什么答什么）/ **多模态识别**（识别车内乘客/手势/视线）中的哪一个？
→ 用户选择"主动服务"
→ 锁定关注维度：主动唤起时机 + 场景触发 + 隐私边界
→ 检索关键词围绕这三个维度展开，**不**纳入"理想同学回答能力评测"这类信息。

## 八、扩展原则

如果用户的业务场景不在上表，按以下顺序构造关注维度：
1. 拆解业务**目的**（赚钱 / 留存 / 体验 / 效率…）
2. 找到该目的下的**关键动作**（用户的某个行为、产品的某个能力）
3. 围绕关键动作枚举**可被竞品做出差异**的能力点
4. 与用户确认 1–3 个最贴近的能力点作为关注维度
