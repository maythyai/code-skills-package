# 完整 Worked Example：车企 AI 主动服务调研走查

> 这是一份示范性走查，展示如何把 SKILL.md 的工作流真实落到一次调研中。
> 注意：示例中的"检索结果""URL""引用"为示意结构，**不是预先存好的事实**。
> 真实运行时，所有内容都必须通过 WebSearch / WebFetch / 浏览器 MCP 实时检索得到。

## 场景

**用户的初始请求**：
> 帮我做个竞品调研，我想了解车企在 AI 主动服务上的最新动作。

## Step 1：前置访谈

调用 AskUserQuestion，问出 4 项关键信息（已知"车企/AI 主动服务"，仍需收敛）：

```
Q1（业务关注点）："AI 主动服务" 想关注哪个细分？
- 主动唤起时机（推荐）：什么场景下主动开口、用什么信号触发
- 场景化卡片：在地图/导航/补能等场景的主动信息推送
- 隐私与授权：主动服务如何征得授权、避免打扰
- 个性化人设：主动服务的语气/拟人化设计

Q2（重点对象）：先看哪些车企？
- 理想 + 蔚来 + 小鹏（推荐）
- 加上问界 / 智己
- 加上特斯拉 / Rivian（海外）

Q3（输出条数）：默认 5–8 条
Q4（落地形态）：对话内 + Markdown 文件（可选写入外部文档/知识库）
```

**用户回答**：
- 关注：主动唤起时机 + 场景化卡片
- 对象：理想、蔚来、小鹏、问界
- 5–8 条，对话内 + Markdown

## Step 5：过滤与发散

假设检索结果：
- 理想：检到 2 条 A 级（OTA 公告 + 春季发布会）
- 蔚来：检到 1 条 B 级（晚点 LatePost 关于 NOMI Agents 的报道）
- 小鹏：检到 1 条 C 级（智能车 SEE 报道）+ 1 条 D 级（公众号软文）
- 问界：未检到时间窗内"主动服务"相关 → 启动兜底

兜底处理：
1. 同行业发散到智己、极氪、零跑 → 检到智己 IM AI 1 条 B 级
2. 仍可在输出中明确"问界在 6 个月时间窗内未检索到主动服务相关公开动向"

合并判断：
- 理想 OTA + 春季发布会是同一公司不同事件 → 分开列
- 蔚来 NOMI Agents + 智己 IM AI 都属"主动 Agent 化"行业动向 → 合并为一条"行业动向"

## 关键学习点

1. **关注点决定纳入**：上面"理想 OTA 主动场景包"被纳入，是因为它直接对应"主动唤起时机"。如果同一次 OTA 还包含了"理想同学回答能力升级"，那部分就**不纳入**。
2. **同类合并要看事件而非公司**：理想 OTA 和理想发布会是不同事件，不合并；蔚来和智己都是 Agent 化，合并。
3. **D 级来源不被丢弃但要警示**：小鹏的例子保留了，但显式标注"待验证"，让用户自己判断。
4. **兜底声明也是有效输出**：问界检不到不写成"问界没动作"，而是"没检索到公开动向"，留出真实可能性。
