# 可专利性初筛（自检，非法律结论）

**读这份文件的时机**：Step 2，对每个发明点跑一遍。输出档位 A / B / C，并在交底书里标注「自检判断（非法律结论）」。

这份文件不判断某个方案能否授权——那是代理人和审查员的工作。它做的是**在把材料交出去之前，把明显的表述问题和明显的落点问题挑出来**，避免代理人拿到的是一份需要推翻重写的稿子。

## 一、三要件自检

### 1. 新颖性（Novelty）——「有没有人已经公开过完全一样的东西」

要问的问题：

| # | 问题 | 答不上来意味着 |
|---|---|---|
| N1 | 在检索范围内，是否存在**单篇**公开文献已经披露了本发明的全部技术特征？ | 需要跑 Step 3 检索；不能凭印象说「没有」 |
| N2 | 是否有更早的公开使用、销售、演示、开源发布、会议演讲、招标文档披露了同一方案？ | 列出所有对外公开事件的时间/地点/方式，交代理人判断 |
| N3 | 本方案是否只是把已知的 A 和已知的 B 简单叠加，叠加后没有产生新的相互作用？ | 若只是叠加，新颖性可能有但创造性弱，需在 Step 3 明确写出叠加产生的意外效果 |
| N4 | 内部文档、代码注释、提交记录里有没有早于申请日的完整方案描述被外部可访问过？ | 检查开源仓库、公开 issue、技术博客 |

**关键提醒**：新颖性判断是「单篇对比」——把多篇文献拼起来否定新颖性是不允许的（那是创造性的做法）。所以自检时问的是「有没有一篇文献全都有」，不是「有没有几篇加起来有」。

**不要自行下结论说「已公开所以没新颖性」。** 公开使用是否构成现有技术，取决于公开时间、公开地域、公开方式（是否使公众能够得知），以及各司法辖区的宽限期规则。这是法律问题。

### 2. 创造性 / 非显而易见（Inventive Step）——「本领域技术人员看了现有技术，会不会自然而然做出同样的东西」

要问的问题：

| # | 问题 | 危险信号 |
|---|---|---|
| I1 | 最接近的现有技术（D1）是什么？它与本发明共享哪些技术特征？ | 说不出 D1 → 还没做检索，不要往下走 |
| I2 | 区别技术特征是什么？（用特征语言，不用效果语言） | 「更精准」「更快」不是特征 |
| I3 | 这个区别解决了 D1 的什么具体失效问题？ | 答不出 → 这个区别可能只是常规改进 |
| I4 | 现有技术里有没有「技术启示」引导本领域技术人员去做这个区别？（例如另一篇文献明确建议了同一手段解决同一问题） | 有明确启示 → 创造性弱，需重新找发明点 |
| I5 | 有没有「预料不到的技术效果」？（数值上的显著跃升、原本认为不可行的路径变得可行、解决了长期存在的技术难题） | 这是创造性最有力的支撑，能量化就量化 |
| I6 | 实现过程中是否存在「技术偏见」被克服？（本领域普遍认为某条路走不通，本发明走通了） | 需要写出偏见是什么、来自哪篇文献或哪种通行做法 |

**创造性论证的标准结构**（交底书第 5 节按这个结构写，代理人会直接复用）：

```
D1（最接近的现有技术）
  ↓ 共享特征：F1, F2, F3
  ↓ 区别特征：F4（按请求指纹聚类分桶，桶内独立统计并推导阈值）
  ↓ D1 的失效条件：流量结构突变时全局阈值误杀正常请求
  ↓ F4 解决的正是该失效条件
  ↓ 可量化效果：误杀率 12% → 1.8%（同一压测脚本，同一数据集）
  ↓ 现有技术中未见把 F4 用于该问题的技术启示
= 创造性论证成立（自检判断，非法律结论）
```

### 3. 实用性（Industrial Applicability）——「能不能被制造或使用，并产生积极效果」

软件方案通常最容易满足这一条，但仍要自检：

| # | 问题 | 不合格的例子 |
|---|---|---|
| U1 | 方案能否在真实计算环境中重复实施并得到相同结果？ | 依赖不可复现的人工主观判断作为必要步骤 |
| U2 | 是否产生可观测的技术效果（性能、资源、准确率、稳定性、时延、功耗）？ | 唯一效果是「用户觉得更好看」 |
| U3 | 是否违背自然规律或逻辑上不可能实现？ | 声称在不增加任何计算/存储的前提下把复杂度从 O(n²) 降到 O(1) |
| U4 | 效果是否只是把已知方案换一种等价表述？ | 换个数据结构但复杂度与资源占用不变 |

## 二、软件专利的特殊难点：客体问题（Subject-Matter Eligibility）

**这是软件类交底书被退回重写的第一大原因，比新颖性/创造性更常见。**

在多数司法辖区，以下三类**本身**不属于专利保护客体：

| 不受保护的类别 | 典型表述 | 为什么 |
|---|---|---|
| 纯算法 / 数学方法 | 「一种基于 XX 公式的权重计算方法」 | 被视为数学方法本身，是抽象规则 |
| 纯商业方法 | 「一种基于用户消费额度的会员等级调整方法」 | 被视为商业活动规则，不解决技术问题 |
| 纯智力活动规则 | 「一种英语单词记忆排序方法」「一种评分规则」 | 只发生在人的思维中，没有技术手段 |

**注意「本身」二字。** 同一个算法内核，绑定到具体技术场景后可能就从 C 档变成 A 档。区别不在算法，在于**它被用来解决什么问题、通过什么技术手段、产生什么技术效果**。

### 落地方法：技术问题 → 技术手段 → 技术效果 三段绑定

抽象内核必须绑定到下面至少一条具体路径上，且绑定要写进步骤里而不是写在背景里：

| 绑定路径 | 怎么写 | 示例（不合格 → 合格） |
|---|---|---|
| **A. 绑定到具体技术领域的数据处理流程** | 明确数据的物理来源、数据的机器表示、处理的触发条件、输出去向哪个系统组件 | 「一种相似度计算方法」→「一种用于分布式缓存预取的方法：从网关访问日志中提取键序列，按时间窗切片为访问指纹，计算指纹间相似度，据此在缓存节点上生成预取指令」 |
| **B. 绑定到系统架构** | 写清模块划分、模块间连接关系与数据流向、部署位置（客户端/边缘/网关/服务端） | 「一种限流方法」→「限流决策模块部署于服务网格 sidecar，与本地令牌桶、全局协调器构成两层结构，sidecar 只在本地统计超阈值时向协调器发起聚合请求」 |
| **C. 绑定到硬件交互** | 写清与传感器、执行器、存储介质、网络接口、专用加速单元的具体交互 | 「一种数据压缩方法」→「一种面向闪存存储介质的写入压缩方法：按闪存页大小（4KB）对齐切分数据块，压缩后不足一页时合并写入，减少写放大与擦除次数」 |
| **D. 绑定到计算机系统内部性能的改进** | 效果落在计算机自身指标上：CPU、内存、时延、吞吐、IO、网络包数、功耗 | 「一种任务调度方法」→「一种批处理任务调度方法，通过合并同数据分区的读取请求，将单次任务的磁盘寻道次数从 N 降到 log N」 |

**自检口诀**：把方案里的「人」「用户」「业务」「金额」「等级」「评分」全部划掉，剩下的还是不是一个能跑在机器上的数据处理过程？如果划完什么都不剩 → C 档。如果划完剩下完整的技术流程 → A 档。

### 常见被驳回的写法 vs 可授权的写法

| # | 被驳回的写法 | 问题 | 可授权的写法 |
|---|---|---|---|
| 1 | 一种商品推荐方法，根据用户历史购买记录计算偏好得分，得分高的商品优先展示 | 纯商业方法 + 智力活动规则；「偏好得分」无数学以外的技术落点 | 一种推荐请求处理方法：客户端上报的候选集超过预设规模时，服务端按物品向量的分片索引做局部近邻检索，仅将 Top-K 候选的向量分片加载入内存，减少单次请求的内存占用与检索时延 |
| 2 | 一种基于 XX 神经网络的图像分类算法，包含编码器、注意力层、解码器 | 纯算法；没有技术问题与部署落点 | 一种边缘设备图像分类方法：将编码器部署于终端、解码器部署于网关，中间只传输 M 维中间特征而非原始图像，在带宽受限（≤ 200kbps）链路下将端到端时延从 1.8s 降至 320ms |
| 3 | 一种订单折扣计算方法，满减规则由运营配置 | 纯商业规则；技术手段仅为「用计算机算数」 | （此例通常无技术落点，判 C 档）若确有技术内核，应改写为：一种折扣规则求值引擎，将规则集编译为有向无环图并按公共子表达式复用求值结果，在单请求需评估 200+ 规则时将求值耗时从 45ms 降至 3ms |
| 4 | 一种风控评分方法，综合多个维度加权打分 | 智力活动规则的机器化；「加权打分」是数学方法 | 一种交易请求的实时特征聚合方法：在流式计算节点上维护滑动窗口特征状态，按账户维度做本地预聚合并仅在窗口翻转时提交全局状态，将特征读取的网络往返从每请求 5 次降至 0 次 |
| 5 | 一种数据可视化方法，将指标以折线图展示 | 信息呈现本身，属审美/认知层面 | 一种大规模时序数据降采样渲染方法：按屏幕像素列宽自适应选择分桶粒度，每像素列只保留极值对，使 10⁸ 点序列在单帧 16ms 内完成渲染 |
| 6 | 一种测试用例生成方法，根据需求文档生成用例 | 若核心是人的判断规则 → 智力活动规则 | 一种基于调用图可达性分析的用例生成方法：从入口函数构建静态调用图，按分支覆盖目标计算最小路径集合，生成的用例集在相同覆盖率下将用例数量减少 40% |
| 7 | 一种区块链存证方法，将哈希写入链上 | 「用区块链」本身不是技术手段创新，通常被视为已知技术的常规使用 | 需给出链上结构的具体改进：一种存证 Merkel 树的裁剪方法，按访问频率将冷叶子节点归档至外部存储并保留审计路径，在存证量达 10⁹ 时将全节点存储占用降低 78% |

**从这张表能看出的规律**：合格的写法都含四要素——(1) 一个具体的技术场景与约束条件，(2) 具体的处理对象（数据的机器表示），(3) 具体的手段（模块/步骤/结构），(4) 落在计算机系统自身指标上的可量化效果。

## 三、初筛输出格式

对每个发明点产出这样一段，直接粘进交底书 Step 2 的位置：

```markdown
### 可专利性初筛（自检判断，非法律结论）

发明点：基于请求指纹聚类的自适应限流阈值计算

| 要件 | 自检问题 | 本轮结论 | 依据 |
|---|---|---|---|
| 客体 | 是否为纯算法/纯商业方法/纯智力活动规则 | 通过（路径 A + B） | 已绑定到网关限流数据处理流程与 sidecar 部署架构 |
| 新颖性 | 检索范围内是否存在单篇文献披露全部特征 | 未发现 | 见检索记录 R1–R14，最接近为 D1 |
| 创造性 | 区别特征是否解决了 D1 的具体失效问题 | 倾向成立 | 区别特征 F4 对应 D1 在流量结构突变下的误杀问题，效果可量化 |
| 实用性 | 是否可在真实环境重复实施并产生技术效果 | 通过 | 已在预发环境压测复现，数据见第 5 节 |

**档位：A（可直接交底）**
**待代理人确认事项**：D1 与本方案的区别是否足以支撑创造性；是否需要将 F4 上位化表述。
```

三档的处置：

| 档位 | 处置 |
|---|---|
| **A** | 直接进 Step 3 |
| **B** | 按「落地方法」四条路径重写发明点表述，重跑初筛；最多重写两轮，两轮后仍 B → 降为 C 处理 |
| **C** | 明确告知用户「以当前表述看不到技术落点」，并写明这是自检判断；同时给出两种出路：(1) 是否存在未写出的技术内核（回到访谈），(2) 是否改走技术秘密/著作权/商标等其他保护路径 |

**C 档不等于方案没价值。** 它只说明不适合走专利。大量优秀的工程改进应该走技术秘密（见 `sufficiency-and-secrecy.md`）。
